## Принятые решения
- Задачи в SRS — только номер из трекера со ссылкой `https://tracker.yandex.ru/<KEY>`, без ссылок на файлы папки — пользователь, 12.10
- Статус позиции заказа меняется целиком при создании заявки; остаток позиции — через Отдел дружбы; при отмене заявки статус возвращается — бизнес/пользователь, 12.10
- Блок «Оформлен возврат» приходит в карточке заказа `GET /api/orders/{id}` (доработка); `items[].count` не меняется, остаток = count − изделия в заявках — пользователь, 12.10
- Способ возврата по умолчанию — признак `is_order_method` в `return-method-list` (не поле в карточке); одинаковая логика при возврате к городу заказа (AC @NEW) — пользователь, 12.10
- Даты и интервалы курьера — от логистики `POST /api/v1/delivery/intervals` по коду службы из `return-method-list`; приложение ограничивает даты сроком возврата, в последний день +3 дня (как AS-IS `PickUpReturnDetailsService` для ПВЗ) — пользователь, 12.10
- Дата «Вернуть до» отдаёт сервер в `return-method-list`; инструкция Почты России — из описания способа — пользователь
- «Написать нам» открывает окно «Отдел дружбы с клиентами» (макет 28) — пользователь, 13.10
- Сумма и баллы к возврату за изделие — в карточке заказа, считает сервер — пользователь
- Создание возврата — новый метод (старые `POST /api/orders/{id}/return` и `return-details` не подходят); проверки дублируются на бэке; кнопка неактивна на время запроса — пользователь
- Новые поля в SRS: в US 1.4 шаг 2 заменено по смыслу; в US 1.2/1.3 имена из задач оставлены по решению пользователя
