# ECOMDEV-1860: [B] Ранний доступ к новинкам. Реализовать механизм раннего доступа к товарам в мобильном приложении

> Офлайн-копия задачи С. Щербатых, снята 17.11.2026 (статус в Трекере — «Закрыт»). Оригинал: https://tracker.yandex.ru/ECOMDEV-1860. Параметры и поля админки — отдельной задачей ECOMDEV-1887. Правила копирования — [README](./README.md).
> Образец крупной задачи по `templates/logic-admin.md`.

## **Цель**

Реализовать базовую логику раннего доступа: параметры системы, поле даты в карточке, определение участия товара в раннем доступе и заполнение раннего остатка, при котором сайт продолжает получать занулённый остаток, а МП реальный

## **Описание реализации**

{% cut "**Контекст**" %}

Сейчас товары категории "Скоро в продаже" являются недоступными для покупки. При попадании товара в данную категорию происходит обнуление остатков, вследствие чего товар становится недоступным во всех местах, где используются остатки. В рамках раннего доступа необходимо изменить существующую логику таким образом, чтобы в период раннего доступа мобильное приложение использовало реальный остаток товара, при этом для сайта продолжала использоваться текущая логика с зануленным остатком.

В период раннего доступа:

* товар должен быть доступен для покупки только в мобильном приложении

* сайт должен продолжать отображать товар как "Скоро в продаже"

* на сайте товар должен оставаться недоступным для покупки

* продажа на сайте и в мобильном приложении должна осуществляться из общего остатка товара

{% endcut %}

### Что нужно сделать

1. Реализовать определение товара, участвующего в раннем доступе, и служебный атрибут `early_access` в `cms_product_attributes`

2. Реализовать разделение остатка: реальный  для МП, занулённый  для сайта

3. Реализовать крон-джобу актуализации

### 1\. Логика использования параметра и полей периода

`early_access_enabled` = 0 - товары не участвуют в раннем доступе, сайт и МП работают по текущей логике "Скоро в продаже"

`early_access_enabled` = 1 - бэк проверяет условия участия товара в раннем доступе, при их выполнении МП использует реальный остаток

Окно раннего доступа задается диапазоном дат: `early_access_start_date` … `early_access_end_date`. Обе границы указывает контент-менеджер вручную

### 2\. Логика раннего доступа

#### 2\.1. Когда товар участвует в раннем доступе

Товар может участвовать в раннем доступе, если одновременно выполняются условия:

* `early_access_enabled` = 1

* заполнены оба поля: `early_access_start_date` и `early_access_end_date`

* текущее время находится в диапазоне `early_access_start_date` … `early_access_end_date`

* товар находится в категории "Скоро в продаже"

* у товара есть остаток

* товар не скрыт

Если хотя бы одно условие не выполняется, товар не участвует в раннем доступе.

#### 2\.2. Служебный атрибут `early_access`

Результат проверки условий сохраняется в таблицу `cms_product_attributes` ( по аналогии с атрибутом `sale` ECOMDEV-1505 )

Новая колонка не создаётся: добавляется новое значение в колонку `name`

| product_id | name | value |
|---|---|---|
| `id товара` | `early_access` | 1 - товар в раннем доступе, 0 - нет |

* проставляется и снимается крон-джобой (описание ниже)

* индексируется в Elasticsearch

* используется для фильтрации в МП (каталог, поиск, раздел "Новинки", рекомендации) и в фидах

* вручную не редактируется, в админке не отображается

Атрибут нужен независимо от выбранного варианта работы с остатком: фильтрация выдачи идет через Elasticsearch по индексируемым полям, вычислить участие на лету в момент запроса и отфильтровать по нему каталог и т.д. не сможем

#### 2\.3. Работа с остатками

Требуемое поведение: внутри окна МП получает реальный остаток, сайт занулённый (`qty_site` = 0)

Способ реализации определяется с разработкой

Отдельное хранение:

* `qty_site_early_access` (`cms_product_stocks`) - реальный остаток по баркодам

* `has_stock_early_access` (`cms_products`) - признак наличия остатка хотя бы по одному баркоду

* `qty_site` остается 0

Альтернативный вариант - расчет на лету (на pbr был выбран как предпочтительный, чтобы не создавать новые поля): новые поля не создаются, фактический остаток берется из источника, где он сохраняется до снятия категории "Скоро в продаже". Логика чтения должна гарантировать, что сайт не получает фактический остаток, а МП получает

### 3\. Механизм актуализации (крон-джоба)

Реализовать крон-джобу, которая проверяет состояние товаров раннего доступа

Предлагаемая периодичность: раз в 30 минут

Крон выполняет две разные задачи:

| **Задача крона** | **Вариант с отдельными полями** | **Вариант расчета на лету** |
|---|---|---|
| 1\. Проставить/снять `early_access` (участие товара) | нужен | нужен |
| 2\. Заполнить/очистить `qty_site_early_access` (ранний остаток) | нужен | не нужен |

Задача 1 нужна в обоих вариантах, так как без индексируемого атрибута невозможна фильтрация выдачи в ES. Задача 2 зависит от выбранного варианта работы с остатком

**При каждом запуске:**

1. Получить товары с заполненными `early_access_start_date` и `early_access_end_date`

2. Проверить `early_access_enabled`

3. Проверить наличие категории "Скоро в продаже"

4. Рассчитать границы окна с учётом `early_access_start_date` и `early_access_end_date`

5. Получить фактический остаток

**Товар соответствует условиям участия:**

* проставить `early_access` = 1

* *(вариант с отдельным хранением)* записать фактический остаток по баркодам в `qty_site_early_access`, установить `has_stock_early_access`, `qty_site` оставить 0;

**Товар перестал соответствовать условиям** (очищена/перенесена дата, отключен `early_access_enabled`, снята категория "Скоро в продаже", закончился остаток, товар скрыт, завершилось окно):

* снять `early_access` (= 0)

* *(вариант с отдельным хранением)* установить `has_stock_early_access` = 0, очистить `qty_site_early_access`

### 4\. Завершение раннего доступа при ручном выпуске (MVP)

Контент-менеджер снимает категорию "Скоро в продаже" и проставляет "Новинки". После этого товар работает как обычная новинка: доступен на сайте и в МП, используется стандартная логика остатков

### 5\. Логика отката

**Точечный** - через `early_access_start_date` / `early_access_end_date`: контент-менеджер очистил одну из дат или сдвинул диапазон так, что текущее время оказалось вне него -\> товар выходит из раннего доступа. Сайт продолжает показывать "Скоро в продаже", в МП покупка становится недоступна, товар также находится в "Скоро в продаже"

**Глобальный** - через `early_access_enabled` = 0: ранний доступ прекращается для всех товаров, в МП они ведут себя как обычные "Скоро в продаже"

### 6\. Справочно: места для проверки, где должна работать логика раннего доступа

Необходимо проверить все места, где используется доступность товара, остатки или статус "Скоро в продаже"

Ожидаемое поведение во всех местах ниже: товар раннего доступа доступен к покупке в МП и недоступен на сайте - остается "Скоро в продаже" или вообще не выводится

### Пересечение с предзаказом

Товар не должен быть одновременно доступен в раннем доступе и по предзаказу. Если товар находится в активном раннем доступе, предзаказ для него должен быть недоступен:

* на сайте не должна отображаться возможность оформить предзаказ

* в МП предзаказ должен быть недоступен

* не должны передаваться признаки и данные предзаказа:

  * `is_preorder_available= false`

  * `isPreorderAvailable = false`

  * тег "Предзаказ" не передавать

* для товара продолжает применяться логика раннего доступа

Если товар не находится в активном раннем доступе (не выполнено хотя бы одно из условий раннего доступа), предзаказ работает по текущей логике без изменений

Наличие включенного `early_access_enabled` само по себе не должно блокировать предзаказ,  ограничение действует только в период, когда товар фактически соответствует условиям раннего доступа

## **Тестирование**

{% cut "Критерии приёмки" %}

 1. Крон проставляет в `cms_product_attributes` атрибут `early_access` = 1 товарам, удовлетворяющим всем условиям участия, и снимает (= 0) при их невыполнении
 2. Внутри окна товар доступен к покупке в МП при наличии реального остатка, при отсутствии остатка недоступен
 3. Внутри окна на сайте товар отображается как "Скоро в продаже"
 4. Продажа в МП идет из общего остатка
 5. До наступления `early_access_start_date`, после `early_access_end_date` и при пустом любом из полей товар работает по текущей логике "Скоро в продаже"
 6. При `early_access_enabled` = 0 ранний доступ не работает ни для одного товара
 7. Точечный откат (очистка или перенос даты) выводит товар из раннего доступа
 8. После ручного выпуска ("Скоро в продаже" -\> "Новинки") товар работает по стандартной логике
 9. Проверены все места из раздела 6: товар раннего доступа доступен к покупке в МП и недоступен на сайте
10. Не нарушена существующая логика товаров "Скоро в продаже", не участвующих в раннем доступе

{% endcut %}
