# ECOMDEV-1731: [B] Приоритезация магазинов для экспресс заказа и обычного самовывоза

> Офлайн-копия задачи С. Щербатых, снята 17.11.2026 (статус в Трекере — «Пауза»). Оригинал: https://tracker.yandex.ru/ECOMDEV-1731. Правила копирования — [README](./README.md).
> Образец `templates/logic-admin.md`: админка разделом в задаче на логику, «(новое)» внутри существующего алгоритма, сценарии по каналам, обработка параметра.

## **Цель**

Реализовать возможность управления приоритетом магазинов для обычного самовывоза, экспресс-самовывоза и экспресс-доставки через админку

## **Описание реализации**

### **Контекст**

При экспресс-доставке магазин определяется из учета расстояния от всех магазинов до адреса пользователя, далее формируется отсортированный по удаленности список магазинов с ненулевым остатком в радиусе 50 км и передается в 1С ([NOVADEV-5610](https://tracker.yandex.ru/NOVADEV-5610))

Сейчас порядок магазинов определяется только гео и наличием остатков. Необходимо иметь возможность вручную поднимать отдельные магазины наверх, например, при открытии нового магазина сделать его приоритетным независимо от расстояния. Приоритет для самовывоза и для доставки может отличаться

### **Необходимо**

**1. Админка**

1. В таблицу  `cms_catalog_stock`добавить три новых поля:

   * `priority_express_delivery`(INT, NULL) - приоритет экспресс-доставки

   * `priority_express_pickup`(INT, NULL) - приоритет экспресс-самовывоза

   * `priority_pickup`(INT, NULL) - приоритет самовывоза

   * Чем меньше число, тем выше приоритет. NULL означает отсутствие ручного приоритета

2. В админке в настройки складов https://staging-admin.12stz.tech/cms/catalog/stock добавить поля ввода для этих трех значений. Поля принимают только неотрицательные значения. Ввод букв и спецсимволов недопустим. Пустое значение валидно и сохраняется как NULL

   1. Приоритет для экспресс-самовывоза
   2. Приоритет для экспресс-доставки
   3. Приоритет для обычного самовывоза

3. Добавить параметр в настройки системы cms_parameters:

   | **alias** | **title** | **description** | **value** | **value_type** |
   |---|---|---|---|---|
   | stores_priority_enable | Включить ручную приоритезацию магазинов | Если параметр выключен - игнорировать приоритет магазина и использовать стандартную логику, включен - применять сортировку в соответствии с приоритетом, выставленным в настройках склада | 0 | bool |

**2. Экспресс-доставка курьером**

Изменить алгоритм формирования массива магазинов для экспресс-доставки (метод сайта `POST /order/proceed-new` , метод старого чекаута`PUT /orders?mode=express_delivery` ,  метод нового чекаута `POST mobile/orders?mode=express_delivery`):

1. Отфильтровать магазины по гео пользователя `cms_users_geo.city_geo_id`(логика из [NOVADEV-5582](https://tracker.yandex.ru/NOVADEV-5582))

2. Отфильтровать по наличию товара в магазине для экспресса (`cms_catalog_item_stock.quantity_old > 0`)

3. Применить сортировку (новое):

   1. На самый верх списка выводятся магазины, у которых в админке задан числовой приоритет. Чем меньше число, тем выше магазин в списке

   2. Магазины, у которых приоритет не задан (пустое значение или `NULL`), отправляются в конец списка (с учетом текущей сортировки)

   3. Если у нескольких магазинов одинаковый приоритет (например, у двух магазинов стоит `1`) или если у них у всех приоритет не задан, то между собой они сортируются по текущей логике

4. Сформировать массив для 1С:

   * `store_code` = нулевой элемент массива

   * `store_code_additional` = следующие 3 элемента массива

**3. Экспресс-самовывоз**

Изменить алгоритм выдачи списка магазинов в чекауте (старый чекаут `POST /mobile/v2/delivery?mode=express_delivery` , новый чекаут `GET /mobile/cart-delivery/pickup-points?mode=express_delivery`, сайт `POST /delivery/delivery/place?mode=express_delivery`):

1. Отфильтровать магазины по гео `city_geo_id` пользователя

2. Отфильтровать по наличию товара в магазине для экспресса (`cms_catalog_item_stock.quantity_old > 0`)

3. Применить сортировку (новое):

   1. На самый верх списка выводятся магазины, у которых в админке задан числовой приоритет. Чем меньше число, тем выше магазин в списке
   2. Магазины, у которых приоритет не задан (пустое значение или `NULL`), сортируются по текущей логике
   3. Если у нескольких магазинов приоритет одинаковый (например, у двух магазинов стоит `1`) или если у них у всех приоритет не задан, то между собой они сортируются по текущей логике

**4.Обычный самовывоз**

Изменить алгоритм выдачи списка магазинов (старый чекаут`POST /mobile/v2/delivery?mode=order` , сайт `POST /delivery/delivery/place?mode=order`):

1. Отфильтровать магазины по `cms_users_geo.city_geo_id` пользователя

2. Отфильтровать по наличию товара на складе

3. Применить сортировку (новое):

   1. На самый верх списка выводятся магазины, у которых в админке задан числовой приоритет. Чем меньше число, тем выше магазин в списке
   2. Магазины, у которых приоритет не задан (пустое поле или `NULL`), сортируются по текущей логике
   3. Если у нескольких магазинов приоритет одинаковый (например, у двух магазинов стоит `1`) или если у них у всех приоритет не задан, то между собой они сортируются по текущей логике

**5.Обработка параметра** Если параметр `stores_priority_enable` выключен - игнорировать поля `priority_*` и использовать стандартную логику, если включен - в сортировке магазинов учитывать приоритет

## **Тестирование**

{% cut "Критерии приёмки " %}

1. В админке в настройках складов отображаются поля "Приоритет экспресс-доставки", "Приоритет экспресс-самовывоза", "Приоритет самовывоза. Поля принимают числовые значения. Пустое значение валидно
2. Магазины с `priority_express_delivery = 1` и наличием товара передается первым в массиве для 1С в `store_code`, в `store_code_additional` передаются следующие по приоритету магазинов
3. В списке точек экспресс-самовывоза магазины с заданным `priority_express_pickup`выводятся выше магазинов без приоритета
4. В списке точек обычного самовывоза магазины с заданным `priority_pickup` выводятся выше магазинов без приоритета
5. Если у нескольких магазинов одинаковый приоритет (или он не задан), они сортируются между собой по текущей логике
6. При выключении параметра в админке должна работать текущая логика приоритезации
