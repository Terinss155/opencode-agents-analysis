# DEVIOS-2618: iOS. Чекбокс согласия на рекламную email-рассылку в старом чекауте

> Образец каркаса Б «Разделы по аспектам» (`templates/mobile-app.md`). Не перенимается: тег `iOS.` (наш — `[iOS]`).

## Цель

На экране "Получатель" старого чекаута показывать чекбокс согласия на рекламную email-рассылку с учетом актуального статуса подписки клиента в Mindbox и передавать согласие при оформлении заказа

## Описание реализации

Макеты [iOS](https://www.figma.com/design/IYUsQtKgWNldFokDgTArkn/%F0%9F%93%B1-05.-Cart--Redesign-?node-id=930-641139&t=n3FQR6chwj685QNK-11)

#### 1\. Добавить чекбокс, не предустановленным

Необходимо добавить чекбокс на экран "Получатель" при оформлении заказа. При отображении он всегда должен быть неотмеченным независимо от статуса подписки клиента

[скриншот]

#### 2\. Видимость чекбокса

Видимость чекбокса определяется ответом метода `POST /api/v1/cart/subscription/check` (логика будет реализована в рамках задачи https://tracker.yandex.ru/ECOMDEV-2059 метод gate в рамках задачи https://tracker.yandex.ru/ECOMDEV-2065 ). Метод вызывается в двух сценариях:

1. При открытии экрана "Получатель", если у пользователя есть email в профиле -  с этим email

2. При вводе/изменении email на экране (см. п. 3) - с введенным email: если email в профиле был - при отличии введенного от профильного; если email в профиле не было - сразу при первом валидном email

Если у пользователя нет email в профиле - при открытии экрана метод не вызывается, чекбокс отображается по умолчанию неотмеченным

Пример ответа метода

```
{
  "success": true,
  "result": {
    "is_subscribed": false
  }
}
```

Интерпретация ответа:

* `is_subscribed = true` -\> чекбокс не показываем (клиент подписан)

* `is_subscribed = false` -\> чекбокс показываем неотмеченным, в том числе если статус получить не удалось

#### 3\. Проверка статуса при вводе/изменении email

* **email в профиле был** - вызывать, когда введенный на экране email отличается от профильного

* **email в профиле не было** - вызывать при первом же валидном email, введенном на экране

1. Вызвать метод `POST /api/v1/cart/subscription/check`, в теле запроса передать введенный email

2. По ответу обновить видимость чекбокса по тем же правилам, что в п. 2

3. Если чекбокс на момент изменения email был отмечен пользователем - сбросить его в неотмеченное состояние, так как статус подписки для нового email на момент ввода еще не известен

4. Чтобы не задедосить бэк частыми запросами при вводе email, нужна защита от лишних вызовов. Вариант на усмотрение разработки:

   * Debounce на ввод - запрос уходит после паузы в наборе (например, 500 мс без нажатий), даже если фокус еще в поле

   * По потере фокуса поля (blur) - отдельного debounce не требует: запрос уходит один раз, когда пользователь закончил редактировать поле и ушел с него

   В любом из вариантов дополнительно нужна валидация формата email на фронте - не вызывать метод, пока введенное значение не соответствует email

#### 4\. Передача согласия при создании заказа

При вызове `PUT /orders` передавать новый параметр `subscribe` (будет добавлен в рамках задачи https://tracker.yandex.ru/ECOMDEV-2059 ) со значением чекбокса - `true`, если отмечен, `false`, если не отмечен

{% note info "Для информации" %}

Чекбокс в чекауте используем только для новой подписки, но не для отписки, поэтому false означает, что клиент не дал новое согласие в рамках этого заказа, а не то, что клиент хочет отписаться, бэк на своей стороне обработает это значение и не будет далее вызывать методы Mindbox для подсписки

{% endnote %}

#### 5\. Ссылка на электронное согласие на рассылку

Текст рядом с чекбоксом содержит ссылку "электронным согласием на рассылку". По ней открывать контент, полученный через `GET /metadata/faq/theme/{id}`, где `id` — значение из `GET /api/v1/settings` -\> `result.settings.faq.themes.subscription_agreement` (будет добавлено в рамках задачи https://tracker.yandex.ru/ECOMDEV-2059 )

## Тестирование

{% cut "Критерии приёмки" %}

1. Чекбокс на экране "Получатель" по умолчанию не отмечен, независимо от статуса подписки

2. При открытии экрана, если у пользователя есть email в профиле, запрашивается статус подписки и чекбокс показывается только если клиент не подписан (или статус получить не удалось). Если email в профиле нет, то запроса при открытии экрана нет, чекбокс показан по умолчанию

3. При изменении email на экране на отличный от профильного, либо при вводе первого валидного email, если профильного не было, статус подписки запрашивается для нового email, чекбокс обновляется по ответу и сбрасывается в неотмеченное состояние

4. Значение чекбокса передается в параметре `subscribe` при вызове `PUT /orders`

5. Ссылка "электронным согласием на рассылку" открывает корректный контент

{% endcut %}
