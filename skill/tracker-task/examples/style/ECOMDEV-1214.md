# ECOMDEV-1214: [B][Mobile-API] Бронирование в магазине. Доработка метода  GET /stocks для возможности фильтрации по размерам и магазинам

> Офлайн-копия задачи С. Щербатых, снята 17.11.2026 (статус в Трекере — «Закрыт»). Оригинал: https://tracker.yandex.ru/ECOMDEV-1214. Правила копирования — [README](./README.md).
> Не перенимается: тег `[Mobile-API]` (наш — `[B][Mobile API]`); типы `str` (наши — `string`).

## Цель

Обеспечить корректное получение и отображение списка городов и магазинов для сценария бронирования товара

## Описание реализации

### **Предлагаемая реализация**

Необходимо доработать метод `GET /v2/products/stocks/{model_id}`, добавив новые опциональные query-параметры:

| **Название** | **Тип** | **Обязательность** | **Описание** |
|---|---|---|---|
| barcode | int | Нет | Используется для отбора городов и магазинов, где есть выбранный размер |
| country\_iso | str | Нет | Фильтрация выдачи по стране |
| geo\_id | str | Нет | Фильтрация выдачи по geo\_id города |
| reservation | int | Нет | Фильтр "Можно бронировать", возможные значения 0/1,<br>1 - возвращать только те магазины, где доступно бронирование,<br>если 0/не передан - выдача без фильтра (как сейчас) |

В ответ метода необходимо добавить новые параметры:

| **Название** | **Тип** | **Обязательность** | **Описание** |
|---|---|---|---|
| result.message | str | Нет | Информационное сообщение для клиента |
| result.items.cities.stores.work\_time | str | Нет | Расписание работы магазина. `cms_catalog_stock.working_time` (получать аналогично методу GET /mobile/cart-delivery/pickup-points) |
| result.items.cities.stores.reservation | bool | Да | Признак бронирования для вывода кнопки "Забронировать здесь" (будет добавлен в рамках задачи https://tracker.yandex.ru/ECOMDEV-819 , параметры системы будут добавлены в рамках https://tracker.yandex.ru/ECOMDEV-1223 ) |
| result.items.cities.stores.full\_address | str | Нет | Полный адрес. Получать из таблицы `cms_catalog_stock.address`(получать аналогично методу GET /mobile/cart-delivery/pickup-points) |
| result.items.cities.stores.route | str | Нет | Маршрут как добраться. Получать из таблицы `cms_catalog_stock.route`(получать аналогично методу GET /mobile/cart-delivery/pickup-points) |
| result.items.cities.stores.lat | number | Нет | Координаты, широта. Получать из таблицы `cms_catalog_stock.latitude` |
| result.items.cities.stores.lng | number | Нет | Координаты, долгота. Получать из таблицы `cms_catalog_stock.longitude` |

**Сценарии использования метода**

1. {% cut "Получение списка городов" %}

   [скриншот]

   {% endcut %}

   1. Используется после выбора размера для отображения списка городов, где доступен выбранный размер

      пример запроса:

      ```
      GET /v2/products/stocks/{model_id}?barcode=2112580400007&country_iso=RU
      ```

      Метод должен вернуть только те города, где есть магазины с остатком по переданному `barcode`. При этом в `stocks` магазинов должны возвращаться все доступные размеры товара, а не только выбранный `barcode`

2. {% cut "Получение магазинов выбранного города" %}

   [скриншот]

   {% endcut %}

   Используется для экрана карты и списка магазинов

   пример запроса:

   ```
   GET /v2/products/stocks/{model_id}?barcode=2112580400007&country_iso=RU&geo_id=0c5b2444-70a0-4932-980c-b4dc0d3f02b5
   ```

   Метод должен вернуть:

   1. Магазины выбранного города
   2. Вернуть в `stocks` все доступные размеры товара в каждом магазине

   Параметр `barcode` используется для отбора магазинов, но не ограничивает состав массива stocks, в массиве должны возвращаться все доступные размеры выбранного товара

3. Фильтр "Можно забронировать"

   1. Если параметр `reservation=1`, то метод должен возвращать только те магазины, которые:
      1. подключены к бронированию через настройку в админке (админка будет дорабатываться в рамках отдельной задачи [ECOMDEV-1223](https://tracker.yandex.ru/ECOMDEV-1223))
      2. бронирование включено (смотреть на параметр системы, будет добавлен в рамках [ECOMDEV-1223](https://tracker.yandex.ru/ECOMDEV-1223))
      3. в магазине есть остаток по товару, доступный  для бронирования. Наличие размера определяется по таблице `cms_catalog_item_stock`по полям `barcode` и `store_code`, подключенного к бронированию (логика аналогична как для экспресс-самовывоза)
   2. Если параметр `reservation=0`, то метод должен возвращать все магазины, где есть остаток по товару, аналогично текущему методу `GET /v2/products/stocks/{model_id}`с учетом переданных фильтров

**Обратная совместимость**

Если новые параметры не переданы, метод должен работать по текущей логике без изменений, структура ответа не меняется

**UPD 26.03** Необходимо добавить новый параметр tk\_id для бронирования в ответ метода `result.items.cities.stores.tk_id`. Если магазин недоступен для бронирования, то есть `reservation=false`, то возвращать `null`, если `reservation=true`, то `tk_id` для бронирования

## Тестирование

{% cut "Критерии приёмки" %}

1. В ответ метода `GET /v2/products/stocks/{model_id}` добавлены новые параметры согласно описанию
2. Добавлены новые query-параметры в метод`GET /v2/products/stocks/{model_id}`
3. Если в запросе передан `barcode`, то в ответе возвращаются только города и магазины, где есть остаток по переданному `barcode`. При этом в `stocks` возвращаются все доступные размеры товара
4. Если в запросе передан `geo_id`, то в ответе возвращаются только магазины, которые:
   1. Находятся в выбранном городе
   2. Имеют остаток по переданному `barcode`
5. Если в запросе передан `reservation=1`, то в ответе возвращаются только магазины, подключенные к бронированию, если `reservation=0`, то все магазины, где есть остатков по переданному баркоду
6. Если новые параметры не переданы, то метод возвращает данные в текущем формате и логике

{% endcut %}
