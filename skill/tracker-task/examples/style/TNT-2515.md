## Цель

Разработать в сервисе mindbox-srv-go два новых grpc-метода:

1. получение статуса email-подписки клиента (проксирование операции Mindbox `checkemailsubscription`, sync)

2. сохранение решения клиента о подписке на email-рассылку (проксирование операции Mindbox `ordersubscription`, async)

**Дополнительная информация**

* Глобальная цель: блок подписки на странице оформления заказа в мобильном приложении и на сайте

  {% cut "Контекст " %}

  Сейчас на сайте и в мобильном приложении есть чекбокс согласия на рекламную email-рассылку, но подписка по нему фактически не оформляется: значение чекбокса передается в Mindbox в составе заказа, а Mindbox не обрабатывает это поле как согласие на подписку. На сайте видимость чекбокса к тому же определяется некорректно,  из-за этого чекбокс может показываться уже подписанному клиенту или не показываться неподписанному

  Договорились с Mindbox, что источником актуального статуса подписки должен быть сам Mindbox, а не внутренние таблицы сайта. Поэтому нужны два новых метода:

  * получать актуальный статус подписки клиента перед показом чекбокса (чтобы не показывать его уже подписанным)

  * оформлять подписку отдельным вызовом

  {% endcut %}

## Описание реализации

1\. Добавить в протобаф `proto/mindbox.proto` в уже существующий service `User` новые rpc `CheckEmailSubscription`, `OrderSubscription`

1\.1 Rpc

* В коде показаны только те поля, которые нужно добавить

* Названия опциональны, могут быть изменены в ходе разработки

  ```
  ...
  service User { 
      rpc CheckEmailSubscription(CheckEmailSubscriptionRequest) returns (CheckEmailSubscriptionResponse) {}
      rpc OrderSubscription(OrderSubscriptionRequest) returns (OrderSubscriptionResponse) {}
  }
  ...


  // CheckEmailSubscription Получение статуса email-подписки клиента. При получении запроса проксировать в Mindbox в операцию checkemailsubscription
  message CheckEmailSubscriptionRequest {
      string email = 1;
  }

  message CheckEmailSubscriptionData {
      string processing_status = 1; // "Found" / "NotFound", как получено от Mindbox
      bool is_subscribed = 2; // true/false - подписан/не подписан, если у клиента есть запись с pointOfContact = "Email". Если такой записи нет (или клиент не найден), поле не передаётся в ответе 
  }

  message CheckEmailSubscriptionResponse {
      string status = 1;
      string message = 2;
      int64 code = 3;
      CheckEmailSubscriptionData data = 4;
      repeated Error errors = 5;
  }

  // OrderSubscription Сохранение решения клиента о подписке на email-рассылку. При получении запроса проксировать в Mindbox в операцию ordersubscription
  message OrderSubscriptionRequest {
      string email = 1;
      bool is_subscribed = 2;
      string brand = 3;
      string point_of_contact = 4;
  }

  message OrderSubscriptionResponse {
      string status = 1;
      string message = 2;
      int64 code = 3;
      repeated Error errors = 4;
  }
  ...
  ```

1\.2 Metadata

Операции `checkemailsubscription` и `ordersubscription` не используют обязательных параметров, передавать аналогично другим запросам

2\. Реализовать логику в новых rpc методах

2\.1 `CheckEmailSubscription`

1. Валидировать обязательные параметры в запросе: `email`. Если валидация не пройдена, то в Mindbox запрос не передавать, сразу возвращать ошибку (текст ошибок может быть изменен на усмотрение разработки)

   * `email` (body)

     * если не заполнен/отсутствует - ошибка `"field 'email' is required"`

     * если формат не соответствует email-адресу - ошибка `"field format 'email' must be a valid email address"`

2. Проксировать метод в операцию Mindbox `checkemailsubscription` ([документация Mindbox](https://docs.google.com/document/d/16M9JmiOpHxG7kQGOpz-QtWtYYSXscsc2rPM59Lceoz8/edit?tab=t.0#heading=h.ujdnheq7uzwz), если нет доступа, ссылки с описанием приложены выше)

3. Маппинг входных и выходных параметров

   **Входные параметры**

   | **rpc `Mindbox.User.CheckEmailSubscription`** | **операция Mindbox `checkemailsubscription`** |
   |---|---|
   | `email` (string) body required | `/customer/email` (string) body |

   **Выходные параметры**

   * `processingStatus` из ответа Mindbox передать в `data.processing_status`

   * найти в массиве `subscriptions[]` запись с `pointOfContact = "Email"` и без параметра {red}(`topic`), если найдена, передать ее `isSubscribed` в `data.is_subscribed`, если не найдена (или `processingStatus = "NotFound"`) - `data.is_subscribed` в ответе не передавать. Monolith будет различать случаи по совокупности `processing_status` и наличия/отсутствия `is_subscribed`: клиент подписан / отписан / подписки нет / клиент не найден

     | **rpc `Mindbox.User.CheckEmailSubscription`** | **операция Mindbox `checkemailsubscription`** |
     |---|---|
     | `data.processing_status` (string) body | `/customer/processingStatus` (string) body |
     | `data.is_subscribed` (bool) body | `/customer/subscriptions[pointOfContact="Email"]/isSubscribed` (bool) body |
