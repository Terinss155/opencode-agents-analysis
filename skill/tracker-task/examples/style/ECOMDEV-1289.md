# ECOMDEV-1289: [B][Mobile-API] Бронирование в магазине. Новый метод проверки доступности оформления бронирования

## Цель

Создать новый метод для проверки пользователя на фрод перед созданием бронирования

## Описание реализации

- Необходимо реализовать новый метод  предварительной проверки возможности оформления бронирования пользователем
- Метод будет использоваться при открытии карточки магазина и после авторизации пользователя
- Метод выполняет проверки на уровне пользователя, должен возвращать только результат проверки доступности бронирования

**Endpoint** `GET /mobile/user/capabilities`(название на усмотрение разработки)

**Назначение**

Проверить, может ли текущий пользователь оформить бронирование

**Описание метода**

1. **Характеристики метода**

   - Архитектура: REST
   - Протокол взаимодействия: HTTPS
   - Формат выходных данных: JSON

2. **Параметры запроса**

   Отсутствуют

3. **Логика работы**

   1. Проверить авторизацию пользователя, если не авторизован, вернуть ошибку авторизации

   2. Если авторизован:

      1. Проверить, что у пользователя существует броней не более числа, указанного в параметре `reservation_max_active`(будет реализован в рамках задачи [ECOMDEV-1223](https://tracker.yandex.ru/ECOMDEV-1223)  )

         1. В таблице `cms_orders` для `user_id` посчитать кол-во активных заказов с `type=reservation` (будет реализовано в рамках [ECOMDEV-819](https://tracker.yandex.ru/ECOMDEV-819) ). Если заказов больше или равно допустимому значению, то вернуть заголовок "У вас уже есть три активных брони" (полный пример будет ниже)
            1. Активными считаем заказы в незавершенных статусах `cms_order_statuses.internal_id NOT IN (17, 56, 55, 48, 23, 33)`

      2. Проверить, что пользователь не находится в blacklist `cms_user_ban_reason`. Если пользователь в blacklist, то вернуть заголовок "Бронирование недоступно" (полный пример будет ниже)

      3. Если пользователь не попал под ограничения, то вернуть для `"permission": "can_reserve"` `"status": true`

         {% cut "Пример ответа" %}

         ```
         {
             "success": true,
             "result": [
                 {
                     "permission": "can_order",
                     "status": true,
                     "title": "",
                     "message": ""
                 },
                 {
                     "permission": "can_reserve",
                     "status": true,
                     "title": "",
                     "message": ""
                 }
             ]
         }
         ```

         {% endcut %}

   3. При превышении допустимого кол-ва активных бронирований необходимо учитывать корректное склонение слова "бронь" в зависимости от значения параметра `reservation_max_active`. Алгоритм:

      1. Если число попадет в диапазон 11-14, то использовать "активных броней"
      2. Во всех остальных случаях:
         1. Если число оканчивается на 1, то "активная бронь"
         2. Если оканчивается на 2-4, то "активные брони"
         3. Если оканчивается на 0 или 5-9, то "активных броней"

4. **Описание** **выходных параметров**

   | **Параметр** | **Тип данных** | **Описание** |
   |---|---|---|
   | success | bool | Флаг успеха выполнения запроса |
   | result | array | Массив объектов доступов (permission) |
   | result\[\].permission | str | Название доступа (can\_order, can\_reserve, и т.д.) |
   | result\[\].status | bool | Статус данного доступа. true  - есть доступ, false - нет. |
   | result\[\].title | str | Заголовок для попапа с причиной блокировки |
   | result\[\].message | str | Текст сообщения для попапа |

   {% cut "Пример ответа, если превышено кол-во активных броней" %}

   ```
   {
       "result": [
           {
               "message": "",
               "permission": "can_order",
               "status": true,
               "title": ""
           },
           {
               "message": "Чтобы забронировать новое изделие, пожалуйста, выкупите или отмените текущую бронь.",
               "permission": "can_reserve",
               "status": false,
               "title": "У вас уже есть три активных брони"
           }
       ],
       "success": true
   }
   ```

   {% endcut %}

   {% cut "Пример ответа, если пользователь в blacklist" %}

   ```
   {
       "success": true,
       "result": [
           {
               "permission": "can_order",
               "status": false,
               "title": "Оформление заказа недоступно",
               "message": "В данный момент эта функция ограничена. Чтобы заказать изделия, пожалуйста, обратитесь в службу поддержки — наши специалисты на связи и помогут все оформить."
           },
           {
               "permission": "can_reserve",
               "status": false,
               "title": "Бронирование недоступно",
               "message": "В данный момент эта функция ограничена. Чтобы зарезервировать изделия, пожалуйста, обратитесь в службу поддержки — наши специалисты на связи и помогут все оформить."
           }
       ]
   }
   ```
