# Request/Response — сайт (Web)

> Основа: регламент wiki `teams/web-development/arxitektura/standarty/request-response`, приведённый к фактической
> практике монолита (сверено с кодом `12storeez-master`, 02.10.2026). Где регламент и код расходятся — действует код.
> Коды ошибок и выбор HTTP-статуса — [api-errors_memo.md](./api-errors_memo.md). Соответствие полей Mobile API — [request-response_mobile-api.md](./request-response_mobile-api.md).

## Контракт запроса

1. Заголовки — язык, версионирование, подпись запроса (регламент); монолит их не требует.
2. CRUD — использовать по возможности.
3. Ответ сайта собирается одним из двух способов — от способа зависят заголовки ответа и HTTP-статус ошибки.
   Способ сборки не путать со структурой ошибки (детальная / плоская — [api-errors_memo.md](./api-errors_memo.md), раздел 2): любая структура возможна при любом способе.

| Способ | Где используется | Заголовки ответа | HTTP-статус ошибки |
|---|---|---|---|
| **Сервис ответа** — `FrontendApiResponseService` (`src/Http/Controller/FrontendApiBaseController.php`) | Новые JWT-контроллеры: `Auth`, `User`, `User/Notifications` | Проставляются автоматически | По коду ошибки — `ResponseErrorCode::getStatusCode()` |
| **Ответ в контроллере** — массив / `SsrResponse` | `Api2/OrdersController` (в т.ч. `return-details`, `return-method-list`), `Product`, `delivery`, `giftcards` | Не проставляются | **200** — ошибка видна только по телу |

Новый метод в существующем контроллере делается тем же способом, что и соседние методы.

## Структура

### Заголовок запроса

| Ключ | Описание |
|:---|:---|
| `X-Request-Id` | Подпись запроса в формате uuid |
| `X-Request-Version` | Запрашиваемая версия API в формате семантического версионирования |
| `X-Language` | Язык запроса |

Монолит эти заголовки не требует — в задаче они не описываются. Раздел «Заголовки» в задаче появляется только для заголовков, специфичных для метода.

#### Пример заголовка запроса

```json
{
  "X-Request-Id": "6c17e0c1-8fa3-4925-9f88-56fec69fb99f",
  "X-Request-Version": "1.000.0",
  "X-Language": "ru",
  "Accept-Language": "ru-RU,ru;q=0.9,en-US;q=0.8,en;q=0.7"
}
```

### Параметры запроса

#### Общие соглашения

- snake_case.
- Только **плоская запись**: `?city_id=...&limit=20&offset=0`.
- Вложенная запись регламента `?filters[...]=...&pagination[...]=...` в монолите не используется: API-контроллеры не читают `filters` / `pagination` из запроса, `limit` / `offset` читаются плоско (например, `src/Modules/Delivery/Controller/GeoController.php`).

| Ключ | Описание |
|:---|:---|
| `limit` | Размер страницы — если нужна пагинация |
| `offset` | Смещение — если нужна пагинация |
| `*` | Фильтры — отдельными параметрами |

### Тело запроса

#### Общие соглашения

- JSON, snake_case.
- Объекты `filters` / `pagination` в теле запроса в коде не используются — не вводить без согласования с бэком.

#### Пример запроса

```
GET /api/orders/{order_id}/return-method-list?country_iso=RU&city=Москва
```

```json
POST /api/orders/{order_id}/return-details

{
  "method_return": "courier",
  "city_return": "Москва",
  "address_return": "ул. Тверская, д. 1",
  "index_return": "125009",
  "date_return": "2026-10-05"
}
```

### Заголовок ответа

| Ключ | Описание |
|:---|:---|
| `X-Response-Id` | Подпись ответа в формате uuid |
| `X-Response-Version` | Версия API в формате семантического версионирования |
| `X-Language` | Язык ответа |

Проставляются автоматически только сервисом ответа; при ответе в контроллере отсутствуют. В задаче не описываются.

#### Пример заголовка ответа

```json
{
  "X-Response-Id": "6c17e0c1-8fa3-4925-9f88-56fec69fb99f",
  "X-Response-Version": "1.000.0",
  "X-Language": "ru"
}
```

### Параметры ответа

#### Общие соглашения

- snake_case.
- `status` — `"success"` или `"error"`.

| Ключ | Описание |
|:---|:---|
| `status` | Статус ответа: `"success"` |
| `message` | Сообщение ответа (может быть пустой строкой) |
| `data` | Объект ответа или `null`; список — `data.items` |
| `pagination` | Только при пагинации: `{limit, offset, total}` |

### Тело ответа

#### Общие соглашения

- JSON, поля — по таблице «Параметры ответа».
- Отступление (ответ в контроллере): `POST /api/orders/{order_id}/return-details` при успехе отдаёт `{"success": true, "message": "..."}` без `status` и `data`.

#### Пример успешного ответа

```json
{
  "status": "success",
  "message": "",
  "pagination": {
    "limit": 100,
    "offset": 100,
    "total": 953
  },
  "data": {
    "items": [
      {
        "method": "courier",
        "method_type": "courier",
        "title": "Курьер",
        "available_dates_return": ["2026-10-05", "2026-10-06"]
      }
    ]
  }
}
```

### Ответ с ошибкой

| Ключ | Описание |
|:---|:---|
| `status` | Статус ответа: `"error"` |
| `message` | Сообщение ошибки |
| `code` | Код ошибки верхнего уровня — строка из `ResponseErrorCode` (`"40000"`, …) |
| `errors` | `Error[]` — только для детальной структуры (формы ввода) |

Отступления ответа в контроллере (`Api2/OrdersController`): дополнительно `"success": false`; `return-details` возвращает в `data`
введённые значения и `available_dates_return`, чтобы форма перерисовалась без повторного запроса.

#### Error

| Ключ | Описание |
|:---|:---|
| `target` | Имя поля, к которому относится ошибка; общая ошибка — `""` |
| `code` | Предметный код из `ResponseErrorCode` — строка (`"20110"`) |
| `message` | Сообщение ошибки |

#### Пример ответа с ошибкой

Детальная структура — форма ввода, клиенту нужно подсветить поле (`POST /api/orders/{order_id}/return-details`; ответ в контроллере → HTTP 200 и дополнительно `success: false`):

```json
{
  "status": "error",
  "success": false,
  "message": "Некорректный запрос",
  "code": "40000",
  "errors": [
    {
      "target": "index_return",
      "code": "20115",
      "message": "Некорректный индекс"
    }
  ]
}
```

Плоская структура — ввода нет, клиенту нужен только факт ошибки для тоста (условный пример: кнопка «Прочитать уведомление» по несуществующему `uuid`; `errors` не передаётся):

```json
{
  "status": "error",
  "message": "Не найдено",
  "code": "40004"
}
```
