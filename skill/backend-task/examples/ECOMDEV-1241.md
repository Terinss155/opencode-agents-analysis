# [B][Mobile API][Gate] Форма возврата. Метод для получения способов возврата

> Эталонный пример задачи типа **«проксирование метода сайта через Gate для МП»** (`[B][Mobile API][Gate]`).
> Источник: Яндекс Трекер, `ECOMDEV-1241`. Статус: метод проксируется, проверено.
> Контракт не дублируется — задача ссылается на задачу с описанием метода сайта ([ECOMDEV-1240](./ECOMDEV-1240.md)).

**Связи**
- Зависит от: DEVANDROID-1578 — Android. Реализация выбора способа возврата и ПВЗ
- Зависит от: DEVIOS-2388 — iOS. Реализация выбора способа возврата через ПВЗ

## Цель

Необходимо проксировать запрос от мобильного приложения на бэк сайта для получения способов возврата.

## Описание реализации

Реализовать проксирование метода согласно [задаче](https://tracker.yandex.ru/ECOMDEV-1240).

```
Gate: GET /api/v1/delivery/{order_id}/return-method-list
Site: GET /mobile/orders/{order_id}/return-method-list
```

## Тестирование

**Критерии приёмки**

- Метод с МП проксируется в метод сайта.
- В swagger указан метод проксирования.

## Что всплыло на тесте (уроки для постановки)

| # | Что произошло | Чего не хватило в постановке |
|---|---|---|
| 1 | Через Gate с гео-параметрами (Москва) приходил только `sdek-pvz`, а прямой запрос в монолит с теми же параметрами возвращал все включённые методы (`courier`, `sdek-pvz`, `5post`). Исправлено на стороне Gate (причина в трекере не описана). | Явно перечислить, что Gate прокидывает в монолит **без изменений**: query-параметры, тело, заголовки. | 2 | В тест-кейсе предусловия: заказ «Выполнен», `cms_orders.end_date` не старше 14 дней, методы включены для МП в админке. | Предусловия для проверки (данные заказа, настройки админки) — в задаче, а не только в тест-кейсе QA. |
