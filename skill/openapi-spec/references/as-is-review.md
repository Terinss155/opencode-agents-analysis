# Разбор действующего API (AS-IS)

> **Новое, 17.11.2026** (`knowledge/_archive/skills_2026-11-17/Анализ_скиллов_эндпоинты.md`, часть 2, §2, §6.2 п. 3). Формат выведен из сложившихся разборов:
> - `knowledge/12storeez-master-web/api/web/order-view_web.md` — образец;
> - `knowledge/12storeez-master-web/api/mobile/order-view_mobile.md`;
> - `projects/returns-2.0/as-is/api/order-refund-get-positions_web.md`;
> - `knowledge/esb-protobufs/api/logistics-intervals.md` — gRPC, свободная структура.
>
> Раньше формат нигде не был описан, хотя `AGENTS.md` поручает разборы `openapi-spec`.

## 1. Когда и где

| Что разбирается | Куда | Имя файла |
|---|---|---|
| Метод, который используется в нескольких процессах (сквозной справочник) | `knowledge/<репозиторий>/api/{web,mobile}/` | `<действие>_<канал>.md`: `order-view_web.md`, `order-view_mobile.md` |
| Метод в рамках одного процесса / проекта | `projects/<проект>/as-is/api/` | то же |
| gRPC / контракт сервиса без HTTP | `knowledge/<репозиторий>/api/` | `<сервис>-<операция>.md` |
| Целевой контракт (TO-BE) | `projects/<проект>/requirements/*_openapi.yaml` | — это не разбор, а спецификация по [web.md](./web.md) / [mobile.md](./mobile.md) и [swagger.md](./swagger.md) |

Разбор — **факты из кода**, не требования: что есть, а не что должно быть. Правила AS-IS / TO-BE — `AGENTS.md`.

## 2. Обязательные правила

1. **Сверка с кодом** — строка под названием метода: дата и коммиты репозиториев, с которыми сверено (`монолит dd4a997ac0, Go 631ac38, …`).
2. **Источник каждого утверждения** — путь к файлу и строке (`ProfileController::actionView()` (`:496`), `config/url.php:25`). Неподтверждённое — «требует проверки», а не догадка.
3. **Канал — в имени файла и заголовке.** Один метод на сайте и в МП разбирается двумя файлами; различия — разделом «Сравнение» в одном из них со ссылкой из другого.
4. **Ответ — как есть**, включая отступления от стандарта (нет конверта, ошибка — HTML 404, HTTP 200 с ошибкой). Отступления от стандарта не исправляются в разборе — они фиксируются.
5. **Имена полей — как в коде** (`colorId`, `need_bank_details`), даже если словарь их не рекомендует ([field-glossary.md](./field-glossary.md), правило 2).
6. **Тематические выводы**, которые иначе пришлось бы выяснять повторно (разная логика сайта и МП, двухфазный срок), — отдельным разделом с пометкой «Зафиксировано, чтобы не выяснять повторно».
7. **Каждое изменение** — строкой в «Версиях документа»: что сверено, что исправлено.
8. Без секретов и персональных данных в примерах.

## 4. Типы и колонки

- Тип в таблицах ответа — как в JSON: `integer`, `string`, `boolean`, `object`, `array`, `object\|null`.
- Тип БД — как в схеме: `int(11)`, `varchar(255) NULL`, `decimal(10,2)`. Сверять с ERD проекта, `knowledge/12storeez-master-web/database/` и `architecture-docs/monolith/database.puml`; свежие таблицы — с миграциями.
- Вычисляемое поле: «Поле БД» — `—`, в описании — чем вычисляется (`canBeReturned()`, формула).

## 5. Чек-лист разбора

- [ ] Строка «Сверено» с датой и коммитами; у утверждений — путь и строка кода
- [ ] Маршрут, обработчик, способ передачи параметров, авторизация, проверка владельца
- [ ] Используемые методы сценария — со ссылками на их разборы
- [ ] Диаграмма показывает ветки ошибок
- [ ] Все поля ответа с типами и условиями присутствия; пример ответа совпадает с таблицей
- [ ] Ошибки — фактический формат и HTTP
- [ ] Маппинг с БД: поле, колонка, тип колонки; вычисляемые помечены
- [ ] Расхождения сайта и МП — в «Сравнении»; повторяющиеся выводы — тематическим разделом
- [ ] Версия документа добавлена
