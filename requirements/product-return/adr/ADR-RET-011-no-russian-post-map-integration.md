# ADR-RET-011: Отказ от вывода карты отделений Почты России в MVP

| Поле | Значение |
|---|---|
| **Статус** | Принято |
| **Дата решения** | 10.09.2026 |
| **Владелец решения** | Product Owner — Рома Пушкарь; согласующие: Product Manager — Катя Филатова, System Analyst — Елена Васильева |
| **Область** | Продукт / Интеграция |

## Контекст

Для некоторых регионов (например, Калининград) единственным доступным способом возврата может выступать Почта России. Интеграция с Почтой России для автоматического создания заявок в рамках MVP не планируется. 
Возник вопрос: нужно ли по API забирать и отрисовывать на карте ближайшие отделения Почты России, чтобы клиент мог выбрать конкретное отделение?

## Решение

Интеграция со справочником отделений Почты России и вывод их на карте выносятся в Post-MVP (с минимальным приоритетом). 
В MVP при выборе Почты России клиенту выводится только текстовая инструкция с просьбой самостоятельно отправить посылку из любого удобного почтового отделения. В качестве компромисса допускается добавление внешней ссылки на Яндекс.Карты или сайт Почты России со списком отделений.

## Последствия

### Положительные
- Существенно экономится время разработки, так как не требуется интеграция справочника отделений и отрисовка карты.

### Отрицательные и риски
- Ухудшается UX: клиент должен сам искать ближайшее отделение Почты России вне контура сайта/приложения компании.
- Отсутствует цифровой след выбранного отделения, что усложняет отслеживание возврата логистами.

## Условия пересмотра

- Подтверждена интеграция со справочником отделений Почты России, дающая надёжный список
  ближайших пунктов для отрисовки на карте.
- Доля возвратов через Почту России, потерянных или задержанных из-за самостоятельного выбора
  клиентом неверного отделения, признана продуктом неприемлемой.
