# Шаг 04 (mobile). Выбор города возврата

**Канал:** Мобильное приложение · **Экран:** оформление возврата, блок города
**Статус:** DRAFT · **Дата:** 07.09.2026
**Результат шага:** в приложении зафиксирован город (название, идентификаторы города и региона, ISO-код страны). В базе ничего не меняется.

> Оговорка та же, что в [шаге 02](02-select-return-items.md): клиент недоступен, поведение восстановлено по контракту гео-API и по параметрам запросов способов и реквизитов возврата.

---

## 1. Пользовательский сценарий

### 1.1 Откуда пользователь приходит

С экрана оформления возврата (после выбора позиций и причин).

### 1.2 Что система отображает / данные

Поле или экран выбора страны и города. Данные — из мобильного гео-API. **Маршруты ниже в этом репозитории отсутствуют** — они относятся к мобильному шлюзу и взяты из его официального swagger-описания (см. `api/index.md`):

| Назначение | Эндпоинт (шлюз) | Карточка |
|---|---|---|
| Страны | `GET /api/v1/geo/countries` | [`api/mobile/geo/get-countries.md`](../../api/mobile/geo/get-countries.md) |
| Города страны / поиск | `GET /api/v1/geo/countries/{country_iso_code}/cities` | [`api/mobile/geo/get-cities.md`](../../api/mobile/geo/get-cities.md) |
| Детали города по идентификатору | `GET /api/v1/geo/countries/{country_iso_code}/cities/{geo_id}/details` | [`api/mobile/geo/get-city-details.md`](../../api/mobile/geo/get-city-details.md) |

### 1.3 Действия пользователя

Выбрать страну и город (поиск или список).

### 1.4 Ограничения

- Город обязателен: без него запрос сохранения реквизитов возврата вернёт ошибку «город не указан», а запрос списка способов без параметров города вернёт запасной вариант из одного `courier`.

### 1.5 Что происходит после действия

Приложение сохраняет параметры города и подставляет их в запросы списка способов (шаг [05](05-select-return-method.md)) и сохранения реквизитов возврата (шаг [06](06-confirm-return-details.md)).

### 1.6 Ошибочные сценарии

Обрабатываются гео-модулем приложения (вне процесса возврата).

## 2. Системная реализация

### 2.0 Диаграмма последовательности

```mermaid
sequenceDiagram
    actor U as Пользователь
    participant M as Мобильное приложение
    participant GW as Мобильный шлюз (гео)

    U->>M: открыть выбор города
    U->>M: ввод строки поиска
    M->>GW: GET /api/v1/geo/countries/{country_iso_code}/cities?search=...
    GW-->>M: список городов
    U->>M: выбрал город
    M->>GW: GET .../cities/{geo_id}/details
    GW-->>M: { город: name, geo_id; регион: geo_id; страна: iso }
    M->>M: сохранить параметры города
    M-->>U: блок способа возврата → запрос списка способов (шаг 05)
```

Заказ (`cms_orders`) на этом шаге не читается и не пишется.

### 2.1 Источники данных

Гео-данные отдаёт мобильный шлюз (проксирование в микросервис доставки-гео). Внутреннее хранилище гео в этом описании не разбирается.

### 2.2 Как система собирает данные

Процесс возврата на сервере в этом шаге не участвует: приложение обращается к гео-эндпоинтам напрямую. Заказ не читается и не пишется.

### 2.3 Обмен по API

```http
GET /api/v1/geo/countries/RU/cities?search={search}&limit={limit}
GET /api/v1/geo/countries/RU/cities/{geo_id}/details
```

Из результата приложение забирает название города, идентификатор города (и региона), ISO-код страны.

### 2.4 Что использует приложение

Параметры для последующих запросов возврата:

| Что | Куда |
|---|---|
| название города | `city` в запросе способов, `city_return` в запросе реквизитов возврата |
| идентификатор города | `cityId` в запросе способов (включает поиск способов «по идентификатору») |
| идентификатор региона | `regionId` в запросе способов |
| ISO-код страны | `countryIso` в запросе способов |

### 2.5 Что передаётся на следующий шаг

Параметры города → запрос `GET /mobile/orders/{order_id}/return-method-list`. Название города → тело запроса `POST /mobile/orders/{order_id}/return-details`.

### 2.6 Что сохраняется или меняется

Ничего. Город запишется в `cms_orders.return_city` на шаге 06.

### 2.7 Неуточнённые места

- Предзаполнение города из адреса заказа в мобильном клиенте не проверить (в запросе реквизитов возврата город приходит от клиента, сервер его не подставляет).
- Город доставки заказа в БД хранится структурой: `cms_orders.city`, `cms_orders.city_fias`, `cms_orders.state`, `cms_orders.country`. В процессе возврата не используется; для TO-BE-предзаполнения источник есть.
- Набор стран определяется гео-сервисом.

## 3. Отличия от TO-BE

| TO-BE (`UC-RET-03`) | AS-IS (mobile) |
|---|---|
| Город предзаполняется из заказа, подтверждается или меняется | Сервер город не предзаполняет; он приходит от клиента |
| После сохранения города — определение базового набора каналов «по месту покупки» | Набор каналов — только по таблице `cms_delivery_city` (шаг 05) |
