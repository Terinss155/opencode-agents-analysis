# Шаг 04 (web). Выбор города возврата

**Канал:** Сайт · **Экран:** «Оформление возврата», блок «Способ возврата» → кнопка города / заглушка «город не выбран»
**Статус:** DRAFT · **Дата:** 07.09.2026
**Результат шага:** в состоянии формы заполнен город (наименование, идентификатор города, ФИАС, регион и его идентификатор, страна и её ISO-код). В базе ничего не меняется.

---

## 1. Пользовательский сценарий

### 1.1 Откуда пользователь приходит

С экрана причин (шаг [03](03-select-return-reason.md)), кнопка «Продолжить» после заполнения причины по последней позиции. Открывается единый экран «Оформление возврата».

### 1.2 Что система отображает

- Заголовок «Оформление возврата».
- Блок «Способ возврата». В его верхнем углу — кнопка выбора города:
  - если город не выбран — «Выбрать город»;
  - если выбран — название города.
- Пока город не выбран, вместо списка способов показывается заглушка с кнопкой (текст про необходимость указать город).
- **Город из заказа автоматически не подставляется.** При открытии экрана город пустой.

### 1.3 Действия пользователя

- Нажать кнопку города (или кнопку в заглушке) — открывается общий гео-попап выбора страны и города (поиск и список).
- Выбрать страну и город, подтвердить.
- После подтверждения: город сохраняется в состоянии формы, а адрес (улица/дом/квартира/индекс) очищается.

### 1.4 Ограничения и зависимости

- Список способов возврата (шаг 05) и все последующие блоки (адрес, дата, реквизиты) появляются только после того, как выбран город.
- Кнопка «Подтвердить возврат» внизу требует, среди прочего, заполненные страну и город.
- Смена города очищает адрес.

### 1.5 Что происходит после действия

- Город сохраняется в памяти попапа.
- Блок способов возврата реагирует на появление/смену города и запрашивает список способов (шаг [05](05-select-return-method.md)).

### 1.6 Ошибочные сценарии

- Закрыл гео-попап без выбора — город остаётся пустым, экран остаётся с заглушкой.
- Ошибки гео-сервиса обрабатываются внутри гео-модуля (вне процесса возврата).

## 2. Системная реализация

### 2.0 Диаграмма последовательности

```mermaid
sequenceDiagram
    actor U as Пользователь
    participant W as Сайт (попап)
    participant GEO as Гео-сервис доставки<br/>(через прокси сайта)

    U->>W: тап «Выбрать город» / кнопка заглушки
    W-->>U: гео-попап (страна + город)
    U->>W: ввод строки поиска города
    W->>GEO: GET /api/v1/delivery/geo/countries/{countryIso}/cities?search=...
    GEO-->>W: список городов
    U->>W: выбрал город, подтвердил
    W->>GEO: GET .../cities/{geo_id}/details (детали города)
    GEO-->>W: { city{title,id,fias}, region{title,id}, country{title,isoCode} }
    W->>W: location = RefundLocation.fromGeo(...); resetAddress('city')
    W-->>U: блок «Способ возврата» → запрос списка способов (шаг 05)
```

Заказ (`cms_orders`) на этом шаге не читается и не пишется.

### 2.1 Источники данных

Города и адреса отдаёт микросервис доставки-гео через прокси-эндпоинты сайта:

| Назначение | Эндпоинт |
|---|---|
| Поиск / список городов | `GET /api/v1/delivery/geo/countries/{countryIso}/cities?search=&limit=&offset=&locale=ru` |
| Детали города по строке | `GET /api/v1/delivery/geo/countries/{countryIso}/cities/normalize?query=` |
| Детали города по идентификатору | `GET /api/v1/delivery/geo/countries/{countryIso}/cities/{geo_id}/details` |
| Страны | `GET /api/v1/delivery/geo/suggest-country`, `GET /api/v1/delivery/geo/countries/{countryIso}` |

Это полный набор гео-эндпоинтов доставки (маршруты подтверждены конфигурацией сайта). **Какие именно из них вызывает попап выбора города — по коду не прослеживалось**; для процесса возврата важен только итоговый набор полей города.

Существующие карточки: [`api/web/geo/get-cities.md`](../../api/web/geo/get-cities.md), [`api/web/geo/get-city-details.md`](../../api/web/geo/get-city-details.md).

Внутреннее устройство гео-сервиса (его таблицы городов и регионов, обращение к внешним данным) в этом описании не разбирается.

### 2.2 Как система собирает данные

Процесс возврата на этом шаге на сервере не участвует: гео-попап обращается к гео-эндпоинтам напрямую. Заказ не читается и не пишется.

### 2.3 Обмен по API

Запросы делает гео-модуль внутри попапа выбора города.

**Пример запроса (поиск города)**

```http
GET /api/v1/delivery/geo/countries/RU/cities?search=Моск&limit=30&offset=0&locale=ru
X-Requested-With: XMLHttpRequest
```

**Пример запроса (детали выбранного города)**

```http
GET /api/v1/delivery/geo/countries/RU/cities/{geo_id}/details?locale=ru
```

Из результата берутся: название города, идентификатор города (`geo_id`), ФИАС города, название и идентификатор региона, название и ISO-код страны. Полная структура ответа гео-сервиса в материалах проекта не сохранена (см. карточки `api/web/geo/*`).

### 2.4 Что использует сайт

| Значение | Куда идёт дальше |
|---|---|
| название города | подпись кнопки; параметр `city` запроса способов; поле `city_return` при сохранении реквизитов возврата |
| идентификатор города | параметр `cityId` запроса способов (включает поиск способов «по идентификатору»); подбор улиц/домов; карта ПВЗ |
| ФИАС города | параметр `cityFias` запроса способов |
| название и идентификатор региона | параметры `region` / `regionId` запроса способов |
| название страны | проверка заполненности формы |
| ISO-код страны | параметр `countryIso` запроса способов; параметр в запросах адреса |

### 2.5 Что передаётся на следующий шаг

Город целиком хранится в памяти сайта. В запрос списка способов (`GET /api/orders/{order_id}/return-method-list`) уходят: название города, ФИАС, идентификатор города, ISO страны, название и идентификатор региона.

### 2.6 Что сохраняется или меняется

Ничего. Город запишется в заказ (`cms_orders.return_city`) только на шаге [08](08-confirm-and-create-return.md), при сохранении реквизитов возврата.

### 2.7 Неуточнённые места

- Внутренняя работа гео-сервиса (внешние источники, кэш, справочники) — вне границ описания.
- Список поддерживаемых стран определяется гео-сервисом. Для возврата отдельных ограничений по стране в коде нет, но доступность способов считается по таблице `cms_delivery_city`, где заведены только российские города (**допущение**).
- Город доставки заказа в БД хранится структурой: `cms_orders.city`, `cms_orders.city_fias`, `cms_orders.state`, `cms_orders.country`. В процессе возврата эти поля **не используются** (город выбирается заново через гео-попап). Для TO-BE-предзаполнения источник есть.

## 3. Отличия от TO-BE

| TO-BE (`UC-RET-03`, `RET-BR-01`, `RET-BR-02`) | AS-IS (web) |
|---|---|
| Город предзаполняется из заказа, пользователь подтверждает или меняет | Город не предзаполняется; при открытии экрана он пустой, пользователь всегда выбирает вручную |
| Отдельный экран страны/города с поиском и списком, если город не определён | Используется общий гео-попап |
| После сохранения города система определяет базовый набор каналов «по месту покупки» и фильтрует по городу | Набор способов определяется только по таблице `cms_delivery_city` (типы транспортных компаний `1`, `11`, `15`); «место покупки» в web-расчёте не участвует |
| При смене города очищается адрес/пункт | Реализовано |
