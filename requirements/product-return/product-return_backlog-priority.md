# Приоритизация backlog: Возврат товара и возврат денежных средств

**Документ:** приоритизация фич процесса возврата товара.
**Метод:** RICE (основной) + MoSCoW (распределение по релизным обязательствам).
**Источник фич:** `user-story/product-return_user-story.md` (US-101…US-206) и `../drafts/`.

## Обоснование выбора метода
- **RICE** — применяем, так как фичи возврата являются продуктовыми (влияют на охват клиентской базы, конверсию повторных покупок, нагрузку на поддержку) и допускают числовую оценку охвата.
- **MoSCoW** — добавляем для фиксации обязательств релиза: часть фич (реквизиты) обязательна по операционным причинам, даже если RICE-скор ниже.

## Допущения при отсутствии точных данных (требуют валидации PO)
- Активная клиентская база онлайн-магазина (совершающих покупки за квартал): **100 000 клиентов**.
- Сегмент, совершающий хотя бы один возврат за квартал: **15 000 клиентов (15%)** — это верхняя оценка охвата (Reach) для сквозных фич.
- Оплата при получении (курьеру) — ~**20%** возврат-заявок (3 000 клиентов/квартал).
- Выбор способа возврата по каналам (у возврат-клиентов): Курьер ~60%, СДЭК ~20%, 5Post ~15%, магазин ~5%.
- **Impact:** 3 = масштабное влияние на пользователя/бизнес; 2 = высокое; 1 = среднее.
- **Confidence:** по подтверждённым бизнес-правилам из `../drafts/` — выше (80–90%); по каналам с открытыми параметрами (5Post, магазин) — ниже (60–80%).
- **Effort** — в человеко-месяцах, оценочно для одной продуктовой команды; точное календарное планирование — задача SA.

## Выводы по порядку спринтов (ориентир)
1. **Спринты 1–2 (Must, «молниеносные победы»):** оформление возврата, город/способы, статусная модель, отмена/автоотмена, возврат денег.
2. **Спринты 3–4 (Must, крупные проекты):** создание заявки и карточка, канал «Курьер», реквизиты.
3. **Спринты 5–6 (Should):** каналы «СДЭК» и «5Post», уведомления.
4. **Позднее (Could):** возврат в розничный магазин — после уточнения процесса.

## Не входит в текущий релиз (Won't have this time)
- Редактирование созданной заявки, включая изменение состава (`US-108` снята; границы возможного Post-MVP не определены).
- Самостоятельный перенос даты/времени приезда курьера — не MVP (`BR-CUR-05`).
- Подключение Беларуси и Казахстана — не MVP (`BR-COM-26`).
