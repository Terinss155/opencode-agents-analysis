# User Story: Возврат товара и возврат денежных средств

**Документ:** пользовательские истории (User Story) на процесс возврата товара и возврата денег клиентом.
**Домен:** E-commerce / Fashion-ритейл. Стиль — INVEST, Acceptance Criteria — Gherkin.
**Источники фактов:** `../../drafts/obshie-biznes-pravila-oformleniya-vozvrata.md`, `../../drafts/vozvrat-kurerom-biznes-process-to-be.md`, `../../drafts/vozvrat-cherez-sdek-pvz-biznes-process-to-be.md`, `../../drafts/vozvrat-cherez-5post-biznes-process-to-be.md`.

## Подтверждённые исходные данные (факты, не допущения)

- Срок создания заявки: **14 дней** — обычный клиент, **30 дней** — F&F, отсчёт от фактического получения товара. Датой подачи считается дата создания заявки в ЛК. (`BR-COM-04`, `COM-OQ-01` закрыт)
- Каналы возврата: **Курьер**, **СДЭК ПВЗ/офис**, **5Post**, **розничный магазин**, **Почта России**. Дистанционные каналы — Курьер, СДЭК, 5Post и Почта России; они применяются только к онлайн-покупке. (`BRD FR-3.x`, уточнение заказчика от 07.09.2026)
- По уточнению заказчика от 07.09.2026 в клиентский путь добавлена **Почта России**: способ доступен только для Калининграда и не требует выбора конкретного отделения при оформлении.
- Базовый набор каналов зависит от места покупки: розничная покупка возвращается только в розничный магазин, покупка в аутлете — только в аутлет, покупка в «Цветном» — только в «Цветной»; для онлайн-покупки доступны розничный магазин, Курьер, 5Post, СДЭК и Почта России с последующей фильтрацией по городу и другим ограничениям.
- Банковские реквизиты запрашиваются **только при оплате заказа курьеру при получении** (наличными или картой — доставка «курьер с примеркой»). Обычная курьерская доставка возможна только с онлайн-оплатой — для неё, как и для всех прочих онлайн-способов, форма не показывается, деньги возвращаются исходным способом, а клиенту выводится текст-подсказка про обращение в поддержку «Дружба» для перевода по другим реквизитам. В форме обязательны фамилия, имя, **отчество**, БИК, номер лицевого счёта; для счёта `30232810...` обязателен номер карты/договора; CVV и паспорт не запрашиваются. (`BR-COM-05`–`BR-COM-07`)
- Возврат денег для Курьера/СДЭК/5Post — **до 10 дней** с момента поступления товара на склад и подтверждения соответствия условиям возврата. ("`BR-COM-17`", "`BR-COM-22`")
- Для возврата через магазин срок возврата денег составляет **до 10 дней** с момента приёма товара и подтверждения его соответствия условиям возврата сотрудником магазина.
- После создания заявки действует **отдельный срок передачи** возврата; если клиент не передал товар — заявка автоматически отменяется. Срок передачи не является остатком 14/30-дневного срока создания. (`BR-COM-23`, `BR-COM-28`)
- Если заявка автоотменена до истечения 14/30-дневного срока, клиент может создать новую заявку. (`BR-COM-29`)
- Отмена заявки клиентом возможна до получения системой статуса канала, подтверждающего приём возврата. Для Курьера таким событием является регистрация приёмки на промежуточном складе транспортной компании, а не физическая передача посылки курьеру. Точный маппинг ограничивающих статусов открыт. (`BR-COM-12`)
- Изменение состава заявки для дистанционных каналов — до передачи данных в транспортную компанию. Способ возврата внутри созданной заявки не меняется: только отмена + новая заявка. (`BR-COM-15`, `BR-COM-16`)
- Начальный клиентский статус заявки — «Заявление на возврат создано». Единая статусная модель возврата и маппинг канальных статусов требуют согласования. (`COM-OQ-04`, `COM-OQ-05`)
- Отдельный клиентский статус «возврат денег» не отображается — этап входит в общую статусную модель. Блок «Возврат средств» (способ и ожидаемый срок) отображается после создания заявки. (`BR-COM-19`, общий процесс 7.2)
- Электронное заявление формируется по запросу из данных БД (PDF отдельно не хранится), скачивается клиентом из ЛК; подпись не требуется. (`BR-COM-08`–`BR-COM-10`)
- Клиенту без авторизации доступен пустой бланк заявления для ручного заполнения. Беларусь и Казахстан не входят в MVP. (`BR-COM-26`)
- Самостоятельный перенос даты/времени курьера **не входит в MVP**. (`BR-CUR-05`)
- QR-код "Узнайте, как вернуть" на упаковке — целевой путь ведёт в ЛК; точный адрес требует согласования. (`COM-OQ-14`)

# Основная пользовательская история

## US-100: Оформление возврата товара

Как пользователь, совершивший покупку,

Я хочу оформить возврат одного, нескольких или всех доступных товаров из заказа удобным доступным способом,

Чтобы вернуть неподошедшие товары и получить за них денежные средства и использованные баллы в соответствии с условиями возврата.

**Приоритет:** Must have

**Оценка:** требует оценки командой после декомпозиции; история является верхнеуровневой и не предназначена для реализации в одном спринте

**Бизнес-ценность:** пользователь самостоятельно оформляет возврат и выбирает доступный для города канал без обращения в поддержку.

**Зависимости:** доступность заказа и товаров для возврата; справочники причин; определение города; получение доступных способов и точек возврата; расчёт суммы и баллов.

```gherkin
Feature: Оформление возврата товара

Scenario: Успешное оформление возврата
  Given пользователь открыл заказ, доступный для возврата
  And в заказе есть хотя бы один товар с доступным для возврата количеством
  When пользователь выбирает один, несколько или все доступные товары и количество каждого товара
  And указывает причину и подпричину для каждого выбранного товара
  And подтверждает предзаполненный город или выбирает другой город
  And выбирает доступный способ возврата и заполняет обязательные для него данные
  And подтверждает итоговые данные возврата
  Then система создаёт заявку на возврат
  And в заявке фиксируются товары, количество, причины, город, способ возврата и данные выбранного способа
  And пользователю отображаются данные созданного возврата

Scenario: Город не удалось определить
  Given пользователь заполнил товары и причины возврата
  And системе не удалось определить город из заказа
  When система открывает экран выбора города
  Then пользователь может выбрать страну
  And найти город по наименованию или выбрать его из списка
  And после выбора города система показывает доступные для него способы возврата

Scenario: Пользователь меняет предзаполненный город
  Given система предзаполнила город из заказа
  When пользователь выбирает другой город
  Then система повторно определяет доступные способы возврата
  And не использует адрес или пункт заказа, относящийся к другому городу

Scenario Outline: Каналы ограничены местом офлайн-покупки
  Given пользователь оформляет возврат товара, приобретённого в <место покупки>
  When система формирует базовый набор каналов возврата
  Then система допускает возврат только через <доступный канал>

  Examples:
    | место покупки      | доступный канал       |
    | розничный магазин | розничный магазин     |
    | аутлет             | аутлет                |
    | «Цветной»          | «Цветной»             |

Scenario: Каналы для онлайн-покупки
  Given пользователь оформляет возврат товара, приобретённого в онлайн-магазине
  When система формирует базовый набор каналов возврата
  Then в базовый набор входят розничный магазин, Курьер, 5Post, СДЭК и Почта России
  And система показывает только каналы, доступные для выбранного города и данных заказа
  And Почта России отображается только для Калининграда

Scenario: Товары не выбраны
  Given пользователь находится на экране выбора товаров
  And не выбрал ни одного товара с доступным количеством
  When пользователь просматривает доступные действия
  Then переход к экрану выбора причин недоступен

Scenario: Причина или подпричина не выбрана
  Given пользователь находится на экране выбора причин
  And причина или подпричина не выбрана хотя бы для одного из товаров, выбранных для возврата
  When пользователь просматривает доступные действия
  Then переход к экрану оформления возврата недоступен

Scenario: Не заполнены обязательные данные оформления
  Given пользователь находится на экране оформления возврата
  And не выбрал город, способ возврата или обязательные данные выбранного способа
  When пользователь просматривает доступные действия
  Then подтверждение возврата недоступно

Scenario: Для возврата требуются банковские реквизиты
  Given пользователь находится на экране оформления возврата
  And система определила, что для возврата денежных средств требуются банковские реквизиты
  And обязательные банковские реквизиты не заполнены
  When пользователь просматривает доступные действия
  Then подтверждение возврата недоступно

Scenario: Банковские реквизиты не требуются
  Given пользователь находится на экране оформления возврата
  And система определила, что деньги возвращаются исходным способом оплаты
  When пользователь заполнил город, способ возврата и обязательные данные выбранного способа
  Then система не требует заполнения банковских реквизитов
  And подтверждение возврата доступно

Scenario: Данные утратили актуальность перед подтверждением
  Given пользователь заполнил все обязательные данные
  And выбранный товар, количество, способ или точка возврата стали недоступны
  When пользователь подтверждает возврат
  Then система не создаёт заявку
  And сообщает, какие данные необходимо выбрать повторно
```

**Декомпозиция:** подробный клиентский путь и канальные ветки описаны в `../use-case/product-return_use-case.md`; детальные продуктовые истории сохранены в разделах A и B настоящего документа.

# Раздел A. Общие истории (все каналы)

## US-101: Просмотр условий и возможности возврата по заказу

Как клиент, совершивший покупку
Я хочу видеть в карточке заказа, доступен ли возврат и до какой даты
Чтобы сразу понять, могу ли я вернуть товар, не обращаясь в поддержку

Приоритет: Must have
Оценка: 3 story points
Ценность: снижает ошибочные обращения в поддержку и преждевременные заявки.
Зависимости: —

```gherkin
Feature: Проверка возможности возврата по заказу

Scenario: Возврат доступен
  Given клиент авторизован и открывает карточку выполненного заказа
  And заказ принадлежит клиенту и имеет статус, допускающий возврат
  And дата фактического получения товара известна
  And срок создания заявки (14 дней; F&F — 30 дней) не истёк
  And в заказе есть изделие с доступным для возврата остатком
  When клиент просматривает карточку заказа
  Then отображается информационное сообщение о сроках возврата
  And отображается кнопка «Оформить возврат»

Scenario: Срок создания заявки истёк
  Given дата фактического получения товара известна
  And срок создания заявки истёк (более 14 дней; F&F — более 30)
  When клиент открывает карточку заказа
  Then система не показывает кнопку «Оформить возврат»
  And начало оформления возврата недоступно

Scenario: Дата фактического получения товара не определена
  Given система не может определить дату фактического получения товара
  When клиент открывает карточку заказа
  Then система не предлагает оформление возврата до уточнения даты (обработка открыта — `COM-OQ-27`)
```

## US-102: Выбор изделий и причин возврата

Как клиент
Я хочу выбрать одно или несколько изделий из заказа и указать причину возврата по каждому
Чтобы оформить возврат именно тех позиций, которые мне не подошли

Приоритет: Must have
Оценка: 5 story points
Ценность: запускает корректный расчёт суммы к возврату и комплектность обработки.
Зависимости: US-101

```gherkin
Feature: Выбор изделий и причин возврата

Scenario: Выбор изделий и причин по каждому
  Given клиент перешёл к оформлению возврата по заказу
  When система показывает изделия, доступные для возврата
  When клиент выбирает изделие и количество в пределах доступного остатка
  And указывает основную причину и уточняющую подпричину по каждому изделию
  Then система позволяет перейти к оформлению
  And к возврату учитываются только выбранные изделия

Scenario: Невозвратная категория, заявлен брак **(под вопросом)**
  Given изделие относится к категории, недоступной для возврата товара надлежащего качества
  When клиент выбирает причину «Брак»
  Then система принимает причину «Брак» и позволяет продолжить оформление
  And система не показывает причины возврата надлежащего качества для этого изделия

Scenario: Причина указана не для всех изделий
  Given клиент выбрал несколько изделий
  And причина указана не для всех выбранных изделий
  When клиент пытается перейти к оформлению
  Then система блокирует переход до указания причины по каждому изделию

Scenario: Недостаточный доступный остаток
  Given часть выкупленного количества ранее возвращена или включена в другую действующую заявку
  When клиент выбирает количество больше доступного остатка
  Then система не позволяет выбрать количество больше доступного остатка
  And максимальным значением для выбора является доступное к возврату количество
```

## US-103: Определение города и списка доступных способов возврата

Как клиент
Я хочу выбрать город возврата и видеть только те способы, которые реально доступны
Чтобы не выбирать неподходящий способ и не сталкиваться с недоступной сдачей

Приоритет: Must have
Оценка: 5 story points
Ценность: снижает число прерванных оформлений и обращений в поддержку по недоступным каналам.
Зависимости: US-102

```gherkin
Feature: Город и доступные способы возврата

Scenario: Город определён, способы доступны
  Given система предзаполнила город возврата
  When клиент подтверждает город или выбирает другой
  Then система показывает только способы возврата, доступные для города и данных заказа
  And клиент может выбрать один из способов

Scenario: Нет ни одного доступного способа **(под воросом?)**
  Given после применения ограничений по городу и месту покупки список способов пуст
  When клиент открывает страницу оформления возврата
  Then система не показывает пустой список
  And отображает сообщение о недоступности возврата в выбранном городе
  And клиент может изменить город, после чего система повторно проверяет доступность

Scenario: Город не определён
  Given системе не удалось предзаполнить город или страну
  When клиент открывает страницу оформления
  Then клиент выбирает город самостоятельно
  And система проверяет доступность способов для выбранного города
```

## US-104: Банковские реквизиты для возврата денег

Как клиент, оплативший заказ курьеру
Я хочу указать банковские реквизиты для возврата денег
Чтобы получить деньги за возвращённый товар на свой счёт

Приоритет: Must have
Оценка: 5 story points
Ценность: обеспечивает возврат денег для заказов с оплатой при получении; исключает CVV/паспортные данные.
Зависимости: US-105

```gherkin
Feature: Банковские реквизиты

Scenario: Заказ оплачен курьеру при получении — реквизиты запрашиваются
  Given заказ доставлен курьером с примеркой и оплачен курьеру наличными или картой
  When клиент переходит к заполнению банковских реквизитов
  Then система запрашивает фамилию, имя и отчество держателя счёта, БИК и номер лицевого счёта
  And отчество является обязательным полем
  And система никогда не запрашивает CVV и паспортные данные
  And после заполнения клиент возвращается на страницу оформления возврата

Scenario: Заказ с онлайн-оплатой (обычный курьер и др.) — реквизиты недоступны для ввода
  Given заказ оплачен онлайн (в т.ч. обычная курьерская доставка без примерки)
  When клиент оформляет возврат
  Then система не показывает форму банковских реквизитов
```
