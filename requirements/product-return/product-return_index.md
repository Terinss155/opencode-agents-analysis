# Требования: возврат товара и возврат денежных средств

Версия бандла: 1 · Дата: 10.09.2026 · Статус: Черновик

Единый логический документ для согласования будущего процесса возврата. Файлы разложены по
подпапкам по типу артефакта; связь между вкладками — по стабильным ID (`BO-`, `PP-`, `BR-`,
`US-`, `UC-RET-`) и ссылкам. Расшифровка префиксов — в легенде матрицы трассируемости.

| Вкладка | Расположение | Назначение | Статус |
|---|---|---|---|
| 00. BRD | [product-return_brd.md](./product-return_brd.md) | Бизнес-цели, границы, AS-IS, целевое состояние (состав возможностей), бизнес-требования | Черновик |
| 01. User Stories | [user-story/](./user-story/product-return_user-story.md) | Пользовательские требования (US-100…US-206) + Acceptance Criteria | В работе |
| 02. Use Cases | [use-case/](./use-case/) | Детализация сложных участков сценария оформления возврата. **В консолидации:** два файла (`product-return_use-case.md`, `product-return_use-case-to-be.md`) подлежат слиянию в единый TO-BE Use Case | DRAFT |
| — Спецификации экранов | [screen-spec/](./screen-spec/product-return_screen-spec.md) | Экраны восприятия (`SCR-RET-01` карточка возврата, `SCR-RET-02` список) | DRAFT |
| 03. Матрица трассируемости | [product-return_traceability.md](./product-return_traceability.md) | Три таблицы: обоснование (BO→PP→BR→US→UC), реализация вниз (US→UC→бэк→данные→API→sequence→экран→NFR→тест), реестр технических артефактов | Черновик |
| — Бизнес-кейс | [product-return_business-case.md](./product-return_business-case.md) | Проблема, финансовая модель, ROI, Payback, рекомендация Go/No-Go | Готов (цифры — оценочные допущения PO) |
| — Приоритизация backlog | [product-return_backlog-priority.md](./product-return_backlog-priority.md) | RICE + MoSCoW по фичам | Готов |
| — AS-IS (пошагово) | [as-is/](./as-is/00-overview.md) | Как процесс работает сейчас — по фактам кодовой базы `12storeez-master` (сайт + мобильное приложение) | DRAFT |
| — Задачи для бэкенда (SIS) | [backend/](./backend/) | `available_return_quantity`, определение возможности возврата, модель данных сущности «возврат» | DRAFT |
| — Sequence-диаграммы (SIS) | [sequence/](./sequence/) | Последовательности по системам (web, mobile, 1С, RCRM, прочие) | — |
| — Вспомогательный анализ | [info/](./info/order-edit_analysis.md) | Разбор кодовой базы: email при заказе, срок возврата по статусу клиента, редактирование заказа | — |

**Порядок чтения:** 00 (BRD) → 01 (User Stories) → 02 (Use Cases по ссылкам из сложных историй).
Исходные бизнес-материалы (общие правила и канальные процессы TO-BE) — в `../drafts/`.
