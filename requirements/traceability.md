# Матрица трассируемости: возврат товара и возврат денежных средств

Версия бандла: 7 · Дата: 11.09.2026 · Статус: Черновик

Вкладка 03 бандла [index.md](./index.md). Прослеживает
требование на всю глубину: `BO → PP → BR → US → UC → бэк-логика → модель данных → API →
sequence → экран → NFR → тест`. Связывает идентификаторы вкладок; содержание артефактов не
пересказывает. Критерии приёмки (AC) живут рядом со своими историями в
[user-story/user-story.md](./user-story/user-story.md) и в
матрицу не выносятся.

**Снизу вверх:** все US трассируются до BR и BO; каждый UC — до своей US. Use Case без родительской US нет.

**Реализация (таблица 2 / 3):**
- `TASK-RET-DATA` (модель данных сущности «возврат») покрывает создание, просмотр и жизненный цикл заявки — US-105…US-107, US-109…US-112, канальные US-201…US-206; описана один раз в таблице 3, в таблице 2 повторяется только ID.
- Бэк-логика проверки права и количества (`BL-RET-ELIG-01`, `BL-RET-QTY-01`) — только вход в оформление (US-101, US-102, UC-RET-01).
- Sequence-диаграммы покрывают шаг создания заявки и исходящие интеграции (US-105 / UC-RET-05).
- Экраны восприятия (`SCR-RET-01/02`) покрывают просмотр карточки, идентификаторов, списка и скачивание заявления (US-106, US-106.1, US-106.2, US-107).

**Открытые места (не пустые ячейки молча):**
- Use Case для US-106, US-107, US-109…US-112 не создаётся: это экраны восприятия (`SCR-RET-*`), простые действия по AC либо процессы вне контура оформления (US-111, US-202), либо детализация заблокирована открытым вопросом (US-110, US-112 → `OQ-1`). `US-108` снята с текущего и подтверждённого Post-MVP-объёма; её ID зарезервирован.
- US-206 (розничный магазин): бизнес-процесс канала не описан — критерии приёмки и Use Case требуют уточнения PO/BA (`OQ-27` — единые правила экспертизы; `OQ-33` — заявка по чеку магазина).
- Единая статусная модель (`OQ-1`) затрагивает US-106, US-110, US-112 и все канальные US — до ответа статусы держатся как «Черновик».
- `OQ-39` блокирует приёмку `US-202`; `OQ-40` и `OQ-41` описывают альтернативную сдачу в другой точке и не блокируют основной сценарий с выбранной точкой.
- Требования стороны компании (`BR-21`…`BR-23`, `BR-25`) во вкладке 01 отдельными US не представлены — истории заводятся при переходе к соответствующей волне.
- `BR-34` относится к возможной автоматизации Post-MVP и не имеет User Story: системная категорийная блокировка снята с MVP, а границы будущей доработки не подтверждены.
- ERD, OpenAPI-контракты, NFR и тест-кейсы для процесса не создавались — в таблице 2 соответствующие столбцы `—`; это осознанный пробел, не упущение матрицы.
