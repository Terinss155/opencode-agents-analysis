# Требования: возврат товара и возврат денежных средств

Версия бандла: 8 · Дата: 11.09.2026 · Статус: Черновик

Единый логический документ для согласования будущего процесса возврата. Файлы разложены по
подпапкам по типу артефакта; связь между вкладками — по стабильным ID (`BO-`, `PP-`, `BR-`,
`OQ-`, `US-`, `UC-RET-`, `ADR-RET-`) и ссылкам. Расшифровка префиксов — в легенде матрицы трассируемости.

| Вкладка | Расположение | Назначение | Статус |
|---|---|---|---|
| 00. BRD | [brd.md](./brd.md) | Омниканальный возврат «Возвраты 2.0»: бизнес-цели, границы, AS-IS, целевое состояние (состав возможностей), бизнес-требования, открытые вопросы. Собран из несогласованного BRD заказчика и логов согласования в `drafts/` | Черновик (v5) |
| 01. User Stories | [user-story/](./user-story/user-story.md) | Эпик + пользовательские истории (US-101…US-206) + Acceptance Criteria; истории разложены по темам: оформление, просмотр, жизненный цикл, каналы | В работе |
| 02. Use Cases | [use-case/](./use-case/) | Детализация сложных участков сценария оформления возврата. **В консолидации:** два файла (`use-case.md`, `use-case-to-be.md`) подлежат слиянию в единый TO-BE Use Case | DRAFT |
| — Спецификации экранов | [screen-spec/](./screen-spec/screen-spec.md) | Экраны восприятия (`SCR-RET-01` карточка возврата, `SCR-RET-02` список) | DRAFT |
| — ADR | [adr/](./adr/) | 13 записей об обосновании решений: редактирование, сущность заявки, интеграция с ТК, отмена, выбор точки, ограничения категорий, комплектность, интерфейс Дружбы, предзаполнение способа и адреса, настройка каналов по Geo ID, отказ от карты Почты России, раздельное отображение одинаковых позиций, отказ от дублирования SMS | В работе |
| 03. Матрица трассируемости | [traceability.md](./traceability.md) | Три таблицы: обоснование (BO→PP→BR→US→UC), реализация вниз (US→UC→бэк→данные→API→sequence→экран→NFR→тест), реестр технических артефактов | Черновик (бандл v7, требования синхр. с BRD v5) |
| — Бизнес-кейс | [business-case.md](./business-case.md) | Учебный пример структуры бизнес-кейса; **источником данных для BRD не является** | Пример |
| — Приоритизация backlog | [backlog-priority.md](./backlog-priority.md) | RICE + MoSCoW по фичам | Готов |
| — AS-IS (пошагово) | [as-is/](./as-is/00-overview.md) | Как процесс работает сейчас — по фактам кодовой базы `12storeez-master` (сайт + мобильное приложение) | DRAFT |
| — Задачи для бэкенда (SIS) | [backend/](./backend/) | `available_return_quantity`, определение возможности возврата, модель данных сущности «возврат» | DRAFT |
| — Sequence-диаграммы (SIS) | [sequence/](./as-is/sequence/) | Последовательности по системам (web, mobile, 1С, RCRM, прочие) | — |
| — Вспомогательный анализ | [info/](./info/order-edit_analysis.md) | Разбор кодовой базы: email при заказе, срок возврата по статусу клиента, редактирование заказа | — |

**Порядок чтения:** 00 (BRD) → 01 (User Stories) → 02 (Use Cases по ссылкам из сложных историй).
Исходные бизнес-материалы — в `drafts/`: несогласованный BRD заказчика `BRD_Возвраты_2_0.docx`,
трекер вопросов `Вопросы_к_БТ_Возвраты_2.0_1.xlsx`, консолидированные логи решений
`Резюме встречи 21.08.2026 — актуальная версия (04.09.2026).md` и резюме встречи от 10.09.2026,
общие правила и канальные процессы TO-BE.

[`drafts/transcriptions/`](drafts/transcriptions/). Добавлена первичная транскрибация
встречи от 10.09.2026 по дополнительным вопросам сайта и мобильного приложения.
