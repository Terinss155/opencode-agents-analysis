# ADR-RET-020: Минимальный набор банковских реквизитов в форме, недостающее запрашивает Дружба

## Контекст

В согласованном макете формы реквизитов есть только поле «Номер банковской карты». Правило
допускает номер карты или номер договора (кредитный счёт), поэтому возник вопрос (`OQ-46`):
отклонит ли банк возврат клиенту без карты, если поля для договора нет.

Раньше для нерезидентов дополнительно запрашивали полные реквизиты счёта и иные данные.

## Решение

Клиент вводит в форме минимальный набор реквизитов (`FR-37`). Отдельные поля для редких случаев
(номер кредитного договора, дополнительные данные нерезидентов) в форму не добавляются.

Если для возврата денежных средств данных не хватает, отдел Дружбы сам связывается с клиентом и
запрашивает их.

## Последствия

### Положительные

- Форма не усложняется для большинства клиентов.
- Scope сайта и МП не растёт за счёт полей и валидаций для единичных случаев.

### Отрицательные и риски

- В редких случаях Дружба выполняет ручную работу, а возврат денег задерживается.
- Нужен процесс, по которому Дружба узнаёт о нехватке данных. Он не описан. 25.09.2026
  рассматривается передача реквизитов из ЛК в RetailCRM, где Дружба может их исправить
  ([User Story, «Требуют подтверждения до фиксации», п. 19](../user-story/user-story.md)).

## Рассмотренные альтернативы

### Добавить поле «Номер договора» и поля для нерезидентов

- **Результат:** отклонена.
- **Причина:** такие случаи редки, а недостающие данные Дружба запрашивает у клиента напрямую.

## Условия пересмотра

- Доля возвратов, по которым Дружба запрашивает недостающие реквизиты, становится заметной
  нагрузкой или заметно задерживает возврат денег.
