# ADR-RET-005: Обязательный выбор конкретной точки передачи возврата

| Поле | Значение |
|---|---|
| **Статус** | Принято |
| **Дата решения** | 10.09.2026 |
| **Владелец решения** | Head of PMO — Светлана Варцаба; согласующие: Product Owner — Рома Пушкарь, Product Manager — Катя Филатова, System Analyst — Елена Васильева, System Analyst — Катя Лемешева |
| **Область** | Продукт / Бизнес-процесс |

## Контекст

Для возврата через ПВЗ рассматривались два клиентских пути: выдать универсальный код и предложить
обратиться в любой пункт либо провести клиента через выбор конкретной точки. Не все пункты,
которые выдают заказы, принимают возвраты. Формулировка «принесите в любой ПВЗ» создаёт риск
отказа в точке и неопределённость для клиента.

Выбор конкретного пункта добавляет шаг в оформление, но фиксирует намерение клиента и позволяет
показать актуальные адрес, часы работы и крайний срок передачи.

## Решение

При оформлении клиент выбирает конкретную точку передачи из актуального перечня точек, которые
принимают возвраты. Выбранная точка сохраняется в заявке и отображается клиенту.

Возможность сдать изделие в другой точке той же ТК по ранее полученному коду этим решением не
определена и требует отдельного подтверждения партнёра.

## Последствия

### Положительные

- Клиент получает определённый и предсказуемый следующий шаг.
- Снижается риск обращения в пункт, который не принимает возвраты.
- Компания получает данные о планируемой точке передачи.

### Отрицательные и риски

- В оформление добавляется обязательный шаг выбора точки.
- Необходим актуальный источник признака «принимает возвраты» для каждого ПВЗ.
- При закрытии или смене точки клиенту может потребоваться отменить и пересоздать заявку.

## Рассмотренные альтернативы

### Универсальный код без выбора конкретного ПВЗ

- **Результат:** отклонена.
- **Причина:** не все ПВЗ принимают возвраты; клиент остаётся без однозначного места передачи.

### Показать только карту ближайших пунктов без сохранения выбора

- **Результат:** отклонена для целевого пути.
- **Причина:** не фиксирует завершённость выбора и не даёт компании информацию о планируемой
  точке передачи.

## Условия пересмотра

- Транспортная компания подтверждает, что любой отображаемый пункт принимает возвраты по одному
  универсальному коду и выбор точки не используется ни одной системой процесса.
- Метрики MVP показывают, что обязательный выбор создаёт неприемлемую долю отмен и пересозданий;
  порог должен определить владелец продукта.
