# User Story: Возврат товара и возврат денежных средств

**Документ:** вкладка 01 бандла требований — пользовательские истории (User Story) на процесс возврата товара и возврата денег клиентом. Файл — контекст вкладки: подтверждённые факты, открытые вопросы, эпик, снятые истории, чек-лист качества. Истории разложены по темам:
- [user-story-creation.md](./user-story-creation.md) — оформление возврата (US-101…US-105);
- [user-story-view.md](./user-story-view.md) — просмотр возврата (US-110…US-113);
- [user-story-lifecycle.md](./user-story-lifecycle.md) — жизненный цикл возврата (US-120…US-123);
- [user-story-channels.md](./user-story-channels.md) — канальные истории (US-201…US-206).

**Домен:** E-commerce / Fashion-ритейл. Стиль — INVEST, Acceptance Criteria — Gherkin.
**Источники фактов:** `../drafts/obshie-biznes-pravila-oformleniya-vozvrata.md`, `../drafts/vozvrat-kurerom-biznes-process-to-be.md`, `../drafts/vozvrat-cherez-sdek-pvz-biznes-process-to-be.md`, `../drafts/vozvrat-cherez-5post-biznes-process-to-be.md`, `../drafts/transcriptions/[bandicam 2026-09-10 14-00-15-394] PJ Возвраты (доп вопросы по сайту и приложениям).md`.

## Подтверждённые исходные данные (факты, не допущения)

- Срок создания заявки в MVP: **14 дней для всех клиентов** с даты фактического получения товара. 30-дневный срок F&F отложен до появления доступного сайту и МП признака F&F. Датой подачи считается дата создания заявки в ЛК. (`BR-12`, `C-6`)
- Каналы возврата: **Курьер**, **СДЭК ПВЗ/офис**, **5Post**, **розничный магазин**, **Почта России**. Дистанционные каналы — Курьер, СДЭК, 5Post и Почта России; они применяются только к онлайн-покупке. (`BRD FR-3.x`, уточнение заказчика от 07.09.2026)
- По уточнению заказчика от 07.09.2026 в клиентский путь добавлена **Почта России**: способ доступен только для Калининграда и не требует выбора конкретного отделения при оформлении.
- Базовый набор каналов зависит от места покупки: розничная покупка возвращается только в розничный магазин, покупка в аутлете — только в аутлет, покупка в «Цветном» — только в «Цветной»; для онлайн-покупки доступны розничный магазин, Курьер, 5Post, СДЭК и Почта России с последующей фильтрацией по городу и другим ограничениям.
- Банковские реквизиты запрашиваются **только при оплате заказа курьеру при получении** (наличными или картой — доставка «курьер с примеркой»). Обычная курьерская доставка возможна только с онлайн-оплатой — для неё, как и для всех прочих онлайн-способов, форма не показывается, деньги возвращаются исходным способом, а клиенту выводится текст-подсказка про обращение в поддержку «Дружба» для перевода по другим реквизитам. В форме обязательны фамилия, имя, **отчество**, БИК, номер лицевого счёта; для счёта `30232810...` обязателен номер карты/договора; CVV и паспорт не запрашиваются. (`BR-COM-05`–`BR-COM-07`)
- Возврат денег для Курьера/СДЭК/5Post — **до 10 дней** с момента поступления товара на склад и подтверждения соответствия условиям возврата. ("`BR-COM-17`", "`BR-COM-22`")
- Для возврата через магазин срок возврата денег составляет **до 10 дней** с момента приёма товара и подтверждения его соответствия условиям возврата сотрудником магазина.
- После создания заявки действует **отдельный срок передачи** возврата; если клиент не передал товар — заявка автоматически отменяется. Срок передачи не является остатком 14-дневного срока создания. (`BR-COM-23`, `BR-COM-28`)
- Если заявка автоотменена до истечения 14-дневного срока, клиент может создать новую заявку. (`BR-COM-29`)
- Клиент не редактирует созданную заявку. Для изменения данных заявка отменяется и создаётся заново, если отмена и повторное оформление ещё доступны. (`BR-10`, `ADR-RET-001`)
- Бизнес-граница самостоятельной отмены — физическая передача изделия курьеру, ПВЗ, постамату или магазину. Для курьерского канала техническое событие и статус, по которым сайт / МП узнают о передаче, не определены — вопрос зафиксирован под `US-202` (`OQ-39`). (`BR-11`, `BR-15`, `ADR-RET-004`)
- Начальный клиентский статус заявки — «Заявление на возврат создано». Единая статусная модель возврата и маппинг канальных статусов требуют согласования. (`COM-OQ-04`, `COM-OQ-05`)
- Отдельный клиентский статус «возврат денег» не отображается — этап входит в общую статусную модель. Блок «Возврат средств» (способ и ожидаемый срок) отображается после создания заявки. (`BR-COM-19`, общий процесс 7.2)
- Электронное заявление формируется по запросу из данных БД (PDF отдельно не хранится), скачивается клиентом из ЛК; подпись не требуется. (`BR-COM-08`–`BR-COM-10`)
- Клиенту без авторизации доступен пустой бланк заявления для ручного заполнения. Беларусь и Казахстан не входят в MVP. (`BR-COM-26`)
- Самостоятельный перенос даты/времени курьера **не входит в MVP**. (`BR-CUR-05`)
- QR-код "Узнайте, как вернуть" на упаковке — целевой путь ведёт в ЛК; точный адрес требует согласования. (`COM-OQ-14`)

# Эпик: Оформление возврата товара

Как пользователь, совершивший покупку,

Я хочу оформить возврат одного, нескольких или всех доступных товаров из заказа удобным доступным способом,

Чтобы вернуть неподошедшие товары и получить за них денежные средства и использованные баллы в соответствии с условиями возврата.

**Тип:** эпик (контейнер историй), не User Story — ID `US-<n>` не присваивается; критерии INVEST, включая Small, к эпику не применяются.

**Приоритет:** Must have

**Оценка:** не оценивается в story points; оценка — сумма дочерних историй.

**Бизнес-ценность:** пользователь самостоятельно оформляет возврат и выбирает доступный для города канал без обращения в поддержку.

**Состав (декомпозиция):**
- Оформление: [user-story-creation.md](./user-story-creation.md) — US-101…US-105
- Просмотр: [user-story-view.md](./user-story-view.md) — US-110…US-113
- Жизненный цикл: [user-story-lifecycle.md](./user-story-lifecycle.md) — US-120…US-123
- Каналы: [user-story-channels.md](./user-story-channels.md) — US-201…US-206

**Сценарий:** сквозной путь оформления раскрыт Use Case `UC-RET-01…UC-RET-05`; собственных Acceptance Criteria у эпика нет — критерии живут в дочерних историях (Золотое правило: пользовательский сценарий не пересказывается на нескольких уровнях).

# Снятая история: изменение состава созданной заявки

История об изменении состава созданной заявки снята с текущего и подтверждённого Post-MVP-объёма.

Причина: в MVP редактирование созданной заявки запрещено (`BR-10`, `ADR-RET-001`). Состав
будущих изменений не определён: неизвестно, какие поля и при каких условиях бизнес может
разрешить редактировать после MVP. Новая User Story создаётся только после подтверждения
пользовательской потребности и границ редактирования.

В новой нумерации ID истории не присваивается. Acceptance Criteria отсутствуют, поскольку
пользовательское требование снято.
