## US-CR-01: Просмотр условий и возможности возврата по заказу

Как клиент, совершивший покупку
Я хочу иметь возможность начать оформление возврата из карточки заказа, если возврат для заказа ещё доступен
Чтобы самостоятельно оформить возврат без обращения в поддержку

Приоритет: Must have
Оценка: 3 story points
Ценность: позволяет клиенту самостоятельно перейти к оформлению возврата для подходящего заказа и исключает попытки оформить возврат, если он уже недоступен.
Зависимости: —

**Бизнес-правила**

- Для обычных клиентов срок оформления возврата составляет 14 дней с момента получения заказа включительно.
- Для клиентов F&F срок оформления возврата составляет 30 дней с момента получения заказа включительно.

```gherkin
Feature: Доступность оформления возврата из карточки заказа

Scenario: Возврат доступен
  Given клиент открыл принадлежащий ему заказ
  And срок оформления возврата не истёк
  And в заказе есть хотя бы одно изделие, доступное для возврата
  When клиент просматривает карточку заказа
  Then клиенту доступно начало оформления возврата
  And клиенту доступна информация о дате, до которой возврат может быть оформлен

Scenario: Возврат снова доступен после автоотмены предыдущей заявки
  Given ранее созданная заявка на возврат была автоматически отменена
  And срок оформления возврата по заказу не истёк
  And изделие доступно для возврата
  When клиент просматривает карточку заказа
  Then клиенту доступно повторное оформление возврата

Scenario: Срок оформления возврата истёк
  Given срок оформления возврата по заказу истёк
  When клиент просматривает карточку заказа
  Then начало оформления возврата недоступно

Scenario: Нет изделий, доступных для возврата 
  Given клиент авторизован 
  And клиент открыл принадлежащий ему заказ 
  And в заказе нет изделий, доступных для возврата 
  When клиент просматривает карточку заказа 
  Then клиенту недоступно начало оформления возврата
```

## US-CR-02: Выбор изделий и причин возврата

Как клиент, оформляющий возврат
Я хочу выбрать одно или несколько изделий из заказа и указать причину возврата для каждого выбранного изделия
Чтобы сформировать возврат только для тех изделий, которые я хочу вернуть

Приоритет: Must have
Оценка: 8 story points (переоценено: добавлен поюнитный выбор галочками вместо счётчика — `ADR-RET-012`, и сценарий кофра/подарка — `ADR-RET-009`)
Ценность: обеспечивает корректное формирование состава возврата и фиксацию причины возврата по каждому выбранному изделию.
Зависимости: US-CR-01

```gherkin
Feature: Формирование состава возврата и указание причин

Scenario: Выбор изделий для возврата 
  Given клиент начал оформление возврата по заказу 
  And в заказе есть изделия, доступные для возврата 
  When клиент выбирает одно или несколько изделий 
  Then выбранные изделия включаются в формируемый возврат 
  And клиенту доступен переход к указанию причин возврата

Scenario: Ни одно изделие не выбрано 
  Given клиент начал оформление возврата по заказу 
  And не выбрал ни одного изделия 
  When клиент продолжает оформление возврата 
  Then переход к указанию причин возврата недоступен

Scenario: Указание причины возврата для выбранных изделий 
  Given клиент выбрал одно или несколько изделий для возврата 
  When клиент указывает причину возврата для каждого выбранного изделия 
  Then указанная причина относится к соответствующему выбранному изделию
  And после указания обязательных причин для всех выбранных изделий клиенту доступно продолжение оформления возврата

Scenario: Причина возврата указана не для всех выбранных изделий 
  Given клиент выбрал несколько изделий для возврата 
  And обязательная причина возврата указана не для каждого выбранного изделия 
  When клиент пытается продолжить оформление возврата 
  Then продолжение оформления возврата недоступно 
  And клиенту необходимо указать причину для каждого выбранного изделия

Scenario: Изделие недоступно для повторного возврата 
  Given единица ранее возвращена или включена в другую действующую заявку
  When система определяет изделия, доступные для оформления возврата 
  Then такая единица изделия недоступна для включения в новый возврат

Scenario: Возврат части количества одной позиции 
  Given в заказе приобретено несколько единиц одной позиции 
  And только часть количества доступна для возврата 
  When клиент формирует состав возврата 
  Then клиент может выбрать для возврата только количество единиц в пределах доступного остатка

Scenario: Кофр или подарок является отдельной позицией заказа 
  Given кофр или подарок оформлен в заказе как отдельная позиция 
  When клиент выбирает связанное основное изделие для возврата 
  Then кофр или подарок не включается в возврат автоматически 
  And клиент может выбрать его отдельно, если он доступен для возврата 
  And клиенту предоставляется информация о необходимости вернуть изделие в полной комплектации

```

### UI/данные для отображения

Для каждого доступного к возврату изделия клиенту должна быть предоставлена информация, достаточная для его идентификации: изображение, наименование, артикул, цвет, размер и стоимость. Для изделия со скидкой отображаются текущая и первоначальная стоимости.

---

## Снято/отложено в Post-MVP: ограничение возврата по невозвратным категориям

Ограничение доступных причин (только «Брак») для отдельных категорий товаров (например,
чулочно-носочные изделия, бельё, купальники) не входит в MVP: в MVP возврат принимается
независимо от категории товара, системные ограничения по категориям и артикулам не
реализуются (`ADR-RET-006`, `RULE-31`, `FR-35`). Настройка категорий, причин и процесса экспертизы при
неподтверждённом браке переносится в Post-MVP и не имеет Acceptance Criteria в этой версии
бандла.

Условие возврата к теме: в ассортимент добавлена категория, для которой приём возврата
надлежащего качества признан недопустимым, либо согласованы правила категорий, причин,
экспертизы и обратной отправки при неподтверждённом браке (см. `ADR-RET-006` → «Условия
пересмотра»).

## US-CR-03: Определение города и списка доступных способов возврата

Как клиент, оформляющий возврат
Я хочу определить город возврата и получить доступные для моего заказа способы возврата
Чтобы выбрать подходящий способ и успешно продолжить оформление возврата

Приоритет: Must have
Оценка: 8 story points
Ценность: исключает выбор способов возврата, недоступных для конкретного заказа и города, и позволяет клиенту продолжить оформление по применимому сценарию.
Зависимости: US-CR-02

<a id="return-city-rules"></a>

**Связанные сценарии:** UC-RET-03 и UC-RET-04 в [Use Cases](../use-case/use-case.md).
**Открытые вопросы:** 
1. Как определяется способ возврата по умолчанию, если способ исходной доставки недоступен для возврата?
2. Если ранее выбранный способ возврата доступен в новом городе, должен ли он оставаться предвыбранным или система должна определить способ заново в соответствии с установленным порядком приоритетов?

**Бизнес-правила**

- Для заказа, оформленного в онлайн-магазине, могут быть доступны следующие способы возврата: розничный магазин, Курьер, 5Post, СДЭК ПВЗ, Почта России (только в Калининграде).

- Доступность конкретного способа дополнительно определяется городом и другими условиями заказа.

- Ограничения «только розничный магазин», «только аутлет» и «только Цветной» относятся к покупкам, совершённым непосредственно в соответствующем офлайн-канале, и не определяют сценарий возврата онлайн-заказа.

**Детальные сценарии выбора точки возврата, отображения карты/списка и данных точки описаны отдельно в требованиях соответствующих каналов возврата.*

```gherkin
Feature: Определение города и доступных способов возврата

Scenario: Для выбранного города доступны способы возврата 
  Given клиент оформляет возврат 
  And город возврата определён 
  When система определяет доступные способы возврата для выбранного города и заказа 
  Then клиенту доступны только способы возврата, применимые к выбранному городу и заказу
  And клиент может выбрать один из доступных способов возврата

Scenario: Город возврата не определён автоматически 
  Given системе не удалось определить город возврата на основании данных исходного заказа 
  When клиент продолжает оформление возврата 
  Then клиент может самостоятельно определить страну и город возврата 
  And после определения города система определяет доступные способы возврата

Scenario: Изменение города после предзаполнения данных возврата 
  Given клиент начал оформление возврата 
  And система определила город возврата и предзаполнила связанные данные на основании исходного заказа 
  When клиент инициирует изменение города возврата 
  Then система предупреждает клиента, что при изменении города ранее определённые данные оформления возврата будут сброшены 
  And изменение города выполняется только после подтверждения клиентом

Scenario: Подтверждение изменения города 
  Given клиент инициировал изменение города возврата 
  And система предупредила о сбросе ранее определённых данных 
  When клиент подтверждает изменение города 
  Then данные, зависящие от предыдущего города, сбрасываются
  And клиент может выбрать новый город возврата
  And для нового города система повторно определяет доступные способы возврата

Scenario: Отказ от изменения города 
  Given клиент инициировал изменение города возврата 
  And система предупредила о сбросе ранее определённых данных 
  When клиент не подтверждает изменение города 
  Then город возврата не изменяется 
  And ранее выбранные и заполненные данные оформления возврата сохраняются 
  And клиент продолжает оформление возврата с текущими данными

Scenario: Ранее выбранный способ доступен после смены города
  Given клиент изменил город возврата
  And ранее выбранный способ возврата доступен в новом городе
  When система повторно определяет доступные способы возврата
  Then ранее выбранный способ возврата остаётся предвыбранным
  And данные адреса или точки возврата предыдущего города не используются
  And клиент должен заново определить адрес или точку возврата, если они требуются для выбранного способа
 
Scenario: Ранее выбранный способ недоступен после смены города 
  Given клиент изменил город возврата 
  And ранее выбранный способ возврата недоступен в новом городе 
  And в новом городе имеется хотя бы один доступный способ возврата 
  When система повторно определяет доступные способы возврата 
  Then ранее выбранный способ возврата не используется 
  And система автоматически определяет доступный способ возврата в соответствии с установленным порядком приоритетов 
  And данные адреса или точки возврата предыдущего города не используются 
  And клиент может изменить автоматически определённый способ на другой доступный

Scenario: Для выбранного города отсутствуют доступные способы возврата 
  Given клиент определил город возврата 
  And для выбранного города и заказа отсутствуют доступные способы возврата 
  When система определяет доступные способы возврата 
  Then клиент информируется об отсутствии доступных способов возврата 
  And продолжение оформления возврата с текущим городом недоступно 
  And клиент может изменить город возврата

Scenario: Автоматическое определение способа возврата по исходному заказу 
  Given клиент оформляет возврат в городе исходного заказа 
  And способ доставки исходного заказа доступен для возврата 
  And адрес или точка исходной доставки доступны для возврата 
  When система определяет способ возврата 
  Then система автоматически выбирает способ возврата, соответствующий способу доставки исходного заказа 
  And предзаполняет адрес или точку возврата данными из исходного заказа 
  And клиент может изменить автоматически выбранный способ на другой доступный

Scenario: Исходный способ доставки недоступен для возврата
  Given способ доставки исходного заказа недоступен для возврата
  And доступен хотя бы один другой способ возврата
  When система определяет доступный способ возврата
  Then система автоматически выбирает способ возврата в соответствии с установленным порядком приоритетов
  And клиент может изменить автоматически выбранный способ на другой доступный

Scenario: Исходная точка недоступна для возврата
  Given выбран город исходного заказа
  And способ доставки исходного заказа доступен для возврата
  And исходная точка доставки недоступна для возврата
  When система определяет данные возврата по исходному заказу
  Then система автоматически выбирает соответствующий способ возврата
  And точка возврата не предзаполняется
  And клиент должен самостоятельно выбрать другую доступную точку возврата для продолжения оформления

Scenario: Возвращение к исходному городу заказа
  Given клиент изменил город возврата на город, отличный от города исходного заказа
  And способ доставки исходного заказа доступен для возврата 
  And исходный адрес или точка доступны для возврата
  When клиент снова выбирает город исходного заказа
  Then система повторно определяет доступные способы возврата для исходного города
  And предзаполняет способ возврата, соответствующий способу доставки исходного заказа 
  And предзаполняет исходный адрес или точку возврата

Scenario: Возвращение к исходному способу возврата 
  Given клиент находится в городе исходного заказа 
  And клиент изменил автоматически выбранный способ возврата на другой 
  And исходный адрес или точка доступны для возврата 
  When клиент снова выбирает способ возврата, соответствующий доставке исходного заказа 
  Then система предзаполняет исходный адрес или точку возврата
```

## US-CR-04: Определение способа возврата денежных средств

Как клиент, оформляющий возврат
Я хочу понимать, каким способом мне будут возвращены денежные средства, и при необходимости указать банковские реквизиты
Чтобы получить денежные средства за возвращённые изделия

Приоритет: Must have
Оценка: 5 story points
Ценность: обеспечивает корректный возврат денежных средств в зависимости от способа оплаты заказа и позволяет клиенту указать банковские реквизиты в случаях, когда возврат исходным способом оплаты невозможен.

**Открытый вопросы:** 
- что должно происходить при переходе к обращению в поддержку «Дружба»: отображение контактной информации, возможность инициировать звонок, переход в чат или другой сценарий?
- Как выполняется возврат при смешанной оплате: сертификат + банковская карта, сертификат + другой способ оплаты?

**Бизнес-требования**

- Фамилия, имя и отчество владельца счёта являются обязательными.
- Данные владельца счёта могут отличаться от данных клиента, оформляющего возврат.

**Ограничения**
- Система не должна запрашивать CVV.
- Система не должна запрашивать паспортные данные в рамках оформления возврата.

```gherkin
Feature: Определение способа возврата денежных средств

Scenario: Заказ оплачен курьеру при получении
  Given заказ был доставлен курьером с примеркой
  And клиент оплатил заказ курьеру наличными или банковской картой
  When клиент оформляет возврат
  Then клиент должен указать банковские реквизиты для возврата денежных средств
  And клиент должен указать фамилию, имя и отчество владельца банковского счёта
  And клиент должен указать название банка, БИК и номер банковского счёта
  And после заполнения обязательных реквизитов клиент может продолжить оформление возврата

Scenario: Заказ оплачен онлайн
  Given заказ был оплачен онлайн
  When клиент оформляет возврат
  Then банковские реквизиты для возврата денежных средств не запрашиваются
  And клиент информируется, что денежные средства будут возвращены исходным способом оплаты
  And клиент может перейти к обращению в поддержку «Дружба», если требуется возврат другим способом или на другие реквизиты

Scenario: Для кредитного счёта требуется дополнительный реквизит
  Given клиент должен указать банковские реквизиты для возврата денежных средств
  And номер банковского счёта начинается с `30232810`
  When клиент указывает банковские реквизиты
  Then клиент должен дополнительно указать номер банковской карты или номер договора

  Given клиент должен указать банковские реквизиты для возврата денежных средств

  And клиент информируется, что возврат будет выполнен на сертификат
```

## US-CR-05: Просмотр информации и создание заявки на возврат

Как клиент
Я хочу проверить данные оформляемого возврата и подтвердить его создание
Чтобы зафиксировать возврат и получить номер заявки для дальнейшего отслеживания

Приоритет: Must have
Оценка: 5 story points
Ценность: позволяет клиенту проверить сформированный возврат перед подтверждением, зафиксировать заявку и получить данные для дальнейшего отслеживания.
Зависимости: US-CR-02, US-CR-03, US-CR-04

**Бизнес-правило**

- Номер возврата формируется на основании номера исходного заказа и порядкового номера возврата по данному заказу.

Формат: `{номер заказа}-{порядковый номер возврата}`.

Пример: `598591-03`, где `598591` — номер исходного заказа, `03` — третий возврат, оформленный по данному заказу.
