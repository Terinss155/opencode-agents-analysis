# [B][Web] Карточка заказа. Доработать расчёт доступности возврата и срок оформления возврата

## Цель

Доработать данные страницы заказа на сайте, чтобы кнопка «Оформить возврат» показывалась с учётом категории клиента и уже созданных заявок — по тем же правилам, что в мобильном приложении (ECOMDEV-2343), — и сайт получал дату, до которой можно оформить возврат.

**Web**
- `GET /profile/view/{id}` — страница заказа; данные формируются на сервере и встраиваются в страницу

## Описание реализации

Что требуется изменить:

1. Доработать `GET /profile/view/{id}`.
2. Добавить новое поле в данные страницы:
   * `status.request_until_date`
3. Изменить расчёт `status.show_refund_button` — подключить общий расчёт доступности возврата из ECOMDEV-2343.

Вне этой задачи:
* общий расчёт доступности возврата и параметр `days_can_be_returned_ff` создаются в ECOMDEV-2343;
* текст «Можно вернуть изделия до …» под кнопкой выводит фронт сайта — отдельная задача;
* блок «Возврат средств» (`data.refund`) и данные доставки заказа для формы возврата отдаются в попапе возврата — задача на `GET /orders/refund/get-positions`;
* дата «Вернуть до …» — в методе `return-method-list`; сумма и баллы к возврату — отдельная задача;
* таблицы `cms_returns`, `cms_return_positions`, `cms_return_statuses` создаются задачей на модель данных.

#### 1\. Выходные параметры

Входные параметры не меняются.

{% cut "**Изменённые поля**" %}

| Параметр | Было | Стало |
|---|---|---|
| `status.show_refund_button` | `true`, если заказ выполнен или в возвратном статусе, срок `end_date + 14 дней` не истёк и хотя бы одна позиция в статусе «Добавлен» и не подарок | Дополнительно: срок считается по категории клиента (14 / 30 дней), и хотя бы у одной позиции остались изделия, не занятые заявками на возврат |

{% endcut %}

{% cut "**Новые поля**" %}

| Поле | Тип данных | Описание |
|---|---|---|
| `status.request_until_date` | `string` (`YYYY-MM-DD`) \| `null` | Последний день, когда можно оформить заявку на возврат. `null`, если у заказа нет даты выполнения или статус заказа не допускает возврат |

```json
{
  "id": 500128139,
  "status": {
    "show_refund_button": true,
    "request_until_date": "2026-10-15"
  }
}
```

{% endcut %}

#### 2\. Изменить логику определения доступности возврата

**Эндпоинт:** `GET /profile/view/{id}`

Метод проходит **общий расчёт доступности возврата из ECOMDEV-2343 целиком** — те же шаги, в том же порядке, без исключений. Расчёт реализуется один раз и используется обоими каналами; для сайта не дублируется. Отличается только то, что метод отдаёт в ответ.

{% cut "Какие шаги ECOMDEV-2343 выполняются" %}

| Шаг ECOMDEV-2343 | В этом методе |
|---|---|
| 1. Проверка статуса заказа | Да, без изменений |
| 2. Категория клиента и срок возврата | Да, без изменений; дата → `status.request_until_date` |
| 3. Проверка срока возврата | Да, без изменений |
| 4. Первичная проверка позиций | Да, без изменений: AS-IS-условия сайта те же, что в мобилке, — `status = 1`, `is_present = 0` |
| 5. Количество изделий в заявках | Да, без изменений |
| 6. Доступное количество | Да, без изменений |
| 7. Признак по позиции | Да, но по позициям в ответ не отдаётся — используется для `status.show_refund_button` |
| 8. Сообщение `can_be_returned` в `messages[]` | Нет — на сайте текст выводит фронт по `status.request_until_date` |
| 9. Банковские реквизиты | Нет — на сайте признак отдаётся в попапе возврата, логика не меняется |

{% endcut %}

{% cut "Изменить логику определения возврата" %}

1. Система выполняет общий расчёт доступности возврата по заказу (ECOMDEV-2343, шаги 1–7).

2. **Формирование `status.show_refund_button`**
   1. `status.show_refund_button = true`, если хотя бы у одной позиции заказа по результату расчёта возврат доступен (`<available_return_quantity> > 0`).
   2. Иначе `status.show_refund_button = false`.

3. **Формирование `status.request_until_date`**
   1. Значение — дата окончания срока возврата из расчёта (ECOMDEV-2343, шаг 2.7), в формате `YYYY-MM-DD`.
   2. Если срок не рассчитан (статус заказа не допускает возврат или нет `cms_orders.end_date`) — `null`.

> **AS-IS:** текущий расчёт кнопки (`Order::canBeReturned()`) заменяется общим расчётом. Его проверка срока через `days_can_be_returned` (14 дней) больше не применяется — она заменена проверкой срока с учётом категории клиента (ECOMDEV-2343, шаги 2–3). Остальные проверки страницы заказа не меняются.

{% endcut %}

{% cut "Маппинг API → БД" %}

| API | Тип данных | БД | Тип данных |
|---|---|---|---|
| `status.show_refund_button` | boolean | Динамический расчёт (ECOMDEV-2343, шаги 1–7) | — |
| `status.request_until_date` | string (`YYYY-MM-DD`) \| null | Динамический расчёт: `cms_orders.end_date + INTERVAL <days_limit> DAY` | — |

{% endcut %}

### Ошибки

Состав ошибок не меняется.
