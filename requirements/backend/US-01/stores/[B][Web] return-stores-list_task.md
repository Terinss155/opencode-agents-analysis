# [B][Web] Форма возврата. Метод для получения списка магазинов, принимающих возвраты

## Цель

Добавить для сайта метод, который возвращает магазины 12 STOREEZ, принимающие возвраты, в выбранном городе возврата — с тем же отбором и тем же набором данных, что метод мобильного приложения: для карты, списка и блока выбранного магазина. Подробная информация о магазине (карточка) — существующий метод `GET /content/showrooms/showroom-view?storeCode={store_code}`.

**Web**
- `GET /content/showrooms/showrooms-return?city_fias={city_fias}` — новый метод, AJAX-запрос формы возврата

## Описание реализации

Что требуется изменить:

1. Создать метод `GET /content/showrooms/showrooms-return`.
2. Входные и выходные параметры: `city_fias`; `data.items[]` со списком магазинов — раздел 1.
3. Подключить общий отбор магазинов из задачи `[B][Mobile API] Форма возврата. Метод для получения списка магазинов, принимающих возвраты` — раздел 2.

Вне этой задачи:
* признак `cms_catalog_stock.for_returns` и его вывод в админку — ECOMDEV-2359;
* общий отбор магазинов для возврата — создаётся в задаче `[B][Mobile API]`;
* расстояние до магазина и поиск по строке «Метро, улица или название…» — на стороне клиента, задача фронта сайта;
* подробная информация о магазине — существующий метод `GET /content/showrooms/showroom-view?storeCode={store_code}` без изменений: он отдаёт всё, что показывает карточка магазина в форме возврата (название, адрес, как добраться, режим работы, телефон, парковка). `storeCode` = `data.items[].store_code` из этого списка;
* существующий метод страницы «Магазины» `GET /content/showrooms/showrooms-city` не меняется и в форме возврата не используется.

#### 1. Входные и выходные параметры

**Входные параметры**

| Параметр | Место | Тип данных | Обязательность | Описание |
|---|---|---|---|---|
| `city_fias` | `query` | string | Да | ID города возврата в геосервисе (ФИАС для РФ) — город, выбранный в форме возврата |

Пагинации нет: метод возвращает все магазины города.

{% cut "**Выходные параметры**" %}

Поля элемента списка совпадают с методом мобильного приложения; отличается только конверт ответа сайта (`data` вместо `result`).

| Поле | Тип данных | Описание |
|---|---|---|
| `success` | bool | `true` — успешный ответ |
| `data.items` | object[] | Магазины, принимающие возвраты в городе. Пустой массив, если таких магазинов нет |
| `data.items[].store_code` | int | Код магазина. Передаётся в заявку на возврат |
| `data.items[].title` | string | Название магазина |
| `data.items[].address` | string \| null | Полный адрес — блок выбранного магазина |
| `data.items[].short_address` | string \| null | Короткий адрес — подзаголовок в списке |
| `data.items[].geo` | string | Координаты строкой `долгота,широта` — как в мобильном методе |
| `data.items[].schedule` | string \| null | Режим работы |

#### 2. Логика отбора магазинов

**Эндпоинт:** `GET /content/showrooms/showrooms-return?city_fias={city_fias}`

{% cut "Логика отбора магазинов" %}

**Проверки выполняются последовательно — от первого пункта к последнему.**

1. **Проверка входного параметра**
   1. `city_fias` передан и не пустой → шаг 2.
   2. Иначе → ошибка (раздел «Ошибки»), дальше не выполняется.

2. **Отбор магазинов** — общий отбор из задачи `[B][Mobile API]`, без изменений и без дублирования. Одно отличие — видимость магазина проверяется для сайта:
   1. `cms_catalog_stock.geo_id = city_fias`;
   2. `cms_catalog_stock.for_returns = 1`;
   3. `cms_catalog_stock.stock_type = 'shop'`;
   4. `cms_catalog_stock.latitude` и `cms_catalog_stock.longitude` заполнены;
   5. магазин видим на сайте — по `cms_catalog_stock._state`, как на странице «Магазины» (в мобильном методе — по `_state_mobile`).

   Порядок — как в мобильном методе: по `cms_catalog_stock.priority`, по убыванию. Не по названию, как на странице «Магазины» сайта (открытый вопрос 3).

3. **Формирование `data.items[]`** — так же, как `result[]` в мобильном методе: те же поля. Магазинов не найдено → `data.items = []`, `success = true`.

{% endcut %}

{% cut "Маппинг API → БД" %}

**Запрос → БД**

| API | Тип данных | БД | Тип данных |
|---|---|---|---|
| `city_fias` | string | `cms_catalog_stock.geo_id` | `varchar(36)` |

**Ответ ← БД**

| API | Тип данных | БД | Тип данных |
|---|---|---|---|
| `data.items[].store_code` | int | `cms_catalog_stock.store_code` | `smallint(6) unsigned` |
| `data.items[].title` | string | `cms_catalog_stock.title_ru` | `varchar(255)` |
| `data.items[].address` | string \| null | `cms_catalog_stock.address` | `varchar(255)` |
| `data.items[].short_address` | string \| null | `cms_catalog_stock.address_short` | `varchar(255)` |
| `data.items[].geo` | string | Динамический расчёт: `cms_catalog_stock.longitude` + «,» + `cms_catalog_stock.latitude` — как в мобильном методе | `varchar(50)` + `varchar(50)` |
| `data.items[].schedule` | string \| null | `cms_catalog_stock.working_time` | `varchar(255)` |

### Ошибки

Структура ошибки — плоская: ввода в форму нет. Ответ собирается так же, как у соседних методов страницы «Магазины».

| HTTP | Код (Web) | `target` | Сообщение | Когда |
|---|---|---|---|---|
| {red}(400) | — | `city_fias` | {red}(Не указан город — текст к согласованию) | `city_fias` не передан или пустой |

> **Ограничение:** соседние методы страницы «Магазины» на непредвиденные ошибки отвечают `success = true`, HTTP 200 и текстом ошибки в `message`. Ошибку параметра нужно вернуть явно: `success = false`.

## Тестирование

**Предусловия**
- Выполнены задачи на признак `cms_catalog_stock.for_returns` и `[B][Mobile API]` (общий отбор).
- В админке у магазинов города отмечен признак «Принимает возвраты», заполнены `geo_id` и координаты.
- В том же городе есть магазин без признака «Принимает возвраты», склад (`stock_type` ≠ `shop`) и магазин, скрытый на сайте.

**Критерии приёмки**
- Запрос с `city_fias` города возвращает только видимые на сайте магазины этого города с признаком «Принимает возвраты», `stock_type = 'shop'` и заполненными координатами.
- Набор и значения полей элемента совпадают с мобильным методом для того же города (кроме магазинов, видимость которых на сайте и в МП различается).
- Город без таких магазинов → `data.items = []`, `success = true`.
- Запрос без `city_fias` или с пустым значением → ошибка по разделу «Ошибки», не 500.
- Ответы `showrooms-city` и `showroom-view` не изменились.
- `GET /content/showrooms/showroom-view?storeCode=` с `store_code` любого магазина из списка возвращает его карточку.
