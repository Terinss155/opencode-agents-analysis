# [B][Mobile API] Форма возврата. Метод для получения списка магазинов, принимающих возвраты

## Цель

Добавить метод, который возвращает магазины 12 STOREEZ, принимающие возвраты, в выбранном городе возврата — с данными для карты, списка и блока выбранного магазина. Подробная информация о магазине (карточка) — отдельный метод.

**Mobile API**
- Site: `GET /mobile/stores/returns?city_fias={city_fias}` — новый метод монолита, создаётся в этой задаче
- Gate: `GET /api/v1/stores/returns?city_fias={city_fias}` — новый гейт `mobile.12stz.*`, задача `[B][Mobile API][Gate]` — в «Связях»

## Описание реализации

Что требуется изменить:

1. Создать метод `GET /mobile/stores/returns`.
2. Входные и выходные параметры: `city_fias`; `result[]` со списком магазинов — раздел 1.
3. Логика отбора магазинов, принимающих возвраты, — раздел 2. Отбор делается общим для сайта и мобильного приложения: метод сайта использует его без изменений.

Вне этой задачи:
* признак `cms_catalog_stock.for_returns` и его вывод в админку — ECOMDEV-2359 (блокирует эту задачу);
* проксирование на новом гейте — задача `[B][Mobile API][Gate]`;
* подробная информация о магазине — задача `[B][Mobile API] Форма возврата. Метод для получения подробной информации о магазине`;
* метод для сайта — задача `[B][Web]`, делается после;
* расстояние до магазина и поиск по строке «Метро, улица или название…» — на стороне клиента;
* существующие методы списка магазинов `GET /mobile/stores` и `GET /mobile/stores/cities` не меняются.

#### 1. Входные и выходные параметры

**Входные параметры**

| Параметр | Место | Тип данных | Обязательность | Описание |
|---|---|---|---|---|
| `city_fias` | `query` | string | Да | ID города возврата в геосервисе (ФИАС для РФ) — город, выбранный в форме возврата |

Пагинации нет: метод возвращает все магазины города.

{% cut "**Выходные параметры**" %}

| Поле | Тип данных | Описание |
|---|---|---|
| `success` | bool | `true` — успешный ответ |
| `result` | object[] | Магазины, принимающие возвраты в городе. Пустой массив, если таких магазинов нет |
| `total` | int | Количество магазинов в `result` |
| `result[].store_code` | int | Код магазина. Передаётся в заявку на возврат |
| `result[].title` | string | Название магазина |
| `result[].address` | string \| null | Полный адрес — блок выбранного магазина |
| `result[].short_address` | string \| null | Короткий адрес — подзаголовок в списке |
| `result[].geo` | string | Координаты строкой `долгота,широта` — как в текущем списке магазинов МП |
| `result[].schedule` | string \| null | Режим работы |

#### 2. Логика отбора магазинов

**Эндпоинт:** `GET /mobile/stores/returns?city_fias={city_fias}`

{% cut "Логика отбора магазинов" %}

**Проверки выполняются последовательно — от первого пункта к последнему.**

1. **Проверка входного параметра**
   1. `city_fias` передан и не пустой → шаг 2.
   2. Иначе → ошибка `1015` (раздел «Ошибки»), дальше не выполняется.

2. **Отбор магазинов** из `cms_catalog_stock` — одновременно выполняются условия:
   1. `cms_catalog_stock.geo_id = city_fias` — магазин находится в городе возврата. Не по `cms_catalog_stock.city_id`: это внутренний номер города, форма возврата его не знает;
   2. `cms_catalog_stock.for_returns = 1` — магазин принимает возвраты;
   3. `cms_catalog_stock.stock_type = 'shop'` — только магазины, без складов;
   4. `cms_catalog_stock.latitude` и `cms_catalog_stock.longitude` заполнены;
   5. магазин видим в мобильном приложении — по `cms_catalog_stock._state_mobile`, как в текущем списке магазинов МП.

   Порядок — по `cms_catalog_stock.priority`, по убыванию, как в текущем списке магазинов МП. Магазины с одинаковым `priority` идут в произвольном порядке (открытый вопрос 3).

3. **Формирование `result[]`**
   1. Каждый отобранный магазин → элемент `result[]`; поля — по «Маппинг API → БД».
   2. Магазинов не найдено → `result = []`, `total = 0`, `success = true`.

{% endcut %}

{% cut "Маппинг API → БД" %}

**Запрос → БД**

| API | Тип данных | БД | Тип данных |
|---|---|---|---|
| `city_fias` | string | `cms_catalog_stock.geo_id` | `varchar(36)` |

**Ответ ← БД**

| API | Тип данных | БД | Тип данных |
|---|---|---|---|
| `result[].store_code` | int | `cms_catalog_stock.store_code` | `smallint(6) unsigned` |
| `result[].title` | string | `cms_catalog_stock.title_ru` | `varchar(255)` |
| `result[].address` | string \| null | `cms_catalog_stock.address` | `varchar(255)` |
| `result[].short_address` | string \| null | `cms_catalog_stock.address_short` | `varchar(255)` |
| `result[].geo` | string | Динамический расчёт: `cms_catalog_stock.longitude` + «,» + `cms_catalog_stock.latitude` — как в текущем списке магазинов МП | `varchar(50)` + `varchar(50)` |
| `result[].schedule` | string \| null | `cms_catalog_stock.working_time` | `varchar(255)` |

{% endcut %}

### Ошибки

Структура ошибки — плоская: ввода в форму нет.

| HTTP | Код (Mobile) | `target` | Сообщение | Когда |
|---|---|---|---|---|
| 400 | `1015` | `city_fias` | {red}(Не указан город — текст к согласованию) | `city_fias` не передан или пустой |
| 401 | `1002` | — | AS-IS | Запрос без валидной сессии |

Пример ответа с ошибкой:

```json
{
  "success": false,
  "result": {
    "error_code": 1015,
    "error_text": "Не указан город"
  }
}
```

## Тестирование

**Предусловия**
- Выполнена задача на признак `cms_catalog_stock.for_returns`.
- В админке у магазинов города отмечен признак «Принимает возвраты», заполнены `geo_id` и координаты.
- В том же городе есть магазин без признака «Принимает возвраты», склад (`stock_type` ≠ `shop`) и магазин, скрытый в мобильном приложении.

**Критерии приёмки**
- Запрос с `city_fias` города возвращает только видимые в МП магазины этого города с признаком «Принимает возвраты», `stock_type = 'shop'` и заполненными координатами.
- Магазин без признака, склад и скрытый в МП магазин в ответ не попадают.
- `geo` — в формате `долгота,широта`, как в `GET /mobile/stores` для того же магазина; точка на карте совпадает с адресом магазина.
- Город без таких магазинов → `result = []`, `total = 0`, `success = true`.
- Запрос без `city_fias` или с пустым значением → ошибка `1015`, HTTP 400, не 500.
- Ответы `GET /mobile/stores` и `GET /mobile/stores/cities` не изменились.
