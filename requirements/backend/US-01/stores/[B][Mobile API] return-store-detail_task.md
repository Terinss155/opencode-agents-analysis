# [B][Mobile API] Форма возврата. Метод для получения подробной информации о магазине

## Цель

Добавить метод, который возвращает подробную информацию о магазине для карточки магазина в форме возврата — с тем же набором и теми же именами полей, что метод сайта `GET /content/showrooms/showroom-view?storeCode={store_code}`.

**Mobile API**
- Site: `GET /mobile/stores/{store_code}` — новый метод монолита, создаётся в этой задаче
- Gate: `GET /api/v1/stores/{store_code}` — новый гейт `mobile.12stz.*`, задача `[B][Mobile API][Gate]` — в «Связях»

## Описание реализации

Что требуется изменить:

1. Создать метод `GET /mobile/stores/{store_code}`.
2. Входные и выходные параметры: `store_code`; `result` с данными магазина — раздел 1.
3. Логика получения магазина — раздел 2.

Вне этой задачи:
* список магазинов, принимающих возвраты, — задача `[B][Mobile API] Форма возврата. Метод для получения списка магазинов, принимающих возвраты`; `store_code` для этого метода берётся из списка;
* проксирование на новом гейте — задача `[B][Mobile API][Gate]`;
* для сайта новый метод не нужен: карточку отдаёт существующий `GET /content/showrooms/showroom-view?storeCode={store_code}`;
* кнопка «Выбрать пункт выдачи» на карточке — действие клиента, данных не требует.

#### 1. Входные и выходные параметры

**Входные параметры**

| Параметр | Место | Тип данных | Обязательность | Описание |
|---|---|---|---|---|
| `store_code` | `path` | int | Да | Код магазина — `result[].store_code` из списка магазинов для возврата |

{% cut "**Выходные параметры**" %}

Имена и формат полей — как в ответе сайта `showroom-view`, чтобы карточка магазина на сайте и в МП строилась по одинаковым данным. Поля `country`, `countryIso`, `image`, `button` из ответа сайта не передаются: на карточке магазина в форме возврата они не используются.

| Поле | Тип данных | Описание |
|---|---|---|
| `success` | bool | `true` — успешный ответ |
| `result` | object | Данные магазина |

| `result.address` | string \| null | Полный адрес |

#### 2. Логика получения магазина

**Эндпоинт:** `GET /mobile/stores/{store_code}`

{% cut "Логика получения магазина" %}

**Проверки выполняются последовательно — от первого пункта к последнему.**

1. **Поиск магазина**
   1. Магазин с `cms_catalog_stock.store_code = store_code` найден → шаг 2.
   2. Иначе → ошибка «Магазин не найден» (раздел «Ошибки»), дальше не выполняется.

   Дополнительных проверок нет — так же, как в `showroom-view` сайта: признак «Принимает возвраты», тип склада и видимость не проверяются, потому что `store_code` берётся из списка, где эти условия уже выполнены.

2. **Формирование `result`** — поля по «Маппинг API → БД».

{% endcut %}

{% cut "Маппинг API → БД" %}

**Запрос → БД**

| API | Тип данных | БД | Тип данных |
|---|---|---|---|
| `store_code` | int | `cms_catalog_stock.store_code` | `smallint(6) unsigned` |

**Ответ ← БД**

| API | Тип данных | БД | Тип данных |
|---|---|---|---|
| `result.name` | string | `cms_catalog_stock.title_ru` | `varchar(255)` |
| `result.address` | string \| null | `cms_catalog_stock.address` | `varchar(255)` |
| `result.route` | string \| null | `cms_catalog_stock.route` | `varchar(500)` |
| `result.schedule` | string \| null | `cms_catalog_stock.working_time` | `varchar(255)` |
| `result.phone` | string | Динамический расчёт: `cms_catalog_stock.number` в формате `showroom-view` сайта | `varchar(50)` |
| `result.parking.name` | string \| null | `cms_catalog_stock.parking_name` | `varchar(255)` |
| `result.parking.schedule` | string \| null | `cms_catalog_stock.parking_schedule` | `varchar(255)` |
| `result.parking.price` | string \| null | `cms_catalog_stock.parking_price` | `text` |

### Ошибки

Структура ошибки — плоская: ввода в форму нет.

| HTTP | Код (Mobile) | `target` | Сообщение | Когда |
|---|---|---|---|---|
| {red}(404) | `1009` | — | Магазин не найден | Нет магазина с таким `store_code` |
| 400 | `1015` | `store_code` | {red}(текст к согласованию) | `store_code` не число |
| 401 | `1002` | — | AS-IS | Запрос без валидной сессии |

Пример ответа с ошибкой:

```json
{
  "success": false,
  "result": {
    "error_code": 1009,
    "error_text": "Магазин не найден"
  }
}
```

## Тестирование

**Предусловия**
- Выполнена задача на список магазинов для возврата; в городе есть магазины с признаком «Принимает возвраты».
- У одного магазина заполнены «Как добраться», телефон и парковка, у другого — не заполнены.

**Критерии приёмки**
- Запрос с `store_code` магазина из списка возвращает его название, адрес, «Как добраться», режим работы, телефон и парковку.
- Для того же магазина значения полей совпадают с ответом сайта `GET /content/showrooms/showroom-view?storeCode={store_code}`, включая случай с незаполненными телефоном и парковкой.
- Несуществующий `store_code` → ошибка `1009`, не 500.
- Нечисловой `store_code` → ошибка `1015`, не 500.
- Ответы `GET /mobile/stores` и `GET /mobile/stores/cities` не изменились.
