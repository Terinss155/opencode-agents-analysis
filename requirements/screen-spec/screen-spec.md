# Спецификация экранов: Возврат товара (TO-BE)

**Статус:** DRAFT
**Область:** сайт и мобильное приложение, просмотр возврата авторизованным пользователем.
**Назначение документа:** описать экраны **восприятия** процесса возврата — что клиент видит, из каких источников, при каких условиях и какие действия ему доступны. Процедурные сценарии создания и отмены — в `../use-case/use-case-to-be.md` и `../user-story/user-story.md`.
**Источники:** `../user-story/user-story-view.md` (US-110 — карточка, US-111 — идентификаторы, US-112 — список, US-113 — заявление), `../user-story/user-story-lifecycle.md` (US-120 — отмена), `../use-case/use-case-to-be.md` (UC-RET-05 — создание), `../backend/return-entity_data-model_task.md` (модель данных), макеты `../mockups/`.

> Почему спецификация экрана, а не Use Case: см. `AGENTS.md` → «Выбор артефакта». Экран возврата ничего не меняет в системе, «сценарий» = «открыл → показано»; ценность — в составе, источниках и правилах отображения.

## SCR-RET-01. Карточка созданного возврата

| Поле | Содержание |
|---|---|
| **Область действия** | Сайт и мобильное приложение, карточка созданного возврата |
| **Назначение** | Клиент видит состав и детали созданной заявки: статус и историю, дальнейшие шаги и срок передачи, способ возврата, возврат денег, документы; понимает, что оформлено верно, и пользуется доступными действиями |
| **Роль** | Авторизованный пользователь — владелец заказа |
| **Точки входа** | Автопереход сразу после создания заявки (`UC-RET-05`); открытие возврата из раздела «Возвраты» (`SCR-RET-02`) |
| **Источник данных** | `GET /returns/{return_id}` (сайт и МП) — **новый эндпоинт (TO-BE)**. В AS-IS отдельной сущности возврата и эндпоинта нет |
| **Стори** | `US-110` (карточка в целом), `US-111` (идентификаторы для передачи — блок 3), `US-113` (заявление) |
| **Связанные сценарии** | Приводит на экран: `UC-RET-05`. Запускается с экрана: раскрытие истории, «Скачать заявление» (`US-113`), «Отменить возврат» (`US-120`) |
| **Макеты** | `../mockups/20-view-return-created-courier.png` … `25-view-return-completed.png`, `26-qr-code.png` |

### Состав экрана

Блоки в порядке отображения сверху вниз.

| # | Блок | Что показывается |
|---|---|---|
| 1 | **Шапка** | Номер возврата, дата и время создания, действие копирования номера, кнопка «назад» |
| 2 | **Статус** (сворачиваемый) | Текущий статус возврата + действие раскрытия истории статусов |
| 3 | **Канальное действие с документом** | «Показать штрихкод» / «Показать QR-код» / «Скачать заявление» / «Скачать чек» — состав по правилам ниже |
| 4 | **«Что дальше»** | Инструкция по дальнейшим действиям; текст-шаблон, зависит от способа возврата. *Контент (копирайт) — вне рамок спецификации* |
| 5 | **«Способ возврата»** | Выбранный способ и относящиеся к нему данные (адрес / точка / часы работы / дата и интервал / «Вернуть до `<дата>`»). Способ **не редактируется** (`BR-COM-16`) |
| 6 | **«Возврат средств»** | Способ возврата денег + клиентский ожидаемый срок зачисления (текст задаётся бизнесом, напр. «в течение 3–5 дней в зависимости от банка») |
| 7 | **«Изделия к возврату · N»** | Счётчик и список: по **каждой возвращаемой единице** — изображение, цена (по макету — со скидкой и зачёркнутая «до скидки»), наименование, артикул, цвет, размер, выбранная причина возврата; после экспертизы — итог по единице (принята / отклонена). **Какую цену показывать на экране возврата — см. открытые вопросы** |
| 8 | **Итоги** | «Итого к возврату» (сумма) и «Баллы к возврату» |
| 9 | **Действия** | «Отменить возврат» + подпись, пока отмена разрешена |

### Правила отображения

**Блок 3 — канальное действие с документом:**

| Условие | Действие |
|---|---|
| Способ = СДЭК, набор идентификаторов получен | «Показать штрихкод» (штрихкод + номер накладной) |
| Способ = 5Post, набор идентификаторов получен | «Показать QR-код» (QR + PIN) |
| Способ = розничный магазин | «Показать QR-код» |
| Возврат оформлен через МП/сайт (любой способ) | «Скачать электронное заявление» (PDF формируется из данных возврата — `US-113`) |
| Статус = «Возврат завершён» / «Выполнен» (любой способ) | «Скачать чек» — **не заменяет** действие выше |

- Действия сочетаются: для СДЭК / 5Post / магазина одновременно доступны «Показать штрихкод/QR-код» и «Скачать заявление».
- Для Курьера и Почты России из блока 3 доступно только «Скачать заявление».
- Идентификаторы СДЭК / 5Post: пока полный набор не получен — действие «Показать штрихкод» / «Показать QR-код» **не отображается** (частичный набор не показываем). Кто и когда выпускает набор — открытый вопрос (`TECH-GAP-04`).

**Блок 5 — «Способ возврата», что показываем дополнительно:**

| Способ | Дополнительные данные |
|---|---|
| Курьер | адрес, дата и интервал приезда курьера |
| СДЭК ПВЗ / офис | адрес точки, дата и интервал (AS-IS) / срок передачи (TO-BE) |
| 5Post | адрес точки, часы работы, «Вернуть до `<дата>`» |
| Розничный магазин | название и ТЦ, адрес, часы работы, «Вернуть до `<дата>`» |
| Почта России | «Вернуть до `<дата>`» |

**Блок 2 — история статусов:** при раскрытии — список статусов с датой и временем каждого перехода в **обратном хронологическом порядке**; показываются только клиентские статусы (`is_client_visible`). Источник — `cms_return_status_history`.

**Блок 9 — «Отменить возврат»:** видно, пока для текущего статуса `cms_return_statuses.can_be_cancelled = true`; после получения монолитом события, соответствующего физической передаче возврата, — скрывается (`US-120`). Подпись: «Можно отменить возврат до того, как он будет передан в службу доставки». Для курьера точное техническое событие и допустимый временной лаг не определены (`OQ-39`).

**Блок 7 / блок 8 после экспертизы:** «Итого к возврату» и «Баллы к возврату» пересчитываются по **принятым** единицам; по каждой единице показывается её итог. Формат отображения итога по единице — открытый вопрос.

### Состояния экрана

| Состояние | Поведение |
|---|---|
| Загрузка | Индикатор загрузки, блоки не показаны |
| Возврат не найден / не принадлежит пользователю | Сообщение «Возврат не найден», карточка не открывается |
| Ошибка загрузки данных | Состояние ошибки + действие «Повторить» |
| Идентификаторы канала ещё не получены | Блок 3 без действия «Показать штрихкод / QR-код» (остальные блоки в норме) |
| Возврат отклонён | Итоговый статус «Отклонён» + причина отклонения (формат и место — открытый вопрос) |
| Возврат завершён | Итоговый статус; в блоке 3 — «Скачать чек»; действие «Отменить возврат» скрыто |

### Действия на экране

| Действие | Условие доступности | Что происходит |
|---|---|---|
| Копировать номер возврата | всегда | Номер копируется в буфер |
| Раскрыть историю статусов | всегда | Показывается список переходов (блок 2, правила отображения) |
| Показать штрихкод / QR-код + PIN | набор идентификаторов получен | Экран штрихкода/QR (`../mockups/26-qr-code.png`) |
| Скачать заявление | возврат оформлен через МП/сайт | PDF формируется из данных возврата — `US-113` |
| Скачать чек | статус «Возврат завершён» / «Выполнен» | Скачивается чек возврата (модуль Receipt) |
| Отменить возврат | `can_be_cancelled = true` для текущего статуса | Запускает `US-120` (отмена заявки) |

> Созданная заявка с карточки **не редактируется** (`BR-10`). Действий «Изменить состав», «Изменить способ», «Изменить точку» и «Перенести дату» нет; соответствующие элементы на макетах `20…24` устарели. Для изменения данных клиент отменяет заявку и создаёт новую, если эти действия ещё доступны.

### Параметры экрана

Данные — из `GET /returns/{return_id}`, из новых сущностей `cms_returns` / `cms_return_positions` / `cms_return_status_history` (см. `../backend/return-entity_data-model_task.md`). Поля изделия — join на `cms_order_positions` по `cms_return_positions.order_position_id`.

| Поле экрана | Источник (TO-BE) | Условие видимости / AS-IS |
|---|---|---|
| Номер возврата | `cms_returns.id` (или `return_order_num`) | AS-IS: номера заявки нет |
| Дата и время создания | `cms_returns.created_at` | всегда |
| Текущий статус | `cms_returns.status_id` → `cms_return_statuses.client_title` | AS-IS: статус **заказа** `cms_orders.status = 31` |
| История статусов (название + дата/время) | `cms_return_status_history[]` (`status_id` → `client_title`, `status_at`), только `is_client_visible` | при раскрытии; AS-IS: нет |
| Штрихкод + номер накладной (СДЭК) | `cms_returns.tracking_number` / `waybill_number` | набор получен; AS-IS: нет |
| QR-код + PIN (5Post) | `cms_returns.qr_code` / `cms_returns.pin_code` | набор получен; AS-IS: нет |
| «Скачать заявление» | формируется из данных возврата (`US-113`); PDF не хранится | оформлено онлайн; AS-IS: заявления нет |
| «Скачать чек» | документ чека возврата (модуль Receipt / `cms_order_position_refunds`) | статус завершён |
| Блок «Что дальше» (текст) | текст-шаблон по `cms_returns.delivery_method` | всегда; контент — вне рамок спецификации |
| Способ возврата — название | `cms_returns.delivery_method` → `cms_return_method.title` | AS-IS: `cms_orders.return_delivery_method` |
| Способ — адрес / точка | `cms_returns.address` / `point_id` + `point_provider` | по способу; AS-IS: `cms_orders.return_address` |
| Способ — часы работы точки | справочник точек ПВЗ / магазина (внешний сервис) | ПВЗ / магазин |
| Способ — дата и интервал (курьер) | `cms_returns.handover_planned_date` + `interval_from` / `interval_to` | способ = курьер; AS-IS: `cms_orders.return_date`, интервал не заполняется |
| «Вернуть до `<дата>`» | `cms_returns.handover_deadline` | способы без выбора даты; AS-IS: нет |
| Возврат средств — способ | `cms_returns.refund_target` (`bank_details` / `original_payment`) | всегда; AS-IS: `cms_orders.return_money` не заполняется |
| Возврат средств — ожидаемый срок (текст) | статический текст, задаётся бизнесом | всегда; юридический предел 10 дней отдельно не выводится |
| «Изделия к возврату · N» | `COUNT(cms_return_positions WHERE return_id = …)` | всегда |
| Изделие — изображение | `cms_order_positions.image_mobile_url` | всегда |
| Изделие — цена (уплаченная) | `cms_order_positions.price` | сумма, фактически уплаченная за единицу |
| Изделие — цена до скидки (зачёркнутая) | `cms_order_positions.price_before_discount` | каталожная «старая цена»; на экране возврата её показ спорен — см. открытые вопросы |
| Изделие — сумма к возврату за единицу | `cms_return_positions.refund_amount` | может быть меньше `price` при оплате баллами / промокодом / сертификатом — авторитетный источник для «сколько вернём» |
| Изделие — наименование / артикул | `cms_order_positions.model_title_ru` / `article` | всегда |
| Изделие — цвет / размер | `cms_order_positions.color_title_ru` / `size_title_ru` | всегда |
| Изделие — причина возврата | `cms_return_positions.reason_code` → `cms_return_reasons` (title через `cms_return_reasons_content`) | всегда; AS-IS: `cms_order_positions.reason` — одна на SKU-линию |
| Изделие — итог после экспертизы | `cms_return_positions.status_id` | после экспертизы; формат — открытый вопрос |
| «Итого к возврату» | `SUM(cms_return_positions.refund_amount)` (по принятым — после экспертизы) | всегда; AS-IS: не рассчитывается |
| «Баллы к возврату» | `SUM(cms_return_positions.refund_bonus_amount)` | всегда; AS-IS: не рассчитывается |
| «Отменить возврат» + подпись | видимость по `cms_return_statuses.can_be_cancelled` текущего статуса | `US-120` |

### Открытые вопросы

- **Цена изделия на экране возврата.** По макету показываются цена со скидкой + зачёркнутая «до скидки». Но клиент получит назад не каталожную цену, а уплаченную сумму (а с учётом баллов/промокода/сертификата — ещё меньше). Что показывать по каждой единице: уплаченную цену (`cms_order_positions.price`) или фактическую сумму к возврату за единицу (`cms_return_positions.refund_amount`); нужна ли вообще зачёркнутая «цена до скидки». Связано с открытым вопросом расчёта `refund_amount` (`../backend/return-entity_data-model_task.md`, §5).
- Формат и место отображения итога по единице после экспертизы (принята / отклонена) и причины отклонения.
- Открытие карточки сразу после создания: автопереход или экран-уведомление «Заявка создана».
- Точная формулировка клиентского текста в блоке «Возврат средств».
- Кто и когда выпускает набор идентификаторов СДЭК / 5Post (`TECH-GAP-04`); через какое время после создания заявки набор должен быть готов.
- Где на карточке показывать точку отсчёта срока возврата денег (поступление на склад + подтверждение).

## SCR-RET-02. Список возвратов

| Поле | Содержание |
|---|---|
| **Область действия** | Сайт и мобильное приложение, раздел «Возвраты» в личном кабинете |
| **Назначение** | Клиент видит все свои оформленные возвраты и их статусы в одном месте; находит нужный и переходит в его карточку |
| **Роль** | Авторизованный пользователь |
| **Точки входа** | Личный кабинет → «Возвраты» |
| **Источник данных** | `GET /returns?user_id=…` (сайт и МП) — **новый эндпоинт (TO-BE)** |
| **Связанные Use Case** | Открытие элемента списка → `SCR-RET-01`. Стори: `US-112` |
| **Макеты** | `../mockups/28-returns-list.png`, `29-returns-list-empty.png` |

### Состав экрана

| # | Блок | Что показывается |
|---|---|---|
| 1 | **Строка возврата** (повторяется) | Верхняя строка: статус (с иконкой + цветом), справа — итоговая сумма к возврату и шеврон. Вторая строка: `№<номер> · <дата создания>`. Ниже: превью изображений возвращаемых изделий; под каждым превью — цена и размер. Вся строка — переход в карточку (`SCR-RET-01`) |
| 2 | **Пустое состояние** | Иконка, заголовок «Возвратов пока не было», пояснение «Все ваши возвраты можно будет посмотреть в этом разделе», кнопка «Перейти в каталог» |

### Правила отображения

- Сортировка: от новых к старым (по `cms_returns.created_at` DESC).
- Статус — `cms_returns.status_id` → `cms_return_statuses.client_title`; в макете: «Создан» (иконка часов), «Выполнен» (зелёный, галочка), «Отменён» (красный, крест). Иконка и цвет — по группе статуса (`cms_return_status_groups` / признак `is_final` + результат).
- Итоговая сумма в строке = «Итого к возврату» этого возврата (та же величина, что в `SCR-RET-01`, блок 8).
- Превью изделий — по одной миниатюре на возвращаемую единицу; порядок — как в возврате.
- Цена под превью — **одна** величина (в макете зачёркнутой «цены до скидки» нет — на экране возврата важна уплаченная / возвращаемая сумма, а не каталожная «старая цена»). Что именно выводить — уплаченную цену (`cms_order_positions.price`) или сумму к возврату за единицу (`cms_return_positions.refund_amount`) — см. открытые вопросы (общий с `SCR-RET-01`).
- **Открытый вопрос:** семантика красной цены в макете (у части изделий цена красная) — со скидкой / позиция не принята к возврату / иное.
- **Открытый вопрос:** нужен ли акцент/бейдж на возвратах, где требуется действие клиента (передать товар, срок передачи истекает).
- **Проверка консистентности:** в списке статус «Выполнен», в карточке — «Возврат завершён». Свести к единому `client_title` в `cms_return_statuses`.

### Состояния экрана

| Состояние | Поведение |
|---|---|
| Загрузка | Индикатор загрузки |
| Есть возвраты | Список строк (блок 1) |
| Возвратов нет | Пустое состояние (блок 2) с кнопкой «Перейти в каталог» |
| Ошибка загрузки | Состояние ошибки + «Повторить» |

### Действия на экране

| Действие | Условие | Что происходит |
|---|---|---|
| Открыть возврат (нажатие на строку) | всегда | Переход на `SCR-RET-01` для выбранного возврата |
| Перейти в каталог | только в пустом состоянии | Переход в каталог |

### Параметры экрана

| Поле экрана | Источник (TO-BE) | Примечание |
|---|---|---|
| Статус (текст + иконка + цвет) | `cms_returns.status_id` → `cms_return_statuses.client_title`; иконка/цвет — по группе статуса | AS-IS: статус заказа |
| Номер возврата | `cms_returns.id` (или `return_order_num`) | AS-IS: нет |
| Дата создания | `cms_returns.created_at` | |

### Открытые вопросы

- Какую цену показывать под превью: уплаченную (`price`) или сумму к возврату за единицу (`refund_amount`); зачёркнутая «цена до скидки» на экране возврата не нужна (общий вопрос с `SCR-RET-01`).
- Семантика красной цены изделия в строке списка.
- Иконки и цвета для каждого статуса / группы статусов.
- Единый `client_title` статуса между списком («Выполнен») и карточкой («Возврат завершён»).
- Акцент на возвратах, требующих действия клиента.
- Пагинация / ограничение по количеству.
