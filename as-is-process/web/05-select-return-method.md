# Шаг 05 (web). Выбор способа возврата

**Канал:** Сайт · **Экран:** «Оформление возврата», блок «Способ возврата»
**Статус:** DRAFT · **Дата:** 07.09.2026
**Результат шага:** в состоянии формы выбран способ возврата и связанный с ним список доступных дат. В базе ничего не меняется.

---

## 1. Пользовательский сценарий

### 1.1 Откуда пользователь приходит

Сразу после выбора города (шаг [04](04-select-city.md)) — тот же экран. Список способов появляется, когда задан город.

### 1.2 Что система отображает

- Пока идёт запрос — индикатор загрузки.
- Затем — плитки способов: по одной на каждый способ, помеченный как активный. На плитке — название способа.
- Под выбранной плиткой — описание способа (если оно задано в справочнике `cms_return_method`).
- Для способа типа «ПВЗ» (`sdek-pvz` или `5post`) дополнительно показывается ссылка **«Пункты выдачи на карте»** — она открывает информационную карту ПВЗ. **Выбрать конкретную точку на этой карте нельзя**, и на процесс это не влияет.

### 1.3 Состав списка

Список способов определяет сервер по городу (см. 2.2). Фактически это подмножество из трёх: `courier` (Курьер), `sdek-pvz` (СДЭК ПВЗ), `5post` (5Post). Если по городу ничего не нашлось — возвращается единственный способ `courier`.

### 1.4 Действия пользователя

- Нажатие на плитку — выбор способа.
- Предвыбор: если после загрузки списка текущий выбор не входит в список, автоматически выбирается **первый** способ.

### 1.5 Ограничения и зависимости

- Смена города заново запрашивает список. Ранее выбранная дата сохраняется, только если она есть в новом списке доступных дат; иначе подставляется первая доступная.
- Смена способа (в отличие от смены города) **не сбрасывает** адрес и индекс. Поля адреса просто показываются или скрываются в зависимости от типа способа.
- Кнопка «Подтвердить возврат» неактивна, пока не выбран способ и не заполнены его обязательные данные (шаг [06](06-fill-return-method-details.md)).

### 1.6 Что происходит после действия

- Способ сохраняется в памяти попапа.
- Если способ — Курьер, показывается блок «Адрес возврата».
- Если у способа есть доступные даты, показывается блок «Дата возврата» (шаг 06).

### 1.7 Ошибочные сценарии

- Если сервер ответил неуспехом или пустыми данными — список остаётся пустым, отдельного сообщения нет.
- Если сервер вернул только `courier` (запасной вариант), пользователь видит один способ.

## 2. Системная реализация

### 2.0 Диаграмма последовательности

```mermaid
sequenceDiagram
    actor U as Пользователь
    participant W as Сайт (попап)
    participant B as Backend
    participant DB as БД
    participant CFG as cms_return_details_config<br/>+ Redis

    Note over W: город выбран на шаге 04
    W->>B: GET /api/orders/{order_id}/return-method-list?city&cityId&countryIso&region&regionId
    B->>DB: SELECT cms_orders (по order_id, user_id)
    B->>DB: cms_delivery_city ⋈ cms_delivery_tk<br/>(type IN 1,11,15) → уникальные type
    Note over B: type 1→courier, 11→5post, 15→sdek-pvz;<br/>пусто → [courier]
    B->>DB: SELECT cms_return_method (по alias)
    B->>CFG: параметры расчёта дат курьера
    B->>DB: cms_orders.end_date (для дат ПВЗ)
    B-->>W: { data: { items: [ {method, method_type, title, description,<br/>active, active_mobile, available_dates_return} ] } }
    W->>W: фильтр active = true; предвыбор первого
    W-->>U: плитки способов + (для ПВЗ) ссылка «Пункты выдачи на карте»
```

### 2.1 Источники данных

| Что нужно | Где хранится | Поля |
|---|---|---|
| Доступные типы транспортных компаний по городу | связка таблиц `cms_delivery_city` и `cms_delivery_tk` | `delivery_city.geo_id` / `city` / `region` / `country`, `delivery_city.tk_id`, `delivery_tk.id`, `delivery_tk.type` |
| Справочник способов возврата | `cms_return_method` | `alias`, `title`, `description`, `is_enabled` (включён на сайте), `is_enabled_mobile` (включён в МП) |
| Параметры расчёта дат курьера | справочник конфигурации возврата (`cms_return_details_config`, последняя версия) + кэш | «доступен ли выбор даты», «задержка в днях», «сколько дат показывать», «время-отсечка» |
| Дата завершения заказа | `cms_orders.end_date` | — |

### 2.2 Как система собирает данные

По запросу `GET /api/orders/{order_id}/return-method-list`:

1. **Находит заказ** по `order_id` среди заказов пользователя; если нет — ответ 404.
2. **Определяет доступные типы транспортных компаний по городу.** В связке `cms_delivery_city` ⋈ `cms_delivery_tk` отбираются строки, где `delivery_tk.type` входит в набор `1`, `11`, `15`:
   - если передан идентификатор города — фильтр по `delivery_city.geo_id` (идентификатор города и региона);
   - иначе — фильтр по названиям города/региона/страны.
   Из результата берутся уникальные значения `delivery_tk.type`.
3. **Переводит типы в способы возврата** по правилу:
   | `delivery_tk.type` | способ (`alias`) |
   |---|---|
   | `1` | `courier` |
   | `11` | `5post` |
   | `15` | `sdek-pvz` |
   Если ни одного типа не нашлось — берётся один способ `courier`.
4. **Достаёт строки этих способов из справочника `cms_return_method`.**
5. **Для каждого способа считает доступные даты:**
   - **Курьер:** если в конфигурации выбор даты выключен — дат нет. Иначе даты формируются от сегодняшнего дня (по московскому времени) с задержкой из конфигурации; если текущее время уже позже «времени-отсечки», добавляется ещё один день. Всего показывается столько дат, сколько указано в конфигурации, подряд.
   - **ПВЗ (`sdek-pvz`, `5post`):** окно возврата — `cms_orders.end_date` плюс 14 дней. Если `end_date` не заполнена — дат нет. Если окно уже закрылось — дат нет. Если сегодня последний день окна — добавляется ещё 3 дня. Даты идут от завтрашнего дня подряд.
6. **Собирает по каждому способу:** внутреннее имя (`method`), тип (`pvz` для ПВЗ, иначе `courier`), название, описание, признак «активен на сайте», признак «активен в МП», список доступных дат.

Существующая карточка: [`api/web/orders/get-return-method-list.md`](../../api/web/orders/get-return-method-list.md).

### 2.3 Обмен по API

**Запрос**

```http
GET /api/orders/{order_id}/return-method-list?city=Москва&cityFias=...&cityId=<идентификатор города>&countryIso=RU&region=...&regionId=...
X-Requested-With: XMLHttpRequest
```

**Ответ**

```json
{
  "status": "success",
  "message": "",
  "data": {
    "items": [
      { "method": "courier", "method_type": "courier", "title": "<из return_method.title>",
        "description": "<из return_method.description>",
        "active": true, "active_mobile": true,
        "available_dates_return": ["2026-09-09", "2026-09-10", "2026-09-11"] },
      { "method": "sdek-pvz", "method_type": "pvz", "title": "<из return_method.title>",
        "description": "<из return_method.description>",
        "active": true, "active_mobile": true,
        "available_dates_return": ["2026-09-08", "2026-09-09"] }
    ]
  }
}
```

Значения `title`, `description` и конкретные даты — иллюстративные; фактические берутся из справочника `cms_return_method` и расчёта дат. Клиентская обёртка сайта приводит `status: "success"` к признаку успешного ответа.

### 2.4 Что использует сайт

| Поле ответа | Использование |
|---|---|
| `active` | в список попадают только способы с `active = true` (включён на сайте) |
| `method` | сохраняется у выбранного способа; уйдёт в запрос сохранения реквизитов возврата как `method_return` |
| `method_type` | `courier` → показать блок адреса; `pvz` → показать ссылку «Пункты выдачи на карте» |
| `title` | подпись плитки |
| `description` | текст под выбранной плиткой |
| `available_dates_return` | список дат для блока «Дата возврата» (шаг 06); непустой список включает этот блок |

Поле `active_mobile` сайт не использует.

### 2.5 Что передаётся на следующий шаг

Внутри попапа хранится выбранный способ. В запрос сохранения реквизитов возврата (`POST /api/orders/{id}/return-details`) уйдут внутреннее имя способа (как `method_return`) и выбранная дата (как `date_return`).

### 2.6 Что сохраняется или меняется

Ничего. Способ запишется в заказ (`cms_orders.return_delivery_tk`, значения `13` / `567` / `55`) на шаге [08](08-confirm-and-create-return.md).

### 2.7 Неуточнённые места

- В ветке «по названиям» (без идентификатора города) фильтр по стране сравнивается с ISO-кодом (например `RU`), тогда как в `delivery_city.country`, предположительно, хранится название страны — совпадение не гарантировано. **Допущение:** в реальном сценарии идентификатор города всегда есть (из гео-попапа), и используется ветка «по идентификатору», где страна не участвует.
- Наполнение таблиц `cms_delivery_city` / `cms_delivery_tk` (в каких городах заведены компании с типом `11` / `15`) определяет фактический состав способов и в коде не зафиксировано.
- Значения конфигурации возврата (задержка, число дат, время-отсечка, «доступен ли выбор даты») хранятся в базе, в коде не зафиксированы.
- **Даты курьера и ПВЗ считаются по разной логике (подтверждено разработкой).** Курьер: список дат формируется только из `cms_return_details_config` (задержка + число дат + время-отсечка); 14-дневный срок / `cms_orders.end_date` в самом списке **не проверяются** (сознательно, без сообщения «последний день»). ПВЗ (`sdek-pvz` / `5post`): точное окно `cms_orders.end_date + 14 дней` (константа в коде, не `days_can_be_returned`). Массив `available_dates_return` — фактический источник «когда можно вернуть» для клиента; отдельного поля «Вернуть до» нет.
- Поле `active` в ответе всегда означает «включён на сайте», независимо от канала; корректность этого для мобильного канала — см. `mobile/`.

## 3. Отличия от TO-BE

| TO-BE (`UC-RET-04`, `RET-BR-03`, `RET-BR-08`) | AS-IS (web) |
|---|---|
| Базовый набор каналов по месту покупки: розница → только магазин; аутлет → только аутлет; «Цветной» → только «Цветной»; онлайн → Магазин, Курьер, 5Post, СДЭК (ПВЗ и офис), Почта России | Только `courier`, `sdek-pvz`, `5post`; набор зависит только от таблицы `cms_delivery_city`, «место покупки» не учитывается |
| Почта России — только для Калининграда | Канала «Почта России» нет |
| Предвыбор способа по способу получения заказа | Предвыбор — просто первый элемент списка, без связи со способом доставки заказа |
| Для ПВЗ / постамата — выбор конкретной точки на карте или в списке, сохранение её идентификатора и адреса | Ссылка «Пункты выдачи на карте» открывает **некликабельную** карту; точка не выбирается и не сохраняется (сервер её и не принимает — см. шаг 06) |
| Расширение «Не удалось определить доступные способы» с повтором | Пустой список молча; при отсутствии данных — запасной вариант из одного `courier` |
| Способ «офис СДЭК» отдельно от «ПВЗ СДЭК» | Только `sdek-pvz` |
