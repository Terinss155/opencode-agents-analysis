# ECOMDEV-2651: [B] Возврат 0.1. Признаки возврата в обмене с 1С

> **Вариант 2 — по предложению Свистуновой (09.11.2026).** Вместо отдельного признака `is_refund_to_original_payment_method` в 1С передаётся способ возврата денег — то же поле, что будет в «Возвратах 2.0». Вариант 1 — файл `ECOMDEV-2651 [B] Возврат 0.1. Признаки возврата в обмене с 1С.md`.

## Цель

Передавать в 1С вместе с заказом:

- **способ возврата денег** — «тем же способом» или «по реквизитам». Нужен, чтобы пустые реквизиты в документе 1С не выглядели ошибкой. В «Возвратах 2.0» способ возврата денег будет у заявки, поэтому 1С делает поле один раз — для этапа 0 и для 2.0;
- **`is_bank_details_confirmed`** — клиент подтвердил банковские реквизиты. Признак уже сохраняется в заказе по задаче ECOMDEV-2649, здесь — только передача в 1С.

**Где:** выгрузка заказа в 1С (SOAP `loadOrder`). Методы возврата сайта и МП, их запросы и ответы, база данных не меняются.

Разделы 1 и 2 ждут ответа 1С-1. Раздел 3 можно делать сразу.

---

## Описание реализации

### 1. Способ возврата денег в выгрузке в 1С {red}(ждёт ответа 1С-1)

Значение вычисляется при каждой выгрузке заказа, отдельно не хранится. Проверки — по порядку:

| № | Условие | Значение |
|---|---|---|
| 1 | В заказе нет возврата | пусто |
| 2 | В `cms_orders.user_refund` есть реквизиты | `bank_details` — по реквизитам |
| 3 | Способ оплаты из таблицы ниже и в заказе не использован подарочный сертификат | `original_payment` — тем же способом |
| 4 | Иначе (оплата при выкупе брони 18, Click & Collect Light 12, устаревшие способы, способ не задан) | пусто |

| Группа | Способ оплаты | Код |
|---|---|---|
| Прямая онлайн-оплата | Онлайн на сайте | 1 |
| Прямая онлайн-оплата | СБП | 16 |
| Прямая онлайн-оплата | Яндекс Pay | 19 |
| Прямая онлайн-оплата | Яндекс СБП | 20 |
| Прямая онлайн-оплата | Яндекс цифровой рубль | 21 |
| BNPL | Долями | 13 |
| BNPL | Подели | 14 |
| BNPL | Сплит | 17 |

Условие «использован сертификат» — то же, что в правиле «нужны реквизиты» (ECOMDEV-2526 §1). После ECOMDEV-2526 и ECOMDEV-2649 реквизиты пишутся в заказ ровно тогда, когда они нужны, поэтому п. 2 и п. 3 не пересекаются.

> Ограничение: значение вычисляется по текущему состоянию заказа. Если способ оплаты заказа сменится после возврата, при следующей выгрузке изменится и способ возврата денег.

### 2. Признак подтверждения в выгрузке в 1С {red}(ждёт ответа 1С-1)

| Поле | Блок | Источник | Значения |
|---|---|---|---|
| `refund_method` {red}(название — 1С-1) | `return` | вычисляется по разделу 1 | `original_payment` / `bank_details` / пусто |
| `is_bank_details_confirmed` | `return` | ключ `is_bank_details_confirmed` в `cms_orders.user_refund` | `true` — подтверждено; пусто — не передан старой версией МП. Если реквизитов в заказе нет, признак не передаётся |

Оба поля добавляются в тело запроса `loadOrder` и в копию тела для журнала обмена (`cms_orders_exchange_log`, `category = 3`), чтобы журнал совпадал с отправленным.

Значения `original_payment` / `bank_details` — как способ возврата денег заявки в «Возвратах 2.0» (`screen-spec.md`, `cms_returns.refund_target`). В ERD 2.0 тот же смысл описан справочником `cms_refund_methods` — коды значений согласовать один раз для обоих этапов.

### 3. `full_name` при возврате тем же способом

`full_name` 1С использует только для возврата на расчётный счёт. Правило формирования не меняется: ФИО из реквизитов, если они есть, иначе — ФИО покупателя из профиля; при возврате из МП по BNPL — пустая строка.

## Тестирование

**Предусловия:** возвраты по заказам с каждым способом оплаты из таблицы раздела 1, с оплатой курьеру, с частичной и полной оплатой сертификатом; заказ без возврата. Стенд с обменом с 1С или журнал `cms_orders_exchange_log`.

**Критерии приёмки**

1. Способ возврата денег в выгрузке: `bank_details` — для заказов с реквизитами; `original_payment` — для онлайн-оплаты и BNPL без сертификата; пусто — для заказа без возврата и для остальных способов оплаты.
2. `is_bank_details_confirmed` в выгрузке совпадает со значением в `cms_orders.user_refund`; в заказе без реквизитов признак не передаётся.
3. Тело выгрузки и журнал обмена содержат одинаковые значения новых полей.
4. `full_name` — по правилу раздела 3, без изменений относительно текущей выгрузки.
5. Остальные поля выгрузки в 1С не изменились.
