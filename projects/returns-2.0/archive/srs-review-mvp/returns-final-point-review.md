# Returns 2.0 — точечные правки по частичной сдаче в магазине

Дата: 05.11.2026. Основание: [переписка 05.11.2026](<../../sources/answers/[2026-11-05 11-00] Переписка Лемешева — Колосов, Варцаба (отмена заявки при частичной сдаче в магазине).md>). Оригиналы SRS, статусная модель и Wiki не изменены.

## 1. Подтверждённые решения

1. Клиент принёс в магазин часть изделий заявки: принесённые получают «Принято», остальные — «Отменено».
2. После определения результатов всех изделий заявка переходит в «Возврат принят», затем — в «Возврат завершен».
3. Сумма и баллы к возврату — без изделий «Отменено».
4. Остальные изделия возвращаются новой заявкой в пределах срока возврата; её может создать сам клиент, а также магазин или Отдел дружбы.
5. Ожидание остальных изделий в прежней заявке не предусматривается.

Действуют без изменений:
- отмена заявки клиентом — только по статусу заявки (US 4);
- `ADR-RET-065` п. 2: остаток позиции с несколькими одинаковыми изделиями при действующей заявке клиент в ЛК и МП не оформляет — его возврат проводит Отдел дружбы;
- определение «Активная заявка» (глоссарий SRS);
- O3, O5, O6 статусной модели — предложения (`ADR-RET-073`, «Предложено»).

## 2. Обязательные изменения

## 3. Исключённые изменения

| Предложение предыдущей карты | Почему исключено |
|---|---|
| `items[].remaining_quantity`: «минус изделия позиции в возврате (`items[].return_items`, TBD)» | Текущее «Количество в позиции минус изделия в возврате» уже опирается на изделия в возврате; после правки 3 значение верное |
| `items[].available_return_quantity` | Формула «Если позицию можно вернуть — равно `remaining_quantity`, иначе 0» верна без изменений |
| Новая колонка примера в US 1.1 | Не устраняет противоречия, добавляет детализацию |
| Шаг 4 US 1.1 МП и сайта («каждое изделие, оформленное в возврат») | Состав блока задаёт поле `return_items`, указанное в шаге; после правки 3 он верный. Пользовательский сценарий не меняется |
| «Опционально» п. 1 шага 4 и ромб flowchart «По заказу есть активные заявки на возврат?» | В активной заявке всегда есть изделие без «Отменено»: если ни одно не принято, заявка отменяется (статусная модель, § 2). Ветка не меняется |
| Новый подпункт «Основных принципов» п. 2 об изделиях «Отменено» | Правило передаётся правкой 1–2 второго подпункта; отдельный подпункт дублировал бы его |

## 4. Проверка пяти условий

Заявка R1: позиция A (1 изделие) и позиция B (1 изделие), срок возврата не истёк.

| Шаг | Состояние | A: `return_items` / `remaining_quantity` / `can_be_returned` / `available_return_quantity` | B | Статус позиции заказа |
|---|---|---|---|---|
| 1 | R1 «Возврат принят»: A — «Отменено», B — «Принято» | 0 / 1 / `true` / 1 | 1 / 0 / `false` / 0 | A — прежний (O2 с правкой 10); B — «Возврат» (O4) |
| 2 | Клиент создаёт R2 по A | 1 / 0 / `false` / 0 | без изменений | A — «Заявка на возврат» (O1) |
| 3 | Клиент отменяет R2 (US 4: статус R2 допускает отмену) | 0 / 1 / `true` / 1 | без изменений | A — прежний (US 4 п. 5 с правкой 7) |

| Условие | Сценарий | Ожидаемый результат |
|---|---|---|
| 1. «Отменено» доступно снова | Шаги 1 и 3 | A в «Ваш заказ» и на экране выбора (US 1.2); не в «Оформлен возврат» |
| 2. «Принято» повторно не возвращается | B на шагах 1–3 | B только в «Оформлен возврат», к выбору недоступна |
| 3. Ограничение `ADR-RET-065` | Позиция C: 2 одинаковых изделия в R1, одно «Принято», другое «Отменено» | 1 / 1 / `false` / 0: изделие видно в «Ваш заказ», к выбору недоступно; возврат — через Отдел дружбы |
| 3а. То же без приёмки | Позиция D: 3 изделия, 1 в действующей заявке без результата | 1 / 2 / `false` / 0, как сейчас |
| 4. Повторная проверка при создании | Открыта старая карточка заказа; клиент отправляет B или повторно A после создания R2 | US 1.5 п. 2 (правка 6) отклоняет: у позиции есть изделия в возврате |
| 5. Статусы согласованы | Шаги 1–3 | R1 «Возврат принят» — не отменяется (US 4, по статусу); изделия R1 без изменений; R2 «Возврат отменен», изделие A в R2 — «Отменено»; позиции заказа — по таблице выше |

## 6. Нерешённые противоречия
