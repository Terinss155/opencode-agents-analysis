# Дополнение к запуску SRS: как поручить Claude Code создание Python-проверки

## Нужно ли заменить предыдущие документы?

**Нет.** Оставь `srs-rules-and-automation-v5.md`, `claude-srs-stage-1-audit-v3.md`, `claude-srs-stage-2-skill-v3.md`, `claude-srs-stage-3-dry-run-v3.md` и `srs-launch-instructions-final.md` без изменений. Они относятся к **исправлению правил оформления SRS**, а не к разработке Python-инструмента. Приступай к скрипту только после того, как выполнены и приняты все три стадии.

`srs-check-pipeline.md` — **неутверждённый проект более широкого конвейера**, источник идей, не команда к запуску. Нельзя выполнять его описанные автоматические правки и запускать агентов только потому, что файл приложен.

## Порядок

| Очередь | Что отправить Claude Code | Режим | Что получишь |
|---|---|---|---|
| 1 | Прежний аудит скилла + v5 | Только чтение | Карта исправления правил |
| 2 | Прежний этап исправления скилла, после одобрения | Только 3 файла скилла | Исправленные инструкции/шаблоны |
| 3 | Прежний пробный разбор после одобрения | Только чтение | Примеры, как новые правила работают |
| **P1** | `claude-srs-script-P1-design-only.md`; дать доступ к `srs-check-pipeline.md`, v5 и текущим SRS как материалам | **Только чтение** | Подробная спецификация проверяющего скрипта, условия ложных срабатываний, MVP |
| **P2** | `claude-srs-script-P2-implement-only.md` **только после одобрения P1** | Создание только `skill/srs/check_srs.py` | Локальная проверяющая утилита без автоправок |
| Далее | Отдельная будущая задача на подключение пайплайна | По отдельному разрешению | Безопасная автоматизация целого процесса |

## Короткое сообщение для запуска P1

«Этапы 1–3 обновления скилла завершены и проверены. Начни отдельный этап P1 по приложенному файлу `claude-srs-script-P1-design-only.md`. Используй `srs-check-pipeline.md` и правила v5 только как входные материалы, проверь актуальный скилл. **Сейчас только анализ, ничего не создавай и не меняй.** Выдай спецификацию проверок, разницу между жёсткими ошибками и предупреждениями, MVP, возможные ложные срабатывания и список файлов будущей реализации. Остановись после ответа».

## Короткое сообщение для P2

После чтения P1 и одобрения его конкретных правил:

«Утверждаю спецификацию P1 и разрешаю выполнить приложенный `claude-srs-script-P2-implement-only.md`. Разрешено создать/изменить **только** `skill/srs/check_srs.py`; любые дополнительные пути требуют нового согласования. **Не меняй SRS, Wiki, AGENTS.md, CLAUDE.md, SKILL.md, шаблоны, требования, вопросы и существующие артефакты.** Не создавай и не запускай автоисправления. Покажи diff, CLI и отчёт о фактически изменённых файлах. Остановись».

## Перед переходом к следующему этапу

- Проверяй `git status` и список затронутых файлов до/после; сохраняй свои незакоммиченные ручные изменения.
- Сравни P1 с целями: номера шагов сайта/МП **могут отличаться**, совпадающие действия должны иметь одинаковый текст при платформенных исключениях, API и маршруты независимы.
- Проверь отсутствие запрета временных вопросов в SRS МП и требования переносить серверную логику из МП в сайт.
- Скрипт **не должен решать**, согласовано ли требование или можно ли передать SRS в разработку. Он только находит проверяемые нарушения и подозрительные места.
- **Не разрешай автоматическую запись в действующие документы** ни на P1, ни на P2.

Если Claude предложит самостоятельно добавить hooks, субагентов, базу, отдельные конфиги или автоматически поправить найденные ошибки, ответь: «Это отдельное предложение. Пока действуют границы P1/P2; выполни только согласованный этап».
