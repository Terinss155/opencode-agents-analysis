# **Автоматическая Отмена Заявок и Сроки**

* Автоматическую отмену заявок убираем из MVP: нет интеграции с ТК, товар может прийти на склад после 14 дней  
* Кнопка ручной отмены для клиента остаётся  
* Срок жизни заявки: 10 дней с момента создания (не 14\)  
  * 14 дней: срок с получения заказа до возможности подать заявку  
  * 10 дней: срок передачи товара после создания заявки  
* Если за 30 дней возврат не поступил на склад: отбивка на дружбу для ручной проверки  
  * В дальнейшем (при наличии интеграции с ТК): отбивка не нужна, автоотмена заработает  
* Промежуточный статус вместо нового статуса: фильтр по дате, не по статусу (предложение Артёма)  
  * Дружбе удобнее работать со статусом, чтобы не терять заказы (позиция Екатерины Филатовой)

# **Схема Взаимодействия Систем (Артём)**

* Мастер-система по нумерации заявок: сайт и мобильное приложение  
* Три потока возвратов:  
  * Клиент создал заявку, выбрал ПВЗ: заявка → Retail CRM → склад → обратный статус «принят»  
  * Клиент выбрал курьера: данные → Retail CRM, дружба договаривается по времени; инфа возвращается на сайт/приложение  
  * Клиент ничего не оформил, просто прислал посылку: если есть КМ-код, Бета идентифицирует и создаёт заявку автоматически; если нет — аномалия/карантин  
* Трек-номера: логисты загружают в 1С, 1С отдаёт на сайт; новая сущность возврата требует учёта во всех системах  
  * Бета Про обещали дать метод, чтобы 1С отдавала данные напрямую в Бету  
* Набор реквизитов: каждая система делает свой минимальный набор, потом сопоставляют  
  * Основной пул разработки можно оценивать уже сейчас, не ждя полной синхронизации

# **Возвраты в Розничных Магазинах**

* Целевой флоу: клиент создаёт заявку в ЛК → формируется QR из внутреннего номера → сотрудник магазина сканирует в отдельном ARM  
  * Данные по возврату (в т.ч. реквизиты для расчётного счёта) подтягиваются автоматически  
* ARM по возвратам онлайн-заказов переносится из маркетинга (1С КА) в розницу  
  * Часть проекта Розница 3.0: все функции розницы выносятся в отдельную систему  
  * Возвраты — первый этап переноса  
* По брони и чекам: QR не формируется, клиент приходит без заявки  
  * Возврат оформляется сразу в магазине; заявка создаётся автоматически постфактум и расходится по системам  
* Кейс: клиент оформил курьера, но пришёл в магазин сам  
  * Незакрытая заявка не блокирует магазин: это намерение, не обязательство  
  * Магазин проводит возврат, новая заявка создаётся автоматически  
* Возврат денег за онлайн-заказы: розница не возвращает сама, получает подтверждение от сайта  
  * Реквизиты нужны бухгалтерии, не рознице; попадают в реестр бухгалтерии автоматически через 1С
