## Что уже решено

| № | Тема | Решение | Источник |
|---|---|---|---|
| 1 | Статус заказа | При возврате статус заказа не меняется: «Заказ выполнен» или «Заказ выдан» остаётся. Возврат виден только по статусам позиций | `ADR-RET-039` |
| 2 | Статусы позиции | «Заявка на возврат» — `return-requested` (предложено RetailCRM), «Частичный возврат» — `return-partial` (нужен ли — открыт), «Возврат» — действующий `lost` | `ADR-RET-101`; [схема статусов v4](../diagrams/state/return-status-v4_state.md), раздел 3 |
| 3 | Сущность возврата в Mindbox | Отдельной сущности возврата и отдельных статусов строки возврата в Mindbox нет; возвращаемые позиции передаются в изменении заказа со статусом возврата | [разбор встречи «Баллы из Mindbox»](<../../meetings/[2026-11-16 14-00] Баллы из Mindbox_summary.md>), тема 3 |
| 4 | Операции для баллов | Расчёт — `Website.CalculateAuthorizedCart`, фиксация — `Website.UpdateOrderv2` | `ADR-RET-092` |

## Что следует из кода для нового процесса

- **Возврат принят.** Пары «Заказ выполнен» и «Заказ выдан» + `lost` уже есть в маппинге — `401`, как сейчас при «Возврат из ЛК».
- **Заявка на возврат, Частичный возврат.** Пар со статусами `return-requested` и `return-partial` в маппинге нет. Без новых строк маппинга такие строки уйдут в Mindbox со статусом `101` — как добавленная позиция нового заказа.
- **События по статусу заказа.** `orderStatus` больше не меняется на `vozv-lk`, `vpost`, `vosm`, `9183`, `9120`: всё, что Mindbox запускает по этим кодам, в новом процессе не сработает.
- **Статусы заявки.** Статусы заявки на возврат («Заявка создана», «Курьер назначен», «Возврат принят», «Заявка отменена» и др.) в Mindbox сейчас не передаются. Заявок по одному заказу может быть несколько.

## Открытые вопросы

### Статусы строк

#### 1. Что означают коды статусов строки Mindbox, которые сайт отправляет по `cms_mb_statuses_map`?

**Кому:** менеджер Mindbox (Ирина Васильева)

Коды: `101`, `102`, `111`, `201`, `202`, `211`, `221`, `222`, `231`, `302`, `311`, `321`, `322`, `401`, `402`, `411`, `501`–`505`, `701`–`703`, `805`. Нужны название и смысл каждого кода, а для кодов возврата — что Mindbox делает при переходе строки в этот статус.

#### 2. Какие коды статусов Mindbox ставить в `cms_mb_statuses_map` для позиций «Заявка на возврат» и «Частичный возврат» в заказе «Заказ выполнен» и «Заказ выдан»?

**Кому:** менеджер Mindbox (Ирина Васильева), Backend Developer (Оля Свистунова)

Варианты:

- **а)** исходный статус строки до приёмки — `311` для «Заказ выполнен», `302` для «Заказ выдан». Mindbox узнаёт о возврате только после приёмки, по `401`;
- **б)** новые статусы строки Mindbox для «Заявка на возврат» и «Частичный возврат». Кто и как заводит их в Mindbox?

Предложение: вариант а) — он совпадает с расчётом баллов в [BL-RET-BONUS](../backend/return-bonus_backend.md), где изделия активной заявки передаются с исходным статусом.

#### 3. Принимает ли Mindbox обратный переход строки из статуса заявки на возврат в исходный статус?

**Кому:** менеджер Mindbox (Ирина Васильева)

При отмене заявки позиция заказа возвращается в прежний статус (переходы O2, O6 [схемы статусов v4](../diagrams/state/return-status-v4_state.md)). Вопрос нужен, если по вопросу 2 выбран вариант б): строка переходит из нового статуса возврата обратно в `311` или `302`.

### События заявки на возврат

#### 4. Что Mindbox сейчас запускает по возвратным статусам заказа и строк?

**Кому:** менеджер Mindbox (Ирина Васильева), CRM-маркетинг

Статусы заказа в `orderStatus`: `vozv-lk`, `9180`, `9186`, `vpost`, `vosm`, `9183`, `9120`, «Возврат поступил в магазин», «Запрос реквизитов». Статусы строк: `401`, `411`, `504`, `505`, `322`. Какие триггерные письма, SMS и push, сегменты и отчёты Mindbox завязаны на эти коды?

#### 5. Как сайту передавать в Mindbox события заявки на возврат, если статус заказа не меняется?

**Кому:** менеджер Mindbox (Ирина Васильева)

Варианты:

- **а)** только статусы строк заказа (вопрос 2). Mindbox видит изделия, но не заявку, её номер и статус;
- **б)** доп. поля заказа в изменении заказа: номер и статус последней заявки. По одному заказу может быть несколько заявок, в полях заказа остаётся только последняя;
- **в)** отдельная операция по событию заявки: номер заявки, номер заказа, статус заявки, изделия, способ возврата.

Какой вариант Mindbox рекомендует и какие операции или поля для него нужно завести? Предложение: вариант в) — заявок по заказу может быть несколько, статус каждой меняется независимо.

#### 6. По каким статусам заявки на возврат сайт передаёт событие в Mindbox?

**Кому:** Product Manager, CRM-маркетинг

Зависит от состава коммуникаций по BRD `OQ-53`. Статусы заявки — [схема статусов v4](../diagrams/state/return-status-v4_state.md), раздел 1.

## Сообщение менеджеру Mindbox (Ирина Васильева)

Ирина, привет! Кроме баллов, есть вопросы по статусам и событиям возврата.

**Как будет работать новый процесс**

1. Статус заказа при возврате не меняется: выполненный заказ остаётся «Выполнен». Сейчас заказ переходит в «Возврат из ЛК» (`vozv-lk`), дальше 1С ведёт его по возвратным статусам.
2. Позиция заказа получает новые статусы: «Заявка на возврат» при создании заявки, «Частичный возврат» и «Возврат» (`lost`) после приёмки изделий.
3. По одному заказу может быть несколько заявок на возврат, у каждой свой номер и свой статус.
4. Статус строки для Mindbox сайт берёт из таблицы маппинга «статус заказа + статус позиции» → код статуса Mindbox. Для «Возврат» в выполненном заказе это `401`, как сейчас.

3. Если клиент отменил заявку, строка вернётся из статуса заявки в исходный статус. Mindbox это примет?
