# Обмен с Mindbox: баллы к возврату, статусы позиций и события возврата

Возвраты 2.0 · 26.11.2026

## Коротко

Mindbox ведёт бонусные счета клиентов и отправляет им письма и уведомления. Когда клиент возвращает товар, Mindbox должен вернуть баллы, которыми клиент оплатил покупку, не начислить баллы за возвращённое и правильно сообщить клиенту о ходе возврата.

Сейчас Mindbox узнаёт о возврате по смене статуса заказа. В новом процессе статус заказа при возврате не меняется, а возврат виден по статусам позиций. Mindbox подтвердил, что для этого подходят действующие операции расчёта и изменения заказа, и описал, при каких статусах позиций он сам возвращает баллы. В документе собрано, как обмен устроен сейчас, что уже решено и какие вопросы остались к менеджеру Mindbox, команде, которая ведёт сервис связи сайта с Mindbox, и бизнесу. В конце — сообщения с оставшимися вопросами.

## Что входит и где смотреть остальное

Всё, что сайт согласует с Mindbox и командой BTS (сервис `mindbox-srv-go`): операции расчёта и фиксации возврата, статусы строк заказа и маппинг `cms_mb_statuses_map`, события заявки на возврат при неизменном статусе заказа (`ADR-RET-039`). Правила возврата и начисления баллов для клиента — [refund-bonus_questions.md](./refund-bonus_questions.md). Логика расчёта и фиксации баллов — [BL-RET-BONUS](../backend/mindbox-return-bonus_backend.md). Деление и объединение строк позиции, скидка промокода по строкам — [order-position-split_questions.md](./order-position-split_questions.md). Коммуникации клиенту по событиям возврата — BRD `OQ-53`.

## Что следует для нового процесса

- **Возврат принят.** Пары «Заказ выполнен» и «Заказ выдан» + `lost` уже есть в маппинге — `401`, категория «Возврат». Mindbox вернёт списанные баллы автоматически (решение 17). Чтобы клиент получал письмо о принятом возврате, код для этих пар меняется на `505` (вопрос 17, вариант г; ECOMDEV-2828).
- **Заявка на возврат.** Пар со статусом `return-requested` в маппинге нет. Без новых строк маппинга такие строки уйдут в Mindbox со статусом `101` «Позиция на резерве», категория «Оформлена»: баллы не вернутся, но статус по смыслу неверный. Код строки — вопрос 6.
- **`totalPrice`, `lineId` и `lineNumber`.** Сайт сейчас передаёт `totalPrice` только при создании заказа (факт 11), `lineId` равен ID товара, `lineNumber` — номеру записи позиции по порядку (факт 3). Для нового процесса нужно передавать `totalPrice` в изменении заказа (решения 21, 22) и уникальный `lineId` строки (решение 15). Части одной позиции получают её номер `lineNumber`, поэтому номер считается по исходным позициям заказа, а не по записям: иначе новая запись сдвинет номера следующих позиций.
- **Отмена заявки.** Строка возвращается в прежний статус: пара «Заказ выполнен» + «Добавлен» уже даёт `311` (решение 18).
- **Письма клиенту.** Письма о возврате запускаются кодами строк: `401` — «Мы получили вашу заявку на возврат», `411`/`504`/`505` — «Мы приняли и проверили ваш возврат», `322` — «Запрос реквизитов»; по статусам заказа писем нет (вопрос 16). Сейчас код строки выбирается по паре «статус заказа + статус позиции», а в новом процессе статус заказа не меняется. Задача — добавить в `cms_mb_statuses_map` строки для «Заказ выполнен» и «Заказ выдан», чтобы строка получала код письма в тот же момент процесса, что и сейчас: при заявке — код письма о заявке, при приёмке — `411`, `504` или `505`. Какой код ставить при заявке — вопрос 6, способ выбора кода по статусу заявки — вопрос 17, вариант г).
- **Отправка при смене статусов позиций.** Изменение заказа из 1С уходит в Mindbox только при смене статуса заказа (факт 17). В новом процессе статус заказа при возврате не меняется, поэтому смену статусов позиций сайт должен отправлять в Mindbox сам — при фиксации возврата ([BL-RET-BONUS](../backend/mindbox-return-bonus_backend.md), 1.7), а если для «Заявка на возврат» заведут свой код Mindbox (вопрос 6, вариант б), — и при переходе строки в этот статус и обратно.
- **Статусы заявки.** Статусы заявки на возврат («Заявка создана», «Курьер назначен», «Возврат принят», «Заявка отменена» и др.) в Mindbox сейчас не передаются. Заявок по одному заказу может быть несколько.

**Решено:** при частичном возврате требований к статусу заказа у Mindbox нет, он смотрит на статусы строк. **Дальнейшее действие:** чтобы клиент получал письма в новом процессе, в `cms_mb_statuses_map` добавляются строки для статусов позиции и заявки при статусах заказа «Заказ выполнен» и «Заказ выдан» — вопрос 17, вариант г).

#### 17. Как сайту передавать в Mindbox события заявки на возврат, если статус заказа не меняется?

**Кому:** менеджер Mindbox (Ирина Васильева), Backend Developer (Оля Свистунова)

Варианты:

- **а)** только статусы строк заказа (вопрос 6). Mindbox видит изделия, но не заявку, её номер и статус;
- **б)** доп. поля заказа в изменении заказа: номер и статус последней заявки. По одному заказу может быть несколько заявок, в полях заказа остаётся только последняя. В заказе Mindbox уже есть доп. поле `returnTrackNumber` «Трек-номер возврата» (решение 12), сайт его сейчас не заполняет;
- **в)** отдельная операция по событию заявки: номер заявки, номер заказа, статус заявки, изделия, способ возврата.

Какой вариант Mindbox рекомендует и какие операции или поля для него нужно завести? Предложение: вариант в) — заявок по заказу может быть несколько, статус каждой меняется независимо.

**Предложение System Analyst (Екатерина Лемешева), не согласовано:** вариант г) — передавать события заявки кодами строк, на которые в Mindbox настроены письма. Письма запускаются кодом строки: `401` — «Мы получили вашу заявку на возврат», `411`, `504` и `505` — одно письмо «Мы приняли и проверили ваш возврат», `322` — «Запрос реквизитов»; по `vozv-lk`, `vpost`, `vosm`, `9183`, `9120` писем нет (вопрос 16). Код строки выбирается по паре «статус заказа + статус позиции», статусы позиции «Заявка на возврат» и «Возврат» различают заявку и принятый возврат. Задача — ECOMDEV-2828.

| Статус позиции в заказе «Заказ выполнен» / «Заказ выдан» | Код строки Mindbox | Письмо клиенту |
|---|---|---|
| «Заявка на возврат» | Новый код вне категорий «Возврат» и «Отмена» (вопрос 6, вариант б) | «Мы получили вашу заявку на возврат» — CRM-менеджер настраивает письмо на новый код |
| Прежний статус после отмены заявки | `311` / `302` — действующие строки маппинга | Нет |
| «Возврат» (`lost`) | `505` вместо `401` | «Мы приняли и проверили ваш возврат» |

Что учесть:

- До приёмки нельзя передавать коды категории «Возврат» (`401`, `411`, `504`, `505`, `322`): Mindbox сразу вернёт баллы, а строку нельзя будет вернуть в прежний статус (решение 17).
- Старый процесс продолжает передавать `401` при возврате из ЛК и прежние коды при возвратных статусах заказа, поэтому его письма продолжают работать. Пара «Заказ выполнен» / «Заказ выдан» + «Возврат» в старом процессе встречается в единичных заказах (на проде в заказах 2000000–2030000 — 6 из 1657 заказов с возвращёнными позициями на 26.11.2026); такие строки при следующей отправке заказа перейдут с `401` на `505`.
- Строка Mindbox содержит изделия одной заявки (решение 15), поэтому у каждой строки свой код по статусу своей позиции. У отменённых изделий остаётся прежний код.
- Переход позиции в «Заявка на возврат» и обратно должен отправлять изменение заказа в Mindbox; переход в «Возврат» отправляется фиксацией возврата (решение 8).
- Если понадобится различать в письмах этапы заявки или склад и магазин (`411` / `504`), в маппинг добавляется третье условие — статус заявки на возврат, например новым полем в `cms_mb_statuses_map`; где его хранить, решает разработка. Нужно ли это — вопрос 18.
