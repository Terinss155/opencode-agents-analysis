# Деление строки позиции заказа при возврате части одинаковых изделий

Возвраты 2.0 · 13.11.2026

## Коротко

Несколько одинаковых изделий, например три футболки, хранятся в заказе одной строкой с количеством. Если клиент возвращает только часть, возвращённые изделия нужно учитывать отдельно от оставшихся. Так можно правильно показать статус, посчитать деньги и баллы и дать вернуть остальное позже. В документе собрано, как решено делить такую строку, как деление влияет на цены, баллы и обмен с RetailCRM, и вопросы к архитектору и разработке: когда делить строку, как её хранить и как собирать обратно.

## Что входит и где смотреть остальное

Когда клиент возвращает часть одинаковых изделий одной позиции заказа, возвращённые единицы отделяются от оставшихся новой строкой позиции заказа. Оставшиеся единицы клиент возвращает следующей заявкой ([разбор встречи 11.11.2026](<../../meetings/[2026-11-11 13-01] Вопросы по обмену плат. реквизитами_summary.md>), тема 11; [разбор PBR 05.11.2026](<../../meetings/[2026-11-05 14-00] PBR Возвраты_summary.md>), тема 1).

## Открытые вопросы

#### 1. В какой момент строка позиции заказа делится на две — при создании заявки на возврат или при приёмке изделий на складе или в магазине?

**Кому:** Product Manager, System Architect (Леша Осипенко)

Позиция заказа получает «Заявка на возврат» при создании заявки, поэтому возвращаемые и оставшиеся единицы расходятся по статусу уже в этот момент. Предлагаемый ответ: вторая строка создаётся при создании заявки на возврат.

#### 2. Хранятся ли единицы одной позиции заказа с разными статусами в отдельных строках позиции заказа?

**Кому:** System Architect (Леша Осипенко)

Речь о строках `cms_order_positions`, а не о статусах изделий в заявке («Принято», «Отменено»). Пример: в позиции 3 футболки; одну приняли по первой заявке, вторая в новой заявке ещё не сдана, третья у клиента. Предлагаемый ответ: три строки — «Возврат» (решение 12), «Заявка на возврат», прежний статус.

#### 3. ~~Какой статус получает строка позиции заказа, все изделия которой возвращены, если у позиции остаются невозвращённые изделия?~~

Закрыт 24.11.2026: строка сразу получает «Возврат», статуса «Частичный возврат» нет — решение 12, `ADR-RET-112`.

#### 4. Как хранятся строки, если по одной позиции заказа одновременно действуют две заявки?

**Кому:** System Architect (Леша Осипенко), Backend Developer (Оля Свистунова)

Пример: клиент оформил вторую заявку, пока первая не принята, или сдал изделия в магазин при действующей курьерской заявке (`ADR-RET-085`). Изделие в заявке (`cms_return_positions.order_position_id`) ссылается на конкретную строку позиции заказа. Предлагаемый ответ: у каждой заявки своя строка «Заявка на возврат»; строки объединяются только после итога по ним — «Возврат» или отмена.

**4.1. Как делится строка позиции заказа, если клиент сдал в магазине без заявки изделия из действующей курьерской заявки?** Кому: System Architect (Леша Осипенко), Backend Developer (Оля Свистунова), 1C Solution Architect (Артём Колосов).

Изделия уже стоят в строке курьерской заявки со статусом «Заявка на возврат». Магазин принимает их без заявки, заявку создаёт 1С сразу в «Возврат принят», а курьерскую заявку отменяют позже клиент или Дружба (`ADR-RET-085`). Не определено, на какую строку ссылается заявка 1С — на строку курьерской заявки или на новую — и когда эта строка получает «Возврат»: сразу при приёмке в магазине или после отмены курьерской заявки.

#### 5. Объединяются ли строки позиции заказа в базе или только в данных, которые бэкенд отдаёт сайту, МП и внешним системам?

**Кому:** System Architect (Леша Осипенко), Backend Developer (Оля Свистунова)

Варианты:

- **В базе.** После итога изделия всех заявок переводятся на одну строку, лишние строки удаляются. Остаётся исходная строка — её id знают 1С и RetailCRM. Что делает 1С со строкой, которую сайт удалил: 1С сопоставляет позиции по id строки.
- **Только при выдаче.** Строки в базе не объединяются; бэкенд группирует их по товару и статусу в карточке заказа и в обмене («Возврат — 3 шт.»). Id строк не исчезают, ссылки из заявок не меняются.

Предложения расходятся, ни одно не согласовано:

- System Analyst — объединять только при выдаче;
- System Architect — объединять в базе: многие функции отдают заказ как есть, при объединении только при выдаче их все пришлось бы менять, а объединение в базе — изменение в одном месте. При объединении возвратная строка удаляется, количество исходной строки увеличивается ([разбор стендапа 23.11.2026](<../../meetings/[2026-11-23 09-59] Стэндап, есть часть про возвраты_summary.md>), тема 4).

#### 6. Как сайт передаёт в RetailCRM позицию, которая на сайте разделена на несколько строк?

**Кому:** RetailCRM (Intaro), Backend Developer (Оля Свистунова)

В RetailCRM позиция остаётся одной строкой, статусы и причины изделий — в свойствах позиции (решение 11). Если сайт делит строку позиции (вариант Б), в обмене с RetailCRM строки одного товара нужно собирать в одну позицию со свойствами по изделиям, а свойства из RetailCRM — раскладывать по строкам сайта. Какие свойства позиции и в каком формате RetailCRM передаёт по каждому изделию: статус, причина, уточнение причины? Нужно ли сайту делить строку позиции заказа, если RetailCRM ведёт статусы изделий в свойствах одной позиции? 1С сопоставляет позиции по id строки. System Architect предположил, что сайт передаёт в RetailCRM возвратные изделия отдельной позицией со свойством возврата (вместо «3 шт.» — позиции «2 шт.» и «1 шт.»); это не обсуждалось с RetailCRM ([разбор стендапа 23.11.2026](<../../meetings/[2026-11-23 09-59] Стэндап, есть часть про возвраты_summary.md>), тема 4). Строки одного товара в Mindbox — [mindbox-exchange_questions.md](./mindbox-exchange_questions.md), решение 11 и вопрос 8.

Статусы Mindbox для новых статусов позиции (`cms_mb_statuses_map`) — [mindbox-exchange_questions.md](./mindbox-exchange_questions.md), вопрос 6.

#### 7. Кто пересчитывает суммы, скидки и баллы строк позиции заказа, когда отделённая строка объединяется с исходной, — Mindbox или сайт?

**Кому:** System Architect (Леша Осипенко), Backend Developer (Оля Свистунова)

Цена хранится на одно изделие (решение 7), а суммы, скидки и баллы — на строку. При делении остаток от округления остаётся на строке с невозвращёнными изделиями (решение 8), начисленные баллы распределяет Mindbox (решение 9). Если клиент отменяет заявку и создаёт новую, строки делятся и объединяются многократно. System Architect считает, что пересчёт выполнит Mindbox, но не уверен ([разбор стендапа 23.11.2026](<../../meetings/[2026-11-23 09-59] Стэндап, есть часть про возвраты_summary.md>), тема 4). Как делится скидка по промокоду — [mindbox-exchange_questions.md](./mindbox-exchange_questions.md), вопрос 12.
