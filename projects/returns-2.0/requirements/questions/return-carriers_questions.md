### Коды служб возврата: обмен с логистикой и записи на сайте

Коды служб используются на двух уровнях.

**Обмен с логистикой.** В запросе пунктов выдачи и в вебхуке городов передаются обычные коды провайдеров `sdek-pvz` и `5post`. Возврат отличается от доставки только признаком: в запросе пунктов — `is_return_available = true`, в вебхуке городов — `has_return_points`. Других кодов для пунктов выдачи логистика не использует.

**Записи на сайте.** Города приёма возвратов сайт хранит в отдельном справочнике `cms_return_city` по коду провайдера логистики — тем же кодам `sdek-pvz` и `5post` (решение 6). Признак `has_return_points` меняет только этот справочник, `has_points` — как сейчас, привязку города к службе доставки.

| Где | ПВЗ СДЭК на возврат |
|---|---|
| Запрос пунктов выдачи в логистику | `sdek-pvz` + `is_return_available = true` |
| Вебхук городов от логистики | `sdek-pvz` + `has_return_points` |
| Список городов возврата на сайте | `cms_return_city`, провайдер `sdek-pvz` |

**Курьер СДЭК на возврат.** Отдельный код нужен и в обмене с логистикой: даты забора логистика отдаёт только по возвратному типу доставки, на код обычного курьера с `is_return = true` отвечает 400. Поэтому `sdek-courier-vzt` — общий код во всех системах: 1С, RetailCRM, сайт, логистика.

Заявки, по которым ранее заводили «СДЭК ПВЗ», — [OPEROPERACII-11760](https://tracker.yandex.ru/OPEROPERACII-11760) (ТК и тип доставки в 1С и WMS) и [SUP-58811](https://tracker.yandex.ru/SUP-58811) (тип доставки и ТК в 1С, на сайте и в RetailCRM), — касаются обычной доставки до ПВЗ, а не возврата.

### Ответ по коду: вебхук покрытия городов

Сейчас вебхук только включает и выключает города, которые уже есть у службы на сайте; новые города не добавляет. Служба ищется по коду среди служб с типом доставки «ПВЗ», поэтому курьерскую службу вебхук не меняет. Признак `has_points` обязателен: пустое значение отклоняется ошибкой `delivery.webhooks.provider_has_points_not_null`.

Источник — код монолита: `src/Modules/Delivery/Controller/WebhooksController.php` (`actionCityCarriersCoverage`), `src/Modules/Delivery/Service/DeliveryCoverageService.php` (`updateCoverageFromWebhook`), `src/Modules/Delivery/Repository/DeliveryCityRepository.php` (`updateStateByGeoIds`).

## Открытые вопросы

#### 1. Как определяется доступность «Почты России» для возврата: через возвратную службу со списком городов, как остальные способы, или фиксированным правилом по региону Калининград и Калининградская область? Есть ли на сайте служба «Почта России» для возврата?

#### 2. Какие службы прямой доставки считаются «курьер, как в заказе» для предвыбора способа «Курьер»: курьер, курьер с примеркой, экспресс-доставка?

**Кому:** логистика (Екатерина Филатова); вопрос из ECOMDEV-2684

Способ возврата, совпадающий со способом доставки заказа, предвыбирается, если город возврата — город заказа (`is_order_method`).

Предложение отправлено логистике (Екатерина Филатова, 17.11.2026, [тред](https://mattermost.12stz.com/12storeez/pl/jfncjirxs7rkmjsqosm45payoa)), сопоставление — по типу службы доставки заказа (`cms_delivery_types`), а не по `slug`: у курьерских служб `slug` свой у каждого исполнителя.

- Курьер, Курьер с примеркой, Курьер с отгрузкой, Экспресс-курьер → «Курьер СДЭК»
- ПВЗ СДЭК → «ПВЗ СДЭК»
- 5Post → «ПВЗ 5Post»
- Самовывоз из магазина → «Магазин 12 STOREEZ»
- Яндекс ПВЗ → способ заранее не выбирается

Подходит ли такое соответствие? Все ли типы доставки учтены?

#### 3. Как называются новые методы способов возврата для МП — в монолите и в Mobile API Gateway?

**Кому:** Катя Лемешева, iOS (вопрос из ECOMDEV-2684)

В SRS МП маршрут гейтвея — `GET /api/v2/delivery/{order_id}/return-method-list` (TBD). Старый метод `GET /mobile/orders/{order_id}/return-method-list` не меняется: им пользуются выпущенные версии приложения.

#### 4. Сохранится ли скрытое «Отображение» у возвратной службы `sdek-courier-vzt` в `cms_delivery_tk` после обмена справочником служб с 1С?
