# ADR-RET-062: Сайт всегда передаёт часовой пояс в запросе дат и интервалов курьера для возврата

| Поле | Значение |
|---|---|
| **Статус** | Принято |
| **Дата решения** | 14.10.2026 |
| **Владелец решения** | System Analyst (BTS) — Елена Васильева; участники: Project Manager — Катя Тихомирова, System Analyst — Катя Лемешева |
| **Область** | Интеграция |
| **Версия** | v1 |

## Контекст

Метод логистики для дат и интервалов принимает, кроме кода типа доставки, часовой пояс: интервалы
считаются в часовом поясе получателя. СДЭК сам определяет часовой пояс по адресу. При ручных
интервалах логистики (переключатель из `ADR-RET-060`) часовой пояс нужен от сайта.

Для прямого потока сайт уже всегда передаёт часовой пояс. При возврате город может подставляться
из заказа без повторной детализации в Geo.

## Решение

1. В запросе дат и интервалов курьера для возврата сайт всегда передаёт часовой пояс — независимо
   от того, откуда приходят интервалы (от ТК или ручные).
2. Часовой пояс берётся из детализации города в Geo. Если город подставлен без детализации —
   из кеша; если в кеше нет — сайт вызывает детализацию и кеширует ответ.

## Последствия

### Положительные

- Интервалы корректны при переключении на ручные интервалы.
- Не зависит от того, как другая ТК определяет часовой пояс.

### Отрицательные и риски

- При подстановке города из заказа возможен дополнительный вызов Geo.

## Рассмотренные альтернативы

### Переключатель «учитывать часовой пояс» в логистике

- **Результат:** отклонена.
- **Причина:** при подключении другой ТК её поведение может отличаться от СДЭК; проще всегда
  передавать часовой пояс.

## Условия пересмотра

- Логистика начнёт сама определять часовой пояс по адресу для всех ТК и ручных интервалов.
