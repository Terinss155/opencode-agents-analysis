## Контекст

Форма банковских реквизитов на сайте и в МП требует номер банковской карты при любом номере лицевого счёта (`FR-37`). Состав формы — минимальный набор реквизитов, номер договора в форму не добавляется (`ADR-RET-020`).

Подтверждённые факты:
- Бухгалтерия переводит возврат платёжным поручением по номеру счёта и БИК. Номер карты или номер договора нужен только для кредитного счёта: такой счёт начинается с «30232810». Это транзитный счёт банка, и зачислить деньги конкретному клиенту банк может только по номеру карты или договора.
- В документе 1С «Возврат клиента» нет поля для номера договора, поэтому из двух вариантов возможен только номер карты.
- На production кредитный счёт указан в 2,9 % заявок с номером карты, личный счёт — в 95 %.
- ИБ: хранение полного номера карты выводит компанию в полный контур PCI DSS и требует ГОСТ-шифрования. Номера карт сейчас хранятся в открытом виде, в том числе в журналах. Существующие данные инфраструктура разово чистит.
- Номер карты не выводится в заявлении на возврат и не хранится в его шаблоне (`ADR-RET-105`).
- Решение Project Manager о номере карты не разделяет этап 0 и «Возвраты 2.0».
- Старые версии МП требуют номер карты при любом счёте и передают его в запросе оформления возврата.

## Решение

Поле «Номер банковской карты» остаётся в форме реквизитов, но показывается только для кредитного счёта, то есть номера лицевого счёта, который начинается с «30232810». Для кредитного счёта номер карты обязателен, ровно 16 цифр. Для других счетов номер карты не запрашивается, не передаётся и не хранится.

Правило действует на этапе 0 и в «Возвратах 2.0».

Кредитный счёт определяют сайт и МП по началу номера счёта. Бэкенд при создании возврата или заявки проверяет то же правило. Если номер карты пришёл при некредитном счёте (старая версия МП), бэкенд запрос не отклоняет и номер карты не сохраняет.

## Последствия

### Положительные

- Номер карты собирается и хранится примерно в 3 % возвратов с реквизитами, а не во всех — с этапа 0.
- Возврат на кредитный счёт остаётся возможным: клиента не нужно просить указать другой счёт.
- Доработка 1С не нужна: поле номера карты в документе «Возврат клиента» уже есть.
- Для большинства клиентов форма реквизитов становится короче на одно поле.
- Этап 0 и «Возвраты 2.0» работают по одному правилу.

### Отрицательные и риски

- Полный номер карты всё равно хранится для кредитных счетов. Вопрос о ГОСТ-шифровании и сроке хранения для этих возвратов остаётся открытым.
- Начало номера кредитного счёта зафиксировано в коде сайта и МП. Если бухгалтерия назовёт другие начала номера, понадобится выпуск приложения.
- Если клиент укажет кредитный счёт другого вида, номер карты не будет запрошен. Тогда недостающие данные запрашивает Дружба (`ADR-RET-020`).
- Старые версии МП продолжают показывать поле карты при любом счёте, пока клиент не обновит приложение; номер карты от них не сохраняется.
- Правка этапа 0 затрагивает задачи бэка, сайта, iOS и Android.

## Рассмотренные альтернативы

### Номер карты обязателен при любом счёте

- **Результат:** отклонена.
- **Причина:** номер карты собирается и хранится во всех возвратах с реквизитами, хотя бухгалтерии он нужен только для кредитного счёта. Хранение требует ГОСТ-шифрования и защиты номера в 1С и RetailCRM.

### Правило только для «Возвратов 2.0», на этапе 0 номер карты обязателен всегда

- **Результат:** отклонена.
- **Причина:** этап 0 собирал бы номер карты во всех возвратах с реквизитами до выпуска «Возвратов 2.0», а в продукте действовали бы два правила для одной формы.

### Без номера карты, кредитный счёт не принимается

- **Результат:** отклонена.
- **Причина:** клиенту, который просит вернуть деньги на кредитный счёт, пришлось бы указывать другой счёт.

### Номер договора вместо номера карты

- **Результат:** отклонена.
- **Причина:** в документе 1С «Возврат клиента» нет поля для номера договора. Потребовалась бы доработка 1С и обмена.

## Условия пересмотра

- Бухгалтерия назовёт другие начала номера кредитного счёта, кроме «30232810».
- ИБ запретит хранить полный номер карты без ГОСТ-шифрования, а ГОСТ-шифрование не будет реализовано к выпуску.
- В документе 1С «Возврат клиента» появится поле для номера договора.
