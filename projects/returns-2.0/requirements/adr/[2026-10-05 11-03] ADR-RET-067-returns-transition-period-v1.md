# ADR-RET-067: Переходный период — старые возвраты доводятся по старой схеме, ручной перевод заказов в возвратные статусы блокируется

| Поле | Значение |
|---|---|
| **Статус** | Предложено |
| **Дата решения** | Не определена |
| **Владелец решения** | Project Manager — Катя Тихомирова (предложение); участник: System Analyst — Катя Лемешева |
| **Область** | Бизнес-процесс / RetailCRM |
| **Версия** | v1 |

## Контекст

Сейчас возврат оформляется сменой статусов заказа и позиций. В новой схеме возврат — отдельная
сущность (`ADR-RET-002`). На момент запуска будут возвраты, начатые по старой схеме. Правило
переходного периода не определено (BRD, риск `R-17`).

## Решение

1. В момент запуска в RetailCRM блокируется ручной перевод заказов в статусы заявки на возврат.
2. Возвраты, оформленные по старой схеме до запуска, доводятся до финала по старой схеме.
3. Новые возвраты после запуска создаются только как отдельная сущность возврата.
4. Отдельные оповещения о переключении не нужны.

## Последствия

### Положительные

- Старые возвраты не переносятся в новую сущность.
- После запуска нельзя оформить возврат по старой схеме.

### Отрицательные и риски

- Какое-то время в системах живут обе схемы; отчётность по возвратам нужно собирать из двух
  источников.
- Не определены дата переключения и как показывать старые возвраты в ЛК и МП.

## Рассмотренные альтернативы

### Перенести возвраты, начатые до запуска, в новую сущность

- **Результат:** отклонена в предложении.
- **Причина:** не обсуждалась как реалистичная; блокировка статусов проще.

## Условия пересмотра

- RetailCRM не сможет заблокировать ручной перевод в возвратные статусы.
- На дату запуска окажется много незавершённых возвратов по старой схеме.
