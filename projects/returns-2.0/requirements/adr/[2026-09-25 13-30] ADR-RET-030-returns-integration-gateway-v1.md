## Контекст

Связь RetailCRM и 1С сейчас реализована через сайт. Команда разработки считает такую схему
неудачной и требующей переписывания. До новой архитектуры единой мастер-системы нет
(`ADR-RET-018`).

Цель проекта — до конца квартала отказаться от вложения бумажных заявлений.

## Решение

Новый функционал возвратов (и выездных примерок) реализуется через шлюз (gateway) по образцу
интеграции Modern Retail. Методы делаются только под возвраты, а логика обменов постепенно переносится
на новую архитектуру.

Для команды RetailCRM объём работ не меняется: меняется только точка подключения. Head of PMO
поставила условие: если переделку не успеть в этом квартале, проект идёт по текущей схеме.

## Последствия

### Положительные

- Закладывается основа переделки обменов без блокировки проекта.
- RetailCRM получает возможность обращаться напрямую в нужную систему.

### Отрицательные и риски

- Растёт объём работ BSA: шлюз нужно поднимать.
- Риск не уложиться в квартал. Тогда работа идёт по текущей схеме.

## Рассмотренные альтернативы

### Обмены по возвратам через монолит сайта (текущая схема)

- **Результат:** остаётся запасным вариантом.
- **Причина:** архитектурно слабая схема, требует переписывания.
