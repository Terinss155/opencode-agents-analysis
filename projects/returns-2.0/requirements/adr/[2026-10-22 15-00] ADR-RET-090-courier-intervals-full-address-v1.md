# ADR-RET-090: В запросе дат и интервалов курьера передаётся только полный адрес — для доставки и для возврата; код города не передаётся

## Контекст

Адрес клиента для возврата передаётся в логистику как адрес отправки, а не адрес доставки (`ADR-RET-060`, решение 3). Для прямого потока СДЭК нужен полный адрес с домом: внутри города разные макрозоны и разная доступность интервалов. Для возвратного потока СДЭК ответил: «Необходимо передавать полный адрес НП, улицу и дом», хотя метод СДЭК для дат возврата принимает и код города. Полную строку адреса от геосервиса СДЭК принимает, в том числе с индексом.

## Решение

1. В запросе дат и интервалов курьера передаётся только полный адрес — и для прямого потока, и для возврата. Код города (ФИАС) в запросе сейчас не передаётся.
2. Логика одинакова для доставки и возврата: полный адрес берётся из геосервиса или собирается из полей адреса. Правило одно для сайта и мобильного приложения.
3. В логистике это два разных параметра: для прямого потока — адрес доставки, для возврата — адрес отправки. Адрес передаётся строкой.

## Последствия

### Положительные

- Одна логика адреса для доставки и возврата.
- По предположению участников, полный адрес понадобится, когда СДЭК начнёт отдавать интервалы для возврата, и для новых ТК.

### Отрицательные и риски

- Для ручного адреса детализация адреса в геосервисе не вызывается — строку нужно собирать по схеме, она не согласована.
- Для новых ТК может понадобиться разбивать адрес по полям.

## Рассмотренные альтернативы

### Для возврата — код города, для прямого потока — полный адрес

- **Результат:** отклонена.
- **Причина:** логику нужно делать одинаковой для обоих потоков; полный адрес универсальнее.

## Открытые вопросы

1. Параметры запроса для возврата. По переписке логистика предварительно планирует тот же метод `Intervals` с новыми параметрами `is_return: true` и `sending_address` (строка); для прямого потока — `delivery_address` (строка). Это предварительно, «если команда не зарубит»; контракт согласуется в канале проекта.
2. Из чего состоит строка полного адреса? Для адреса из геосервиса — `fullTitle` из детализации адреса (страна, регион, населённый пункт, улица, дом). Для ручного адреса предложено собирать строку по той же схеме — страна, регион, населённый пункт, улица, дом: страну, регион и населённый пункт брать из детализации города и добавлять через запятую улицу и дом. Регион нужен, потому что бывают города с одинаковыми названиями. Это предложение, не решение. System Analyst BTS публикует состав полного адреса в канале.

## Условия пересмотра

- СДЭК начнёт отдавать конкретные интервалы для возврата — проверить, что полного адреса достаточно.
- Подключаются новые ТК, которым нужен адрес по полям.
