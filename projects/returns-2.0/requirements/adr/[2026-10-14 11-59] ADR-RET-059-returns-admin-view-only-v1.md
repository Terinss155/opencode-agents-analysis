# ADR-RET-059: В админке сайта — список и карточка возвратов только для просмотра, без редактирования

| Поле | Значение |
|---|---|
| **Статус** | Предложено |
| **Дата решения** | Не определена |
| **Владелец решения** | Project Manager — Катя Тихомирова (предложение); участники: Team Leader — Максим Пестов, System Architect — Леша Осипенко |
| **Область** | Продукт / Админка сайта |
| **Версия** | v1 |

## Контекст

В админке сайта есть список заказов с карточкой и журналом обменов. Его используют разработчики, QA,
команда 1С и Project Manager: смотрят обмены с RetailCRM и 1С и разбирают расхождения. Отдел Дружбы
открывает заказ в админке, чтобы отправить ссылку. Список заказов в админке давно планируют убрать,
чтобы управлять заказами только в RetailCRM.

Возврат хранится на сайте как отдельная сущность (`ADR-RET-018`, `ADR-RET-044`). Оформляет возврат
Дружба в RetailCRM, в админке сайта такой операции нет (`ADR-RET-014`). По возвратам будет много
обменов.

Журнал обменов по заказам хранится в БД сайта, и из-за этого были сбои. В требованиях раздел
возвратов в админке не обсуждался.

## Решение

1. В админке сайта делаются список возвратов и карточка возврата — только для просмотра.
2. Изменять возврат через админку сайта нельзя; управление возвратами — в RetailCRM.
3. Показывать ли журнал обменов по возврату в админке, этим решением не определено. Предложены
   варианты: журнал в карточке, как у заказов, или отдельная страница в Grafana с фильтрами по
   возврату, доступная QA, команде 1С и Project Manager. Параллельно предложено завести задачу на
   вынос журналов по заказам и возвратам из БД сайта.

Решение выносится на встречу по возвратам 15.10.2026.

## Последствия

### Положительные

- QA, разработчики и команда 1С видят данные возврата на сайте и могут сверять их с RetailCRM.
- Отсутствие редактирования не противоречит `ADR-RET-014` и не создаёт второй точки изменения
  возврата.

### Отрицательные и риски

- Растёт функциональность админки, которую для заказов планируют убрать.
- Если журнал обменов будет храниться в БД сайта, по возвратам возможны те же сбои, что по заказам.

## Рассмотренные альтернативы

### Не делать возвраты в админке

- **Результат:** отклонена в предложении.
- **Причина:** без админки негде проверить данные возврата на сайте, кроме БД; обмен с RetailCRM
  бывает нестабилен.

### Список и карточка с редактированием, как у заказов

- **Результат:** отклонена.
- **Причина:** управление возвратами — только в RetailCRM.

## Условия пересмотра

- На встрече по возвратам 15.10.2026 владельцы продукта не подтвердят раздел возвратов в админке.
- Выбран способ показа журнала обменов (админка или Grafana).
- Из админки уберут список заказов.
