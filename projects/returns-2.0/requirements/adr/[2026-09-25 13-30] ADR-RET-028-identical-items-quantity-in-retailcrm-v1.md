# ADR-RET-028: Одинаковые позиции в RetailCRM в MVP передаются количеством, без разбиения по строкам

## Контекст

Если в заказе несколько единиц одного артикула, в RetailCRM меняется только количество. Разбиение
товаров по строкам в RetailCRM есть, но не включено. Чтобы оно корректно работало, нужно
переписывать интеграцию с сайтом.

На сайте каждая единица показывается отдельно и выбирается галочкой (`ADR-RET-012`). Поэтому
возникает вопрос, как передать в RetailCRM возврат одной из двух одинаковых единиц и разные причины
для них.

## Решение

В MVP разбиение по строкам в RetailCRM не включается. В окне создания возврата сотрудник выбирает
количество, и оно переносится в возвратный заказ. Разбиение по строкам — отдельный трек вместе с
переработкой интеграции с сайтом.

Разные причины или статусы для одинаковых единиц одного артикула — редкий случай (менее 1% заказов
за год). Он отложен и в MVP не поддерживается.

## Последствия

### Положительные

- Интеграция RetailCRM ↔ сайт для MVP не переписывается.

### Отрицательные и риски

- При смене статуса одной из нескольких одинаковых единиц в исходном заказе статус меняется у всех.
- Если на сайте клиент укажет разные причины для одинаковых единиц (`ADR-RET-012`), передать их в
  RetailCRM раздельно нельзя. Как поступать в этом случае, не определено.

## Рассмотренные альтернативы

### Включить разбиение по строкам в MVP

- **Результат:** отложена (отдельный трек).
- **Причина:** нужно переписывать интеграцию с сайтом — это большая отдельная работа.

## Условия пересмотра

- Начинается трек по разбиению по строкам.
- Доля заказов с разными причинами для одинаковых единиц заметно превышает 1%.
