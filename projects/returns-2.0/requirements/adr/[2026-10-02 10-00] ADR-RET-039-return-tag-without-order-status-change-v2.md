# ADR-RET-039: Статус исходного заказа не меняется, статусы позиций — «Заявка на возврат» → «Возвращено»

## Контекст

В v1 (`ADR-RET-015`, предложение от 01.10.2026) предлагалось не менять при возврате ни статус
заказа, ни статусы позиций, а признак возврата вычислять по связи позиции заказа с позицией возврата.

Статус исходного заказа при возврате не меняется (`ADR-RET-019`; 25.09.2026 — «как у Lamoda»).
Сейчас при оформлении заявки меняется статус заказа: возврат из ЛК, частичный или полный.

Product Manager обосновала, зачем нужен статус позиции. Когда клиент звонит в Дружбу, сотрудник должен
видеть, по каким позициям уже есть действия, в том числе до того, как изделие вернулось.

## Решение

Статус исходного заказа при возврате не меняется и остаётся «Выполнен», даже если возвращены все
позиции.

Меняются статусы позиций исходного заказа:
1. Промежуточный — «Заявка на возврат». Ставится в момент подачи заявки, когда изделие ещё не
   вернулось.
2. Финальный — «Возвращено». Ставится, когда возврат совершился.

Если клиент звонит в Дружбу по уже оформленной заявке, сотрудник находит связанный возвратный заказ
из исходного и дорабатывает его, не создавая дубль.

## Последствия

### Положительные

- Дружба видит в исходном заказе, по каким позициям уже есть заявки и возвраты.
- Повторный возврат тех же позиций виден сразу.

### Отрицательные и риски

- На статусы позиций завязаны триггеры Mindbox и уведомления — их нужно проверить и переделать.
- Расходится с BRD `RULE-29`: там сказано, что состояние возврата не является статусом позиции заказа.
- При нескольких одинаковых единицах в одной строке (без разбиения по строкам, `ADR-RET-028`) статус
  меняется у всех единиц сразу.
- Нужно определить, что происходит со статусом позиции при отмене заявки (это войдёт в статусную
  схему `ADR-RET-040`).

## Рассмотренные альтернативы

### Не менять статусы позиций, вычислять признак по связи (решение v1)

- **Результат:** отклонена.
- **Причина:** Дружбе нужен явный статус позиции в исходном заказе.

### Менять статус позиции только в финале (при возврате)

- **Результат:** отклонена.
- **Причина:** между заявкой и возвратом Дружба не увидит, что по позиции уже есть заявка.

## Условия пересмотра

- Проверка триггеров Mindbox покажет, что новые статусы позиций ломают коммуникации.
