# ADR-RET-103: Токен вебхука RetailCRM передаётся в заголовке `X-Api-Token`

| Поле | Значение |
|---|---|
| **Статус** | Принято |
| **Дата решения** | 16.11.2026 |
| **Владелец решения** | Backend Developer (Оля Свистунова), Лид аналитиков RetailCRM (Алена Господинова) |
| **Область** | Интеграция / Безопасность |
| **Версия** | v1 |

## Контекст

- Вебхук RetailCRM сейчас передаёт токен в строке запроса ([разбор встречи 16.11.2026](<../../meetings/[2026-11-16 15-06] Weekly 12storeez & Intaro_summary.md>), тема 5).
- Сайт проверяет токен из параметра строки запроса `token` по таблице `api_tokens`. Проверка общая для всех методов модуля API сайта: заказы (`OrdersNewController`, `OrdersController`), товары, магазины, клиенты (код монолита, `modules/api/controllers/ApiController.php`).
- Тем же вебхуком RetailCRM будет передавать платёжные реквизиты заявки на возврат — номер карты и другие банковские данные (тема 5 разбора). Лид аналитиков RetailCRM рекомендовала перенести токен в заголовок, чтобы не скомпрометировать эти данные.

## Решение

RetailCRM передаёт токен вебхука в заголовке `X-Api-Token`. Сайт принимает токен из заголовка; приём токена из строки запроса пока сохраняется.

## Последствия

### Положительные

- Токен не попадает в URL запроса, по которому передаются платёжные реквизиты.
- Остальные потребители модуля API продолжают работать с токеном в строке запроса; переключение RetailCRM на заголовок не ломает обмен.

### Отрицательные и риски

- Пока сайт принимает токен из строки запроса, токен в URL остаётся допустимым: защита реквизитов зависит от того, что RetailCRM переключил вебхук на заголовок (открытый вопрос 1).
- Доработка на двух сторонах: настройка вебхука RetailCRM и приём на сайте.

## Рассмотренные альтернативы

### Оставить токен только в строке запроса

- **Результат:** не выбрана.
- **Причина:** перенос токена в заголовок — рекомендация RetailCRM для безопасности, чтобы не скомпрометировать передаваемые платёжные реквизиты; Backend Developer согласилась доработать приём.

### Принимать токен только из заголовка

- **Результат:** не выбрана.
- **Причина:** приём из строки запроса сохраняется, чтобы ничего не сломать при переключении.

1. Когда сайт перестаёт принимать токен из строки запроса для вебхука RetailCRM?

## Условия пересмотра

- Обмен с RetailCRM переходит на другой способ аутентификации (например, подпись запроса).
- Платёжные реквизиты перестают передаваться вебхуком RetailCRM.
