# ADR-RET-089: Для адреса курьера, введённого вручную, даты и интервалы запрашиваются у логистики; не пришли — заявка уходит Дружбе

## Контекст

При возврате способом «Курьер» клиент указывает адрес забора: подставленный из заказа или новый, выбранный из подсказок геосервиса. Геосервис может не найти адрес — например, клиент ошибся в адресе или индексе — или быть недоступен. Если в заказе был некорректный адрес, при возврате подставится тот же (из v1).

В прямом потоке заказ с адресом, введённым вручную, оформляется: получает причину обработки «проверить адрес» (`address_check`), в RetailCRM уходит комментарий «Необходимо проверить адрес и условия доставки (адрес был введён вручную).», Дружба уточняет адрес у клиента (из v1).

В v1 (`ADR-RET-074`) для ручного адреса даты и интервалы курьера не запрашивались: заявка сразу уходила Дружбе, Дружба уточняла адрес и согласовывала дату при звонке.

Для дат СДЭК в прямом потоке логистике нужен полный адрес, сейчас сайт его не передаёт. У СДЭК свой геосервис: при проверке адресов заказов с прода для прямого потока по 3 адресам РФ из 5 даты пришли.

На встрече System Analyst BTS спросила, есть ли смысл получать интервалы для ручного адреса, если Дружба всё равно свяжется с клиентом. Head of Customer Service: Дружба уточнит, но задача — снизить число ручных обращений к Дружбе, и «если мы пока можем там помочь, мы поможем»; пытаться получить даты для всех адресов — «Конечно». Product Manager: это сократит нагрузку на Дружбу и время обработки.

## Решение

1. В форме возврата способом «Курьер» клиент может ввести адрес вручную, без выбора из подсказок геосервиса, — как при оформлении заказа (без изменений из v1).
2. Для адреса, введённого вручную, даты и интервалы курьера запрашиваются у логистики, как для адреса из подсказок.
3. Если логистика вернула даты, клиент выбирает дату и интервал, и заявка идёт по обычному сценарию: получает «Заявка на возврат принята» (подтверждено участником встречи).
4. Если логистика вернула ошибку или ответ без дат, заявка уходит Дружбе в статусе «Возврат ожидает обработки» — по `ADR-RET-075`; на встрече так был поставлен вопрос, отдельно не обсуждалось.
5. Если адрес введён вручную и даты не получены, вместе с заявкой в RetailCRM передаётся причина обработки «проверить адрес», как у заказа: Дружба видит, что адрес нужно проверить (подтверждено участником встречи). Если даты получены, причина не передаётся.

## Последствия

### Положительные

- Ошибка в адресе или недоступность геосервиса не блокирует оформление возврата курьером (из v1).
- Меньше заявок уходит в ручную обработку Дружбы: если СДЭК распознал адрес, клиент выбирает дату сам.

### Отрицательные и риски

- Для ручного адреса строку адреса нужно собирать без детализации адреса в геосервисе; состав строки не согласован (`ADR-RET-090`).
- Проверка «3 из 5» делалась для прямого потока; для возврата адрес идёт в другой метод СДЭК.
- Клиент может ввести адрес вручную, даже если подходящий адрес был в подсказках (из v1).
- Ручной адрес больше не всегда ведёт в «Возврат ожидает обработки»: на диаграмме состояний меняется переход S15.

## Рассмотренные альтернативы

### Не запрашивать даты для ручного адреса (решение v1)

- **Результат:** заменена.
- **Причина:** задача — снизить число обращений к Дружбе (Head of Customer Service, Product Manager).

### Только адрес из подсказок геосервиса

- **Результат:** отклонена (из v1).
- **Причина:** клиент с адресом, который геосервис не находит, или при недоступности геосервиса не может оформить возврат курьером; в прямом потоке такой заказ оформляется.

### Отдельный статус для заявки с ручным адресом

- **Результат:** отклонена (из v1).
- **Причина:** причину Дружба видит в комментарии RetailCRM, отдельный статус для этого не нужен.

## Открытые вопросы

1. Отдаёт ли возвратный метод СДЭК даты для ручных адресов? Проверка делалась для прямого потока.
2. Будет ли так же для заказа: запрашиваются ли даты для ручного адреса в прямом потоке? Вопрос ставился и про заказ.

## Условия пересмотра

- По ручным адресам СДЭК массово возвращает ошибку — запрос не снижает нагрузку на Дружбу.
- В прямом потоке изменится обработка заказов с адресом, введённым вручную (из v1).
