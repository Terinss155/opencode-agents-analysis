# ADR-RET-018: Без единой мастер-системы возврата до новой архитектуры

| Поле | Значение |
|---|---|
| **Статус** | Принято |
| **Дата решения** | Не определена (решение архитектурного комитета, озвучено 24.09.2026) |
| **Владелец решения** | Архитектурный комитет; озвучил TeamLead ERP 1C Development — Алексей Крицин; подтвердила Head of PMO — Светлана Варцаба |
| **Область** | Архитектура / Данные |
| **Версия** | v1 |

## Контекст

Возврат — отдельная сущность на сайте, в RetailCRM и 1С (`ADR-RET-002`). Нужно было определить,
какая система является мастер-системой этой сущности (`OQ-19`; предварительно — 1С).

Для заказа единой мастер-системы в текущей архитектуре нет: в разные моменты жизненного цикла
источником данных служат разные системы. Мастер-системы определены в новой архитектуре.

## Решение

До перехода на новую архитектуру единой мастер-системы для возврата нет. Как и для заказа, в разные
моменты жизненного цикла источником данных возврата служат разные системы.

На сайте возврат — отдельная сущность со своими статусами. К ней привязан раздел «Возвраты» в ЛК,
где показывается как минимум статус возврата.

Мастер-система возврата определяется в рамках новой архитектуры.

## Последствия

### Положительные

- Текущая архитектура обмена не перерабатывается: возврат повторяет модель заказа.
- Проект не ждёт решения о целевой архитектуре.

### Отрицательные и риски

- Источник истины при расхождениях зависит от этапа: правило выбора источника для каждого статуса
  нужно описать отдельно (`OQ-1`).
- Возрастает риск расхождения данных между сайтом, RetailCRM и 1С. Нужна гарантированная и
  идемпотентная передача данных (`INT-09`).
- При переходе на новую архитектуру потребуется миграция ответственности за данные возврата.

## Рассмотренные альтернативы

### Назначить мастер-системой 1С

- **Результат:** отклонена для текущей архитектуры.
- **Причина:** архитектурный комитет решил не перерабатывать текущую архитектуру; для заказа
  единой мастер-системы тоже нет.

## Условия пересмотра

- Начинается переход на новую архитектуру, где определены мастер-системы.
- Архитектурный комитет согласует предложение от 25.09.2026: обмены по возвратам реализовать через
  новый шлюз (gateway), заложив основу переделки обменов. Head of PMO: если переделку не успеть в
  этом квартале — идти по текущей схеме.
- Расхождения данных возврата между системами не удаётся разрешить без назначения единого
  источника.
