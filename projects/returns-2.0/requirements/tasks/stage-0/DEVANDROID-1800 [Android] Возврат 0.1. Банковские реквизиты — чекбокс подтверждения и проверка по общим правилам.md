# DEVANDROID-1800: [Android] Возврат 0.1. Банковские реквизиты: чекбокс подтверждения и проверка по общим правилам

## Цель

Сейчас клиент не подтверждает банковские реквизиты при возврате, а 1С нужно подтверждение для разбора спорных ситуаций. Экран реквизитов проверяет поля только масками и длиной, а при неверном значении клиент не видит, какое поле исправить: кнопка просто недоступна.

Нужно:

1. Добавить на экран реквизитов чекбокс подтверждения и передавать признак `is_bank_details_confirmed` в запросе оформления возврата.
2. Проверять поля экрана реквизитов по тем же правилам, что и бэк, и показывать ошибку под полем.

Связанные задачи на бэк: ECOMDEV-2649 (признак подтверждения в `POST /mobile/orders/{order_id}/return`), ECOMDEV-2526 (правило «нужны реквизиты» и правила формата). Задача iOS с теми же требованиями — DEVIOS-2709.

> Колонки «Что сейчас» составлены по коду iOS. Код Android не проверялся {red}(сверить поведение Android и поправить колонки при расхождении).

## Описание реализации

### 1. Показ блока реквизитов

Нужны ли реквизиты, решает бэк: признак `return.is_bank_data_required` в данных заказа (`GET /api/orders/{order_id}` через ESB). Своей логики по способу оплаты в приложении нет и не добавляется.

| № | Экран | Что меняется | Что сейчас |
|---|---|---|---|
| 1 | «Способ возврата»: блок «Банковские реквизиты» | блок показывается только при `is_bank_data_required = true` | так и работает, не меняется |
| 2 | «Способ возврата»: кнопка оформления возврата | при `is_bank_data_required = true` и незаполненных, неверных или неподтверждённых реквизитах — подсветка блока реквизитов и прокрутка к нему | так и работает; условие меняется по разделу 2 |

Если признак не пришёл в данных заказа, блок показывается, как сейчас.

Правило «нужны реквизиты» меняется на бэке (ECOMDEV-2526). После выкатки бэка блок начнёт показываться по новому правилу без доработки приложения, включая уже установленные версии.

### 2. Экран «Банковские реквизиты»

| № | Что меняется | Что сейчас |
|---|---|---|
| 1 | Поля проверяются по правилам из таблицы ниже, ошибка показывается под полем | ошибки под полями нет, недоступна кнопка |
| 2 | ИНН банка необязателен | обязателен, ровно 10 цифр |
| 3 | Номер лицевого счёта — ровно 20 цифр | на iOS маска ограничивает 20 цифрами, но кнопка проверяет только, что поле не пустое |
| 4 | Под полями — чекбокс подтверждения реквизитов, по умолчанию не отмечен | чекбокса нет |
| 5 | Кнопка «Готово» доступна, только если все поля прошли проверку и чекбокс отмечен | доступна, если поля заполнены (БИК — 9, ИНН — 10, карта — 16 цифр) |
| 6 | Поле «Номер банковской карты» показывается, только если номер лицевого счёта начинается с {red}(`30232810`) (кредитный счёт) | показывается всегда, обязательно |

**Правила проверки полей** — совпадают с ECOMDEV-2526 §2:

| Поле | Правило |
|---|---|
| Фамилия получателя | обязательно, до 255 символов |
| Имя получателя | обязательно, до 255 символов |
| Отчество получателя | обязательно, до 255 символов |
| Название банка | обязательно, до 255 символов |
| БИК банка | обязательно, ровно 9 цифр |
| ИНН банка | необязательно; если заполнено — ровно 10 цифр |
| Номер лицевого счёта | обязательно, ровно 20 цифр |
| Номер банковской карты | только при кредитном счёте: обязательно, ровно 16 цифр |

Маски ввода и цифровая клавиатура для БИК, ИНН, счёта и карты не меняются. Проверка ссылок и тегов в ФИО и названии банка остаётся только на бэке, её ошибка показывается по разделу 4.

Поле «Номер банковской карты» скрыто, пока номер счёта не начинается с {red}(`30232810`). Если клиент изменил счёт на некредитный, поле скрывается, а введённый номер карты не проверяется и не отправляется.

Когда проверяется:

- при выходе из поля: если значение не проходит правило, под полем показывается текст ошибки;
- при вводе в поле с ошибкой: ошибка скрывается, как только значение начинает проходить правило.

Тексты ошибок — как на сайте:

| Ситуация | Текст ошибки |
|---|---|
| Поле пустое | Заполните это поле |
| БИК не из 9 цифр | Неверный формат БИК |
| ИНН заполнен не из 10 цифр | Неверный формат ИНН |
| Счёт не из 20 цифр | Неверный формат номера счета |
| Карта не из 16 цифр | Неверный формат карты |

Отображение ошибки под полем — по макету экрана.

**Чекбокс подтверждения**

- Текст: «Подтверждаю корректность указанных мной банковских реквизитов» — как на сайте.
- По умолчанию не отмечен. Отметка — осознанное действие клиента, предзаполнять её нельзя.
- Отметка сохраняется вместе с реквизитами: при повторном открытии экрана чекбокс отмечен.
- Изменение любого поля снимает отметку: клиент подтверждает реквизиты в том виде, в котором они уйдут в возврат.

### 3. Оформление возврата

`POST /api/orders/{order_id}/return` (через ESB → `POST /mobile/orders/{order_id}/return`):

| № | Что меняется | Что сейчас |
|---|---|---|
| 1 | При `is_bank_data_required = true` в теле запроса вместе с реквизитами передаётся `is_bank_details_confirmed = true` | передаются только реквизиты и позиции |
| 2 | При `is_bank_data_required = false` запрос — как сейчас, без `is_bank_details_confirmed` | — |

| Параметр | Место | Тип данных | Значение |
|---|---|---|---|
| `is_bank_details_confirmed` | `body` | `boolean` | `true` — чекбокс отмечен |

Остальные параметры запроса не меняются.

### 4. Ошибки от бэка

При оформлении возврата бэк возвращает ошибку текстом. Приложение показывает этот текст пользователю, как сейчас. Формат ответа с ошибкой бэк не меняет. Новая ошибка бэка — «Подтвердите банковские реквизиты», если реквизиты нужны, а признак подтверждения пришёл со значением `false`.

### 5. Выкатка

Новая версия приложения выпускается после выкатки ECOMDEV-2526 пп. 3–4. Сейчас бэк при оплате курьеру требует ИНН банка и номер карты при любом счёте и отклонит возврат без них.

- После выкатки бэка старые версии приложения продолжают работать: ИНН и номер карты они передают, бэк их принимает, номер карты при некредитном счёте не сохраняет.
- Бэк принимает запрос без `is_bank_details_confirmed` от старых версий приложения (признак сохраняется как `null`).

## Критерии приёмки

### Показ блока реквизитов

1. Блок «Банковские реквизиты» показывается, только если в данных заказа `is_bank_data_required = true`.
2. При `is_bank_data_required = true` возврат нельзя оформить, пока реквизиты не заполнены, не прошли проверку и не подтверждены: блок подсвечивается, экран прокручивается к нему.
3. При `is_bank_data_required = false` блок не показывается и возврат оформляется без реквизитов.

### Экран реквизитов

4. Для каждого поля из таблицы раздела 2 неверное значение даёт ошибку под полем с текстом из таблицы при выходе из поля; ошибка скрывается, как только значение исправлено.
5. Пустой ИНН не даёт ошибки; заполненный не полностью — даёт.
6. Номер счёта короче 20 цифр даёт ошибку.
7. Чекбокс подтверждения по умолчанию не отмечен; «Готово» недоступна, пока хотя бы одно поле не проходит проверку или чекбокс не отмечен.
8. При повторном открытии экрана отметка чекбокса сохраняется; изменение любого поля снимает отметку.
9. Подписи полей, маски ввода и клавиатуры не изменились.
10. Поле «Номер банковской карты» скрыто, пока номер счёта не начинается с `30232810`; при таком счёте поле показывается и обязательно.
11. Если счёт изменён с кредитного на другой, поле карты скрывается, ошибка по нему не мешает «Готово», номер карты в запрос не передаётся.

### Оформление возврата

12. При `is_bank_data_required = true` в `POST /api/orders/{order_id}/return` передаётся `is_bank_details_confirmed = true`.
13. Набор реквизитов, который принимает экран, не получает ошибок формата от бэка (кроме ссылок и тегов в ФИО и названии банка).
14. Если бэк отклонил возврат, пользователю показывается текст ошибки из ответа.
15. Сценарий возврата без реквизитов (онлайн-оплата без сертификата) работает как раньше.
