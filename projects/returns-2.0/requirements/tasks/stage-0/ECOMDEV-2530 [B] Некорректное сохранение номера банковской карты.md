# ECOMDEV-2530: [B] Некорректное сохранение номера банковской карты

## Цель

Номер банковской карты, который клиент указал при оформлении возврата в мобильном приложении, должен сохраняться в заказе и передаваться в 1С и RetailCRM без искажений. Это нужно, чтобы деньги вернулись по корректным реквизитам.

## Описание проблемы

**Где:** `POST /mobile/orders/{order_id}/return`. Приложение вызывает его через ESB как `POST /api/orders/{order_id}/return`.

**Шаги воспроизведения:**

1. В мобильном приложении открыть заказ, для которого нужны реквизиты (например, оплаченный курьеру).
2. Оформить возврат, указав реквизиты, у которых номер лицевого счёта и номер карты различаются.
3. Открыть заказ в админке и посмотреть реквизиты возврата.

**Фактический результат:** в поле «Номер банковской карты» записан номер лицевого счёта. Номер карты из запроса проверяется на корректность, но не сохраняется.

**Ожидаемый результат:** в поле «Номер банковской карты» записан номер карты, который клиент указал в приложении.

На сайте ошибки нет: возврат через сайт сохраняет номер карты корректно.

## Описание реализации

1. При оформлении возврата из мобильного приложения сохранять в поле номера карты значение номера карты из запроса, а не номера лицевого счёта.
2. Убедиться, что исправленное значение передаётся дальше: в карточку заказа в админке, в 1С и в RetailCRM.
3. Выгрузить список заказов с возвратом, оформленным из мобильного приложения, у которых номер карты совпадает с номером лицевого счёта. Передать список бизнесу и финансам, чтобы они решили, нужно ли уточнять реквизиты у клиентов и исправлять данные в 1С и RetailCRM. Исправление исторических данных в задачу не входит.

## Критерии приёмки

1. После оформления возврата из мобильного приложения в заказе сохраняются оба значения ровно так, как их указал клиент:
   - номер лицевого счёта;
   - номер карты.
2. Номер карты, указанный клиентом, отображается в карточке заказа в админке.
3. Номер карты, указанный клиентом, передаётся в 1С.
4. Номер карты, указанный клиентом, передаётся в RetailCRM.
5. Остальные реквизиты (ФИО, БИК, ИНН, название банка, номер лицевого счёта) сохраняются и передаются как раньше.
6. Возврат через сайт работает как раньше.
7. Выгружен и передан бизнесу список затронутых заказов: номер заказа, дата оформления возврата, клиент.
