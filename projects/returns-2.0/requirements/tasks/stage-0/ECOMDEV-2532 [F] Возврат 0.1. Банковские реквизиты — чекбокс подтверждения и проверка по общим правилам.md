# ECOMDEV-2532: [F] Возврат 0.1. Банковские реквизиты: чекбокс подтверждения и проверка по общим правилам

## Цель

Передавать проверенные и подтверждённые клиентом реквизиты в запросе создания возврата, чтобы к возврату попадали реквизиты, которые клиент указал при оформлении.

## Описание реализации

### Контекст

Сейчас сайт сохраняет реквизиты отдельным запросом `POST /user/cabinet/return-item/ajax/check-bank-details`, а возврат создаёт запросом `POST /orders/refund/save-reason` только с позициями: бэкенд берёт последнюю сохранённую запись пользователя. Форма проверяет только заполненность полей по длине маски, а при ошибке создания возврата всё равно открывается окно успеха.

**Необходимо:**

1. Убрать поле «ИНН банка», показывать поле «Номер банковской карты» только для кредитного счёта, проверять поля формы и показывать ошибку под полем.
2. Добавить чекбокс подтверждения реквизитов.
3. Передавать реквизиты и подтверждение в `POST /orders/refund/save-reason`; `POST /user/cabinet/return-item/ajax/check-bank-details` в сценарии возврата не вызывать.
4. Показывать ошибки создания возврата и не открывать окно успеха при ошибке.

Бэкенд: ECOMDEV-2649 (реквизиты и подтверждение в `POST /orders/refund/save-reason`), ECOMDEV-2526 (правило «нужны реквизиты» и формат реквизитов).

### 1. Показ блока реквизитов

Блок «Банковские реквизиты» показывается при `data.need_bank_details = true` в ответе `GET /orders/refund/get-positions?id={order_id}` — так и работает, не меняется. Своей логики по способу оплаты на сайте нет и не добавляется. Правило признака меняется на бэкенде (ECOMDEV-2526): после выкатки блок показывается по новому правилу, в том числе для заказов с подарочным сертификатом.

### 2. Попап «Банковские реквизиты»

| № | Что меняется | Что сейчас |
|---|---|---|
| 1 | Поле «ИНН банка» удалено | обязательное поле |
| 2 | Поле «Номер банковской карты» показывается, только если номер лицевого счёта начинается с {red}(`30232810`) (кредитный счёт) | показывается всегда, обязательно |
| 3 | Поля проверяются по правилам из таблицы ниже, ошибка показывается под полем | проверяется только заполненность по длине маски |
| 4 | Под полями — чекбокс подтверждения реквизитов | чекбокса нет |
| 5 | Кнопка «Продолжить» доступна, только если все видимые поля прошли проверку и чекбокс отмечен | доступна, если поля заполнены по длине маски |
| 6 | «Продолжить» сохраняет реквизиты и отметку чекбокса в данных попапа оформления возврата и закрывает попап. Запрос к бэкенду не отправляется | отправляет `POST /user/cabinet/return-item/ajax/check-bank-details` |

**Правила проверки полей**

| Поле | Правило | Текст ошибки | Маска ввода |
|---|---|---|---|
| Фамилия получателя | обязательно, до 255 символов | «Заполните это поле» | — |
| Имя получателя | обязательно, до 255 символов | «Заполните это поле» | — |
| Отчество получателя | обязательно, до 255 символов | «Заполните это поле» | — |
| Название банка | обязательно, до 255 символов | «Заполните это поле» | — |
| БИК банка | обязательно, ровно 9 цифр | «Неверный формат БИК» | 9 цифр, как сейчас |
| Номер лицевого счёта | обязательно, ровно 20 цифр | «Неверный формат номера счета» | `###-##-###-#-####-#######`, как сейчас |
| Номер банковской карты | только при кредитном счёте: обязательно, ровно 16 цифр | «Неверный формат карты» | `####-####-####-####`, как сейчас |

- Пустое обязательное поле — «Заполните это поле».
- Тексты — существующие тексты правил проверки полей сайта, не меняются. Ошибки бэкенда показываются с текстом из ответа, как сейчас; он может отличаться от текста проверки на сайте.
- Дефисы маски при проверке не учитываются: проверяется количество цифр.
- Ссылки и теги в ФИО и названии банка проверяет только бэкенд, его ошибка показывается по разделу 4.
- При выходе из поля с неверным значением под полем показывается ошибка; при вводе ошибка скрывается, как только значение начинает проходить правило.

**Кредитный счёт и поле «Номер банковской карты»**

- Кредитный счёт — номер лицевого счёта, первые 8 цифр которого `30232810` {red}(подтверждение бухгалтерии — открытый вопрос 1). Дефисы маски не учитываются: в поле с маской такой счёт начинается с `302-32-810-`.
- Поле «Номер банковской карты» по умолчанию скрыто и показывается, как только первые 8 цифр введённого номера счёта — `30232810`. Пример: `30232810…` → поле показывается; `40817810…` → поле скрыто.
- Если клиент изменил начало счёта и счёт перестал быть кредитным, поле карты скрывается, введённый номер карты не проверяется и не отправляется.

**Чекбокс подтверждения**

- Текст: «Подтверждаю корректность указанных мной банковских реквизитов».
- По умолчанию не отмечен. Отметка — действие клиента, предзаполнять её нельзя.
- При повторном открытии попапа введённые реквизиты и отметка сохраняются.
- Изменение любого поля снимает отметку.

### 3. Создание возврата

1. При `need_bank_details = true` кнопка «Подтвердить возврат» недоступна, пока реквизиты не введены в попапе «Банковские реквизиты», — так и работает. Меняется только условие заполненности: сейчас проверяются непустые ИНН, название банка, ФИО, счёт и номер карты; после доработки — реквизиты сохранены кнопкой «Продолжить» по разделу 2 (видимые поля прошли проверку, чекбокс отмечен). ИНН не учитывается, номер карты — только при кредитном счёте.
2. При нажатии на кнопку «Подтвердить возврат» вызывать `POST /orders/refund/save-reason`:
   - `need_bank_details = true` → вместе с `positions` передавать реквизиты и `is_bank_details_confirmed` по таблице ниже;
   - `need_bank_details = false` → передавать только `positions`, как сейчас.

| Параметр | Поле формы | Значение |
|---|---|---|
| `surname` | Фамилия получателя | как введено |
| `name` | Имя получателя | как введено |
| `patronymic` | Отчество получателя | как введено |
| `bank_name` | Название банка | как введено |
| `bank_bic` | БИК банка | 9 цифр |
| `user_account` | Номер лицевого счёта | по маске, как сейчас |
| `user_card_number` | Номер банковской карты | по маске, как сейчас; только при кредитном счёте, иначе параметр не передаётся |
| `is_bank_details_confirmed` | Чекбокс подтверждения | `true` |

`bank_inn` не передаётся. `POST /user/cabinet/return-item/ajax/check-bank-details` в сценарии возврата не вызывается; сам метод не меняется.

### 4. Ошибки создания возврата

| № | Ошибка `POST /orders/refund/save-reason` | Что показываем |
|---|---|---|
| 1 | Ошибки по полям реквизитов или по `is_bank_details_confirmed` | открывается попап «Банковские реквизиты» с введёнными данными: ошибки полей — под полями, ошибка подтверждения — под чекбоксом, отметка чекбокса снята |
| 2 | Прочие ошибки | уведомление с текстом из ответа, как сейчас |

В обоих случаях окно успеха «Заявка уже у нас» не открывается, попап оформления возврата остаётся открытым. Ключи ошибок по полям — имена параметров запроса (`surname`, `bank_bic`, `is_bank_details_confirmed` и т. д.).

Выкатывать одним релизом с ECOMDEV-2526 и ECOMDEV-2649: до них бэкенд не принимает реквизиты в `POST /orders/refund/save-reason`, после них не создаёт без них возврат, для которого реквизиты нужны.

## Тестирование

{% cut "Критерии приёмки" %}

**Показ блока реквизитов**

1. `need_bank_details = true` → блок «Банковские реквизиты» показывается; `false` → блок не показывается, в `POST /orders/refund/save-reason` передаются только `positions`, возврат оформляется как раньше.

**Попап «Банковские реквизиты»**

2. Поля «ИНН банка» нет; подписи и маски остальных полей не изменились.
3. Неверное значение любого поля из таблицы раздела 2 даёт ошибку под полем с текстом из таблицы при выходе из поля; ошибка скрывается, как только значение исправлено.
4. Поле «Номер банковской карты» скрыто, пока номер счёта не начинается с `30232810`; при таком счёте поле показывается и обязательно. Если счёт изменён на некредитный, поле скрывается и не мешает «Продолжить».
5. Чекбокс по умолчанию не отмечен; «Продолжить» недоступна, пока хотя бы одно видимое поле не проходит проверку или чекбокс не отмечен.
6. При повторном открытии попапа реквизиты и отметка сохраняются; изменение любого поля снимает отметку.
7. «Продолжить» не отправляет запросов; `POST /user/cabinet/return-item/ajax/check-bank-details` в сценарии возврата не вызывается.

**Создание возврата**

8. `need_bank_details = true` → «Подтвердить возврат» недоступна, пока реквизиты не введены и не подтверждены.
9. В `POST /orders/refund/save-reason` переданы `positions`, реквизиты из таблицы раздела 3 и `is_bank_details_confirmed = true`; `bank_inn` не передан; `user_card_number` передан только при кредитном счёте.
10. Реквизиты, которые пропускает форма, не получают от бэкенда ошибок формата (кроме ссылок и тегов в ФИО и названии банка).
11. Ошибка по полям реквизитов → попап «Банковские реквизиты» с ошибками под полями; ошибка подтверждения → ошибка под чекбоксом, отметка снята; окно успеха не открывается.
12. Прочая ошибка → уведомление с текстом из ответа; окно успеха не открывается.
