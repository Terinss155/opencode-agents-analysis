# ECOMDEV-2532: [F] Возврат 0.1. Банковские реквизиты: чекбокс подтверждения и проверка по общим правилам

## Цель

Сейчас сайт сохраняет реквизиты отдельным запросом `POST /user/cabinet/return-item/ajax/check-bank-details`, а возврат создаёт запросом `POST /orders/refund/save-reason` без реквизитов: бэк берёт последнюю сохранённую запись пользователя. Поэтому к возврату могут попасть старые реквизиты. Клиент не подтверждает реквизиты, а 1С нужно подтверждение для разбора спорных ситуаций. Форма реквизитов проверяет только заполненность по длине маски, а ошибку создания возврата клиент не видит: окно успеха открывается всегда.

Нужно:

1. Добавить в форму реквизитов чекбокс подтверждения.
2. Передавать реквизиты и подтверждение клиента в запросе создания возврата `POST /orders/refund/save-reason`, не вызывать `POST /user/cabinet/return-item/ajax/check-bank-details`.
3. Проверять поля формы по тем же правилам, что и бэк.
4. Показывать ошибки создания возврата и не открывать окно успеха при ошибке.

Связанные задачи на бэк: ECOMDEV-2649 (реквизиты и подтверждение в `POST /orders/refund/save-reason`), ECOMDEV-2526 (правило «нужны реквизиты» и правила формата).

## Описание реализации

### 1. Показ блока реквизитов

Нужны ли реквизиты, решает бэк: признак `data.need_bank_details` в ответе `GET /orders/refund/get-positions?id={order_id}`. Своей логики по способу оплаты на сайте нет и не добавляется. Блок «Банковские реквизиты» показывается только при `need_bank_details = true` — так и работает, не меняется.

Правило «нужны реквизиты» меняется на бэке (ECOMDEV-2526). После выкатки бэка блок начнёт показываться по новому правилу без доработки сайта.

### 2. Попап «Банковские реквизиты»

| № | Что меняется | Что сейчас |
|---|---|---|
| 1 | Поля проверяются по правилам из таблицы ниже, ошибка показывается под полем | правила из `validationRules.js` описаны в полях, но не применяются: проверяется только заполненность по длине маски |
| 2 | ИНН банка необязателен | обязателен |
| 3 | Под полями — чекбокс подтверждения реквизитов, по умолчанию не отмечен | чекбокса нет |
| 4 | Кнопка «Продолжить» доступна, только если все поля прошли проверку и чекбокс отмечен | доступна, если поля заполнены по длине маски |
| 5 | «Продолжить» сохраняет реквизиты и состояние чекбокса в данных попапа оформления возврата и закрывает попап. Запрос к бэку не отправляется | отправляет `POST /user/cabinet/return-item/ajax/check-bank-details`, при успехе закрывает попап |

**Правила проверки полей** — совпадают с ECOMDEV-2526 §2:

| Поле | Правило | Маска ввода |
|---|---|---|
| Фамилия получателя | обязательно, до 255 символов | — |
| Имя получателя | обязательно, до 255 символов | — |
| Отчество получателя | обязательно, до 255 символов | — |
| Название банка | обязательно, до 255 символов | — |
| БИК банка | обязательно, ровно 9 цифр | 9 цифр, как сейчас |
| ИНН банка | необязательно; если заполнено — ровно 10 цифр | 10 цифр, как сейчас |
| Номер лицевого счёта | обязательно, ровно 20 цифр | `###-##-###-#-####-#######`, как сейчас |
| Номер банковской карты | обязательно, ровно 16 цифр | `####-####-####-####`, как сейчас |

Дефисы маски при проверке не учитываются: проверяется количество цифр. Проверка ссылок и тегов в ФИО и названии банка остаётся только на бэке, её ошибка показывается по разделу 4.

Когда проверяется:

- при выходе из поля: если значение не проходит правило, под полем показывается текст ошибки;
- при вводе в поле с ошибкой: ошибка скрывается, как только значение начинает проходить правило.

**Чекбокс подтверждения**

- Текст: «Подтверждаю корректность указанных мной банковских реквизитов» (текст на согласовании, см. «Открытые вопросы»).
- По умолчанию не отмечен. Отметка — осознанное действие клиента, предзаполнять её нельзя.
- При повторном открытии попапа ранее введённые реквизиты и отметка чекбокса сохраняются.
- Изменение любого поля снимает отметку: клиент подтверждает реквизиты в том виде, в котором они уйдут в возврат.
- Ошибка подтверждения от бэка показывается под чекбоксом (раздел 4).

### 3. Создание возврата

Кнопка «Подтвердить возврат» в попапе оформления возврата:

| № | Что меняется | Что сейчас |
|---|---|---|
| 1 | При `need_bank_details = true` кнопка недоступна, пока реквизиты не введены и не подтверждены чекбоксом в попапе «Банковские реквизиты» | проверяется заполненность 7 полей, БИК не учитывается, ИНН обязателен |
| 2 | При `need_bank_details = true` в `POST /orders/refund/save-reason` вместе с `positions` передаются реквизиты и `is_bank_details_confirmed = true` | передаются только `positions` |
| 3 | При `need_bank_details = false` запрос — как сейчас, только `positions` | — |

**`POST /orders/refund/save-reason` — новые параметры** (по задаче ECOMDEV-2649):

| Параметр | Поле формы | Формат |
|---|---|---|
| `surname` | Фамилия получателя | как введено |
| `name` | Имя получателя | как введено |
| `patronymic` | Отчество получателя | как введено |
| `bank_name` | Название банка | как введено |
| `bank_bic` | БИК банка | 9 цифр |
| `bank_inn` | ИНН банка | 10 цифр или пустая строка |
| `user_account` | Номер лицевого счёта | по маске, как сейчас |
| `user_card_number` | Номер банковской карты | по маске, как сейчас |
| `is_bank_details_confirmed` | Чекбокс подтверждения | `true` |

`POST /user/cabinet/return-item/ajax/check-bank-details` в сценарии возврата больше не вызывается.

### 4. Ошибки создания возврата

Сейчас ошибка `POST /orders/refund/save-reason` показывается уведомлением, но окно успеха «Заявка уже у нас» всё равно открывается: ошибка не прерывает сценарий.

| № | Ошибка `POST /orders/refund/save-reason` | Что показываем |
|---|---|---|
| 1 | Ошибки по полям реквизитов или по `is_bank_details_confirmed` | открывается попап «Банковские реквизиты» с введёнными данными: ошибки полей — под полями, ошибка подтверждения — под чекбоксом, отметка чекбокса снята |
| 2 | Прочие ошибки | уведомление с текстом из ответа, как сейчас |

В обоих случаях окно успеха не открывается, попап оформления возврата остаётся открытым.

Ключи ошибок по полям — имена параметров запроса (`surname`, `bank_bic`, `is_bank_details_confirmed` и т. д.), как сейчас у ошибок `POST /user/cabinet/return-item/ajax/check-bank-details`.

### 5. Выкатка

Выкатывается одновременно с задачей бэка ECOMDEV-2649: после неё бэк не создаёт возврат без реквизитов в запросе, а до неё не принимает реквизиты в `POST /orders/refund/save-reason`. Нужен ли переходный режим — открытый вопрос задачи ECOMDEV-2649.

## Критерии приёмки

### Показ блока реквизитов

1. Блок «Банковские реквизиты» показывается, только если в ответе `GET /orders/refund/get-positions` пришло `need_bank_details = true`.
2. При `need_bank_details = false` блок не показывается, возврат оформляется без реквизитов, в `POST /orders/refund/save-reason` передаются только `positions`.

### Попап «Банковские реквизиты»

3. Для каждого поля из таблицы раздела 2 неверное значение даёт ошибку под полем при выходе из поля; ошибка скрывается, как только значение исправлено.
4. Пустой ИНН не даёт ошибки; заполненный не полностью — даёт.
5. Чекбокс подтверждения по умолчанию не отмечен; «Продолжить» недоступна, пока хотя бы одно поле не проходит проверку или чекбокс не отмечен.
6. При повторном открытии попапа отметка чекбокса сохраняется; изменение любого поля снимает отметку.
7. «Продолжить» не отправляет запросов к бэку; `POST /user/cabinet/return-item/ajax/check-bank-details` в сценарии возврата не вызывается.
8. Подписи полей и маски ввода не изменились.

### Создание возврата

9. При `need_bank_details = true` «Подтвердить возврат» недоступна, пока реквизиты не введены и не подтверждены чекбоксом.
10. В `POST /orders/refund/save-reason` передаются все реквизиты из таблицы раздела 3 и `is_bank_details_confirmed = true`.
11. Набор реквизитов, который пропускает форма, не получает от бэка ошибок формата (кроме ссылок и тегов в ФИО и названии банка).
12. При ошибке по полям реквизитов открывается попап «Банковские реквизиты» с ошибками под полями; при ошибке подтверждения — ошибка под чекбоксом, отметка снята; окно успеха не открывается.
13. При прочей ошибке `POST /orders/refund/save-reason` показывается уведомление с текстом из ответа; окно успеха не открывается.
14. Сценарий возврата без реквизитов (онлайн-оплата без сертификата) работает как раньше.
