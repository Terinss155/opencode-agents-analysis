# Эпик: Оформление возврата товара

Как пользователь, совершивший покупку,

Я хочу оформить возврат одного, нескольких или всех доступных товаров из заказа удобным доступным способом,

Чтобы вернуть неподошедшие товары и получить за них денежные средства и использованные баллы в соответствии с условиями возврата.

**Тип:** эпик (контейнер историй), не User Story — ID `US-<n>` не присваивается; критерии INVEST, включая Small, к эпику не применяются.

**Приоритет:** Must have

**Оценка:** не оценивается в story points; оценка — сумма дочерних историй.

**Бизнес-ценность:** пользователь самостоятельно оформляет возврат и выбирает доступный для города канал без обращения в поддержку.

**Состав (декомпозиция):**
- [ECOMDEV-2246 [MVP] Возвраты](#ecomdev-2246-mvp-возвраты) — US1…US4, US6, US7, US10, US12 (ECOMDEV-2281, 2275, 2276, 2277, 2279, 2280; US10, US12 — ECOMDEV-TBD); US13 перенесена в US1.1 (14.10.2026)
- [ECOMDEV-2256 [Post-MVP] Возвраты](./user-story-post-mvp.md#ecomdev-2256-post-mvp-возвраты) — US5, US8, US11 (ECOMDEV-2278, 2282; US11 — ECOMDEV-TBD); **NEW 07.10.2026:** US14, US15; **NEW 16.10.2026:** US16

Соответствие прежним ID — в разделе [«Соответствие задач Jira и ID бандла»](#соответствие-задач-jira-и-id-бандла).

**Сценарий:** сквозной путь оформления раскрыт в SRS (US 1.1–1.5); собственных Acceptance Criteria у эпика нет — критерии живут в дочерних историях (Золотое правило: пользовательский сценарий не пересказывается на нескольких уровнях).

# Снятая история: изменение состава созданной заявки

История об изменении состава созданной заявки снята с текущего и подтверждённого Post-MVP-объёма.

Причина: в MVP редактирование созданной заявки запрещено (`RULE-05`, `ADR-RET-001`). Состав
будущих изменений не определён: неизвестно, какие поля и при каких условиях бизнес может
разрешить редактировать после MVP. Новая User Story создаётся только после подтверждения
пользовательской потребности и границ редактирования.

В новой нумерации ID истории не присваивается. Acceptance Criteria отсутствуют, поскольку
пользовательское требование снято.

```
Feature: Отображение кнопки и условий возврата в карточке заказа

Сценарий: Кнопка возврата доступна при отсутствии ранее созданных заявок
  Дано заявки на возврат для всех позиций заказа отсутствуют

Сценарий: Кнопка возврата доступна при наличии действующей заявки на часть товаров
  Дано в заказе есть позиция, на которую еще не оформлен возврат

  Тогда кнопка оформления возврата отображается и активна

  Тогда система автоматически отправляет клиенту уведомление (Push/Email) с напоминанием об истекающем сроке передачи возврата
```
