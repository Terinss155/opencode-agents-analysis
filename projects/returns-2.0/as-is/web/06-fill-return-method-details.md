# Шаг 06 (web). Заполнение данных способа: адрес / индекс / дата

**Канал:** Сайт · **Экран:** «Оформление возврата», блоки «Адрес возврата» и «Дата возврата»
**Статус:** DRAFT · **Дата:** 07.09.2026
**Результат шага:** в состоянии формы заполнены улица/дом/квартира/индекс (только для курьера) и дата. В базе ничего не меняется.

---

## 1. Пользовательский сценарий

### 1.1 Откуда пользователь приходит

Тот же экран «Оформление возврата», после выбора способа (шаг [05](05-select-return-method.md)). Состав блоков зависит от типа выбранного способа.

### 1.2 Что система отображает

**Если способ — Курьер:**
- Блок «Адрес возврата»:
  - поле «Улица» — подсказки по гео-сервису в пределах выбранного города;
  - поле «Дом» — подсказки домов после выбора улицы; допускается ручной ввод;
  - поле «Квартира / офис» — свободный ввод;
  - поле «Индекс» — появляется, если по выбранному дому индекс не определился автоматически; если определился — подставляется и скрывается.
- Блок «Дата возврата» (если для способа есть доступные даты).

**Если способ — ПВЗ (`sdek-pvz` / `5post`):**
- Блока адреса **нет**.
- Блок «Дата возврата» (если есть доступные даты).
- Ссылка «Пункты выдачи на карте» — информационная (см. шаг 05).

**Блок «Дата возврата»:** плитки-даты из списка доступных дат выбранного способа; на плитке — день недели и «число месяц».

### 1.3 Действия пользователя

| Действие | Что меняется |
|---|---|
| Ввод / выбор улицы | сохраняется улица; при этом дом, квартира и индекс очищаются |
| Выбор дома из подсказки | сохраняется дом; если пришёл индекс — сохраняется индекс |
| Ручной ввод дома | сохраняется дом; поле индекса показывается принудительно |
| Ввод квартиры | сохраняется квартира |
| Ввод индекса | сохраняется индекс |
| Выбор даты | сохраняется дата |

Адрес для отправки собирается на сайте в одну строку вида «{улица}, д. {дом}, кв. {квартира}» (пустые части опускаются).

### 1.4 Ограничения

Кнопка «Подтвердить возврат» активируется только когда заполнено:
- **ПВЗ:** страна, город, дата.
- **Курьер:** страна, город, дом, индекс, дата.

Улица и квартира в проверку готовности не входят, но пустая улица даст пустой адрес и ошибку проверки на сервере на шаге 08.

Автоподстановка даты: если список дат пуст — дата сбрасывается; если ранее выбранная дата есть в новом списке — остаётся; иначе выбирается первая доступная.

### 1.5 Что происходит после действия

Значения складываются в память попапа. Далее, по кнопке «Подтвердить возврат» (шаг [08](08-confirm-and-create-return.md)), они уходят в запрос сохранения реквизитов возврата.

### 1.6 Ошибочные сценарии

- Гео-сервис недоступен: подсказки отключаются, поле индекса показывается принудительно, улица и дом вводятся вручную.
- Ошибка проверки даты на сервере (на шаге 08): показывается всплывающее окно «Выберите другой день» с текстом про оформление после 15:00; актуальный список дат берётся из данных ответа.
- Для ПВЗ конкретная точка (адрес пункта) не запрашивается и не вводится.

## 2. Системная реализация

### 2.0 Диаграмма последовательности

```mermaid
sequenceDiagram
    actor U as Пользователь
    participant W as Сайт (попап)
    participant GEO as Гео-сервис доставки

    Note over W: список доступных дат получен на шаге 05
    alt способ = Курьер
        U->>W: ввод улицы
        W->>GEO: GET .../geo/countries/{countryIso}/addresses?cityId&search
        GEO-->>W: подсказки улиц
        U->>W: выбор дома
        W->>GEO: GET .../addresses/{geo_id}/details
        GEO-->>W: { street, house{building,block}, postalCode }
        W->>W: details.street/house/index; addressFormatted
        U->>W: ввод квартиры, выбор даты
    else способ = ПВЗ (sdek-pvz / 5post)
        U->>W: выбор даты
    end
    Note over W: значения складываются в память попапа;<br/>на бэкенд уйдут по кнопке «Подтвердить возврат» (шаг 08)
```

Запросов процесса возврата на этом шаге нет — только гео-подсказки.

### 2.1 Источники данных

| Данные | Источник |
|---|---|
| Подсказки улиц / домов / деталей адреса | гео-эндпоинты сайта: `GET /api/v1/delivery/geo/countries/{countryIso}/addresses`, `.../addresses/{geo_id}/details` |
| Доступные даты | список `available_dates_return` из ответа шага 05 (расчёт описан там же) |

Существующие карточки: [`api/web/geo/get-addresses.md`](../../reference/api/web/geo/get-addresses.md), [`api/web/geo/get-address-details.md`](../../reference/api/web/geo/get-address-details.md).

### 2.2 Как система собирает данные

На этом шаге сервер процесса возврата не вызывается (обращения идут только к гео-подсказкам). Даты уже получены на шаге 05.

Правила расчёта дат (выполняются на шаге 05):
- **Курьер:** если в конфигурации выбор даты выключен — дат нет. Иначе даты от сегодняшнего дня с задержкой из конфигурации; если текущее московское время позже времени-отсечки — плюс один день. Количество дат — из конфигурации.
- **ПВЗ:** окно `cms_orders.end_date + 14 дней`; вне окна — дат нет; в последний день окна — плюс 3 дня; даты от завтрашнего дня.

### 2.3 Обмен по API

Гео-подсказки (инициатор — форма адреса):

```http
GET /api/v1/delivery/geo/countries/{countryIso}/addresses?cityId={cityId}&search={search}&limit=5
GET /api/v1/delivery/geo/countries/{countryIso}/addresses/{geo_id}/details
```

Из деталей адреса берутся: идентификатор и название улицы, номер и корпус дома, почтовый индекс, тип объекта.

Запросов процесса возврата на этом шаге нет.

### 2.4 Что использует сайт

| Данные | Использование |
|---|---|
| улица + дом + квартира | собираются в строку `address_return` |
| индекс | `index_return` |
| дата | `date_return` |
| список доступных дат | плитки дат и автоподстановка |

### 2.5 Что передаётся на следующий шаг

Через память попапа в запрос `POST /api/orders/{order_id}/return-details` (шаг 08):
- курьер: `method_return`, `address_return`, `city_return`, `date_return`, `index_return`;
- ПВЗ: `method_return`, `city_return`, `date_return` (адрес и индекс для ПВЗ сайт не отправляет).

### 2.6 Что сохраняется или меняется

Ничего. Запись — на шаге 08:
- адрес → `cms_orders.return_address` (только если пришло непустое);
- индекс → `cms_orders.return_postal` (только если пришло непустое);
- дата → `cms_orders.return_date`.

Для ПВЗ сервер дополнительно обнуляет индекс и адрес перед сохранением, даже если бы их прислали.

### 2.7 Неуточнённые места

- На сайте жёстко обязательны только «Дом» и «Индекс»; «Улица» и «Квартира» — нет. Полноту адреса сервер проверяет по строке `address_return` (длина не больше 1024 символов).
- Индекс на сервере проверяется как ровно 6 цифр.
- Дата на сервере проверяется по формату «ГГГГ-ММ-ДД» и по вхождению в список доступных дат; если список пуст, а дата передана — ошибка «выбор даты недоступен».
- Поле `cms_orders.return_interval` (интервал курьера) не заполняется — интервалов в AS-IS нет.
- Окно возврата для ПВЗ (14 дней от даты завершения заказа) и «+3 дня в последний день» — **зашитые в код константы**, не связаны с параметром `days_can_be_returned` из таблицы `cms_parameters`.
- Расчёт дат курьера (задержка, число дат, время-отсечка) — из справочника `cms_return_details_config`, конкретные значения в коде не зафиксированы.

## 3. Отличия от TO-BE

| TO-BE (`UC-RET-04.1`, `UC-RET-04.2`, `UC-RET-04.3`) | AS-IS (web) |
|---|---|
| Курьер: адрес заказа предзаполняется при совпадении города и способа получения | Предзаполнения нет; адрес всегда вводится вручную |
| Курьер: выбор даты **и интервала**, повторная проверка интервала | Только дата; интервалов нет |
| 5Post / СДЭК: список точек, карта, выбор конкретного пункта, сохранение его идентификатора и адреса, сводка канала | Точка не выбирается; карта информационная; в `cms_orders` (на шаге 08) сохраняются только город + дата + способ, пункт — нет |
| 5Post / СДЭК: дата передачи **не выбирается** — вместо неё срок передачи после создания заявки (норматив ТК) + автоотмена | Для `sdek-pvz` / `5post` показываются плитки дат (`available_dates_return`, окно `end_date + 14 дней`), дата сохраняется в `return_date` |
| Расширение «Даты или интервалы отсутствуют» — сообщение и возврат к выбору способа | При пустых датах блок дат просто не показывается |
| Дата «Можно вернуть до» = `cms_orders.end_date` + 14 / 30 дней (F&F) — показывается клиенту | Не рассчитывается и не показывается |
