# Настройки, влияющие на сроки, даты и интервалы доставки (`master` + `develop`, MR !511 и !521)

Ссылка на Яндекс Вики: https://wiki.yandex.ru/teams/web-development/dokumentacija/produkty-i-servisy/produkt-logistika/issledovanija-dlja-servisa-logistiki/issledovanie-nastrojjki-vlijajushhie-na-sroki-daty/

Таблица объединяет описание для `master` и изменения в `develop`. В колонке «Как влияет» два пути расчёта разделены:
- **Формула**: даты и интервалы считаются по настройкам (как на `master`).
- **СДЭК** (новое в `develop`): даты и слоты запрашиваются у СДЭК.

Путь СДЭК включается, только если одновременно выполнено всё перечисленное:
1. включены оба флага «Использовать интервалы от ТК» (на ТК в 1С и на типе доставки);
2. «Код 3PL оператора» у ТК в 1С равен `CDEK`;
3. в запросе передан адрес.

Строки, добавленные в `develop`, помечены «🆕».

## Настройки

| Сущность | Настройка | На что влияет | Как влияет |
|---|---|---|---|
| **Юр. лица** | Срок доставки отображается в рабочих днях | Дни недели доставки | «Нет»: доставка возможна в любой день недели. «Да»: даты на субботу и воскресенье переносятся на понедельник, праздники не учитываются. Формула: применяется. СДЭК: к датам не применяется |
| **Юр. лица** | Есть интеграция | Выбор типа доставки-победителя | «Нет»: ближайшая дата от ТК не запрашивается, в расчёте победителя используется минимальное количество дней типа. «Да»: система периодически запрашивает у ТК ближайшую дату (SDT/Маршрут при заполненном коде SDT, либо CSE), она участвует в расчёте победителя. Даты, которые видит клиент, не меняются. В `develop` не перепроверялось |
| **Юр. лица** | Активно | Наличие вариантов доставки | «Нет»: все типы доставки этого юр. лица не показываются клиенту |
| **ТК в 1С** | 🆕 Использовать интервалы от ТК | Источник дат и слотов | Первый из двух флагов. Выключен: даты считаются по формуле. Включён вместе с флагом типа доставки: даты и слоты берутся из СДЭК. По умолчанию выключен |
| **ТК в 1С** | 🆕 Код 3PL оператора | Допуск к запросу в СДЭК | Должен быть `CDEK`. Пустое значение или другой код: в расчёте тип доставки исключается из ответа, в методе интервалов возвращается ошибка 400 |
| **ТК в 1С** | Количество дней интервалов, возвращаемых пользователю | Сколько дат показать | Формула: число ближайших дат, при 0 список дат пуст, дата без интервалов не показывается. СДЭК: верхняя граница числа дат. Значение 0 или меньше: расчёт переходит на формулу, метод интервалов возвращает ошибку 500 |
| **ТК в 1С** | Интервалы ТК | Время доставки | Формула: запасной вариант, используются, только если не заданы календарь и интервалы типа доставки. СДЭК: не используются |
| **ТК в 1С** | Активна | Наличие вариантов доставки | «Нет»: все типы доставки этой ТК не показываются |
| **Способ доставки** | Календарь доставки (на способ) | Интервалы на период | Формула: для периода (дата с / дата по) заменяет обычные интервалы, приоритет ниже, чем у календаря типа. СДЭК: не применяется |
| **Способ доставки** | Активен | Наличие вариантов доставки | «Нет»: способ и все его типы не показываются |
| **Тип доставки** | 🆕 Использовать интервалы от ТК | Источник дат и слотов | Второй флаг. Работает только вместе с флагом на ТК в 1С |
| **Тип доставки** | Разброс доставки для отображения пользователю | Формат срока | Формула: «Да» — клиент видит только срок «от X до Y дней» без дат и интервалов, «Нет» — даты и интервалы. СДЭК: не применяется, даты возвращаются всегда |
| **Тип доставки** | Количество дней доставки по умолчанию: От / До | Текст срока («3–5 дней») | Только отображаемый диапазон в днях, расчёт дат не меняет. «От» должно быть меньше или равно «До». Значения `from_days` и `to_days` выдаются на обоих путях |
| **Тип доставки** | Минимальное количество дней доставки | Ближайшая доступная дата | Формула: сдвигает первую дату на (значение − 1) суток: 0 — экспресс, 1 — день отгрузки (Москва), 2 — следующий день. СДЭК: к датам не применяется |
| **Тип доставки** | Минимальное количество дней доставки C&C | Ближайшая дата для заказов C&C | Формула: как предыдущая настройка, но только для C&C. Если не заполнено, применяется 0, а не значение для обычных заказов, рекомендуется заполнять. СДЭК: к датам не применяется |
| **Тип доставки** | Запас по времени (в минутах) | Ближайшая дата | Прибавляется ко времени оформления заказа (передача заказа в 1С-WMS). Формула: чем больше запас, тем позже ближайшая дата. СДЭК: входит в расчёт даты приёмки заказа, с которой запрашиваются интервалы |
| **Тип доставки** | Время консолидации (в минутах) | Ближайшая дата и интервалы в день заказа | Время на сборку. Формула: если сборка переходит на следующие сутки, дата сдвигается на день; при доставке в день заказа скрываются интервалы, начинающиеся раньше окончания сборки. СДЭК: входит в расчёт даты приёмки заказа |
| **Тип доставки** | Интервалы (региональные) | Время доставки | Формула: используются, если нет календаря на нужную дату, показываются только для нужного дня недели. СДЭК: не используются, слоты берутся из СДЭК, слот скрывается при `agreed_count` = `total_count` |
| **Тип доставки** | Календарь доставки (на тип) | Интервалы на период | Формула: самый высокий приоритет, для дат в периоде заменяет все остальные интервалы. СДЭК: не применяется |
| **Тип доставки** | Активен | Наличие варианта доставки | «Нет»: тип доставки не показывается |
| **Тип доставки** | Коэффициенты (приоритет, срок, стоимость) и процент победителя | Какой тип доставки покажется клиенту | Если в способе доставки несколько типов, показывается один «победитель», меньше коэффициент — выше шанс. Формула: срок считается до `NextDeliveryDate` или по минимальному количеству дней. СДЭК: срок считается до первой даты СДЭК, 0 если дат нет |
| **Интервал** | День недели | Когда доступен интервал | Формула: интервал показывается только на выбранный день недели. СДЭК: не используется |
| **Интервал** | Время для клиента (с / по) | Что видит клиент | Формула: «ЧЧ:ММ – ЧЧ:ММ». СДЭК: слоты получают подпись такого же вида из ответа СДЭК, `internal_time_from` и `internal_time_to` пустые |
| **Интервал** | Время ТК (с / по) | Скрытие интервалов в день заказа | Формула: если раньше окончания сборки, интервал не показывается. СДЭК: не используется |
| **Интервал** | Код интервала | Передача в 1С | Не влияет на отображение, передаётся вместе с интервалом. СДЭК: код слота формируется как `ЧЧ:ММ-ЧЧ:ММ` |
| **Заказ** | Время оформления и часовой пояс | Ближайшая дата | Время не передано: берётся текущее. Часовой пояс (формат `UTC±HH:MM`) не передан: Москва. 🆕 В `develop` часовой пояс передаётся и в расчёт |
| **Заказ** | 🆕 Тип заказа C&C | Дата приёмки заказа для СДЭК | Не C&C: дата заказа с учётом запаса и консолидации, время 23:30 в часовом поясе заказа. C&C: следующие сутки, 23:30 UTC. Для формулы: переключает на минимальное количество дней C&C |
| **Заказ** | 🆕 Адрес доставки (`house_geo_id`, в методе интервалов `delivery_address`) | Допуск к запросу в СДЭК | Если при включённой интеграции адрес не передан: в расчёте тип доставки исключается из ответа, в методе интервалов возвращается ошибка 400 |

## В каком порядке выбираются даты и интервалы

Система берёт первый найденный источник, остальные игнорирует.

| Приоритет | Откуда берутся даты и интервалы | Когда применяется |
|---|---|---|
| 0 🆕 | СДЭК | Выполнены три условия пути СДЭК и СДЭК ответил без ошибки. Иначе расчёт возвращается к формуле (в методе интервалов вместо этого возвращается ошибка) |
| 1 | Календарь доставки типа доставки | Дата входит в период календаря и в календаре есть интервалы |
| 2 | Календарь доставки способа доставки | То же условие |
| 3 | Интервалы типа доставки | Заданы региональные интервалы |
| 4 | Интервалы ТК в 1С | Ничего из выше перечисленного не задано |
| — | Ничего не найдено | Дата не показывается |

## Пример расчёта

Заказ оформлен 2 ноября в 15:45. Запас по времени 360 минут, время консолидации 480 минут, минимальное количество дней доставки равно 1.

| Шаг | Формула | СДЭК (не C&C) |
|---|---|---|
| Время с запасом | 2 ноября, 21:45 | 2 ноября, 21:45 |
| Заказ собран | 3 ноября, 05:45 (сборка переходит на следующие сутки, +1 день) | 3 ноября, 05:45 |
| Результат | Ближайшая дата доставки: 4 ноября | Дата приёмки заказа: 3 ноября, 23:30. Даты и слоты определяет СДЭК |

Для C&C на пути СДЭК дата приёмки: 4 ноября, 23:30 UTC.

## Фиксированные значения в коде `develop` (не настраиваются)

| Значение | Где используется |
|---|---|
| Тариф СДЭК 482, точка отгрузки MSK660 | Запрос интервалов и воркер пунктов выдачи |
| Время приёмки заказа 23:30 | Дата приёмки для СДЭК |
| Таймаут запросов к СДЭК 30 секунд | Токен, интервалы, пункты выдачи |
| Кэш ответа расчёта 10 минут | Расчёт дат |

## Примечания

1. Изменения настроек применяются не сразу: расчёт кэшируется на 10 минут, инвалидации кэша при сохранении настроек в прочитанном коде нет.
2. Влияние «Есть интеграция» на показ дат в коде не подтверждено: данные ТК используются для коэффициента победителя (`getIntegrationInfo`). Формулировку стоит сверить с владельцем функции.
3. На `master` календарь доставки загружается с условием `date_from >= время заказа`, поэтому уже начавшийся календарь может не применяться. В `develop` это отдельно не перепроверялось.
4. Ограничения по весу, цене и количеству товаров в таблице не учтены: они влияют на показ типа доставки целиком, а не на даты.
5. Интеграция интервалов СДЭК работает только для кода `CDEK`, тарифа 482 и точки MSK660. Эти значения зашиты в коде.
6. Описание поля админки «Использовать интервалы от ТК» взято из ветки `dev` фронтенда (ветки `develop` в `logistics-frontend` нет).
